# matrix-avro v0.3.2 review fixes

## 1. [P1] Preserve values when normalizing map keys

- Locations: `MatrixAvroWriter.groovy`, `toRecordAvroValue`, line 821, and `AvroSchemaCompatibility.groovy`, `findIncompatibleRecordValue`, line 178 at review time.
- Schema inference converts map keys to strings, but serialization retrieves values from the original map using a `String` key. Groovy `GString` keys do not match that lookup, so values are silently replaced with null.
- Avro MAP serialization also normalizes keys and can silently overwrite values when distinct keys have the same text, such as a String/interpolated-key pair or `1` and `"1"`. Both declared MAP schemas and inferred MAP schemas (rows with different key sets) are affected. `toMapAvroValue` and `findIncompatibleMapValue` must share the validation described below. This MAP collision path was traced during review, not reproduced.
- Reproduced with a map constructed as `["${keyName}": 'Alice']`, where `keyName = 'name'`: the value round-trips as `[name: null]`.

1.1 [x] Extract shared map-key validation and normalization logic for serialization and compatibility checking, covering Avro RECORD and MAP values, inferred and declared schemas, and union branch selection. Apply the same one-pass null-key and collision validation in `toMapAvroValue` and `findIncompatibleMapValue` as in record conversion and compatibility checking; never let normalized MAP keys silently overwrite values. Use a per-cell context created in the row-writing loop, where the column name and row number are available, and thread it through compatibility checks, union probes, and conversion. Cache map-key validation and record lookup state by map identity within that context so nested maps and repeated union probes reuse it; discard the context after the cell is written.

- Validate normalized keys in one pass per map value used by a RECORD or MAP schema, even when direct String-key lookups succeed. Raise collisions from this contextual validation as `AvroSchemaException` containing the column name, nested path, and clashing keys. The existing row-loop catch adds the row number. A collision encountered while probing a RECORD or MAP union branch is a hard error, not a signal to try another branch. Keep the existing `findIncompatibleValue(schema, value, path)` and `isCompatible(schema, value)` signatures as convenience overloads that create a context without column/row metadata. The former preserves the supplied path; the latter uses an unspecified/root path. Their collision and null-key errors report the available path without inventing a column name or row number. Add contextual overloads for writer calls, and retain and extend the existing `AvroSchemaCompatibilityTest` coverage of the three-argument signature.
- Reject null map keys with `AvroSchemaException` before applying `String.valueOf` or constructing schemas/records; report the column name and nested path, plus the row number when available. Apply this policy during inference and writing, including declared map and record schemas. A literal String key `"null"` remains valid and distinct from a null key. Null-key rejection is a hard error during union probing, just like a collision. The null-key data-loss path was traced during review, not reproduced.
- During inference, validate collisions before constructing record fields, using the available column and row context, and build fields from validated normalized keys rather than `recordSample.keySet()`. Reuse the same validation helper; schema inference and row writing are separate passes.
- Restrict the allocation-free String-key fast path to an allowlist of exact runtime classes: `HashMap`, `LinkedHashMap`, `ConcurrentHashMap`, the JDK immutable map implementation classes obtained from representative `Map.of(...)` / `Map.copyOf(...)` instances, and exact `TreeMap` only when `comparator() == null`. Collect immutable implementation classes from `Map.of()`, `Map.of('a', 1)`, and `Map.of('a', 1, 'b', 2)` into a Set so duplicate classes do not matter and both single-entry and empty/multi-entry implementations are included. Obtain these classes through public factory results rather than referencing JDK-internal class names. Do not admit subclasses or infer key semantics from interfaces. Every other map, including wrappers, identity maps, and TreeMaps with custom comparators, gets full normalized-key validation.
- For an allowlisted map, walk keys once to reject null and detect non-String keys. While keys are all Strings, avoid allocating a normalized-key Set or lookup view: the map already guarantees their uniqueness. On the first non-String key, initialize normalized-key validation using the preceding keys as well, then validate the remaining keys without repeating validation during compatibility/conversion.
- For field lookup, try `input.get(name)` first. If it returns null, use `input.containsKey(name)` to preserve a present null value. On the first missing key, build a normalized lookup view once for that map value and reuse it for all subsequent misses, compatibility checks, union probes, and conversion. Ordinary String-keyed maps should reuse the original map where possible. Do not rescan all keys for every missing field or repeat collision scans between compatibility checking and serialization.
- Collision behavior is separate from silent value loss: inference currently normalizes keys into a Set for comparison but builds fields from the original keys. A map containing both a String key and an equivalent interpolated key is expected to fail with a raw duplicate-field error at `Schema.setFields`. This collision path was traced, not reproduced during the review.

1.2 [x] Add regression coverage for inferred records, declared records using `AvroSchemaDecl.record(...)`, and compatibility/union branch selection with interpolated keys. Cover present null values, invalid values under interpolated keys, non-nullable fields where supported, and collisions between String and interpolated keys. Add collision tests for an `IdentityHashMap` containing distinct String objects with equal text, an unmodifiable wrapper around that identity map, and a TreeMap with a comparator that permits equal-text String keys; all must use full validation and reject collisions. Add collision cases for a declared MAP column and an inferred MAP column whose rows have different key sets. Cover both String/interpolated-key collisions and numeric/String collisions such as `1` and `"1"`, including compatibility checks and nested MAP values; assert the same contextual `AvroSchemaException` and hard-error union behavior as for records. Add an enum-key round trip and a collision between an enum constant `NAME` and the String key `"NAME"`. Add null-key rejection cases for inferred records, declared records, and declared maps, including nested paths, and verify that a literal String key `"null"` retains its value. Assert the collision exception type, column name, row number, nested path, and clashing keys, and verify that a collision during union probing is a hard error. Add short performance checks using a large declared record column with mostly missing optional fields, a large ordinary String-keyed record-shaped column, and a large ordinary String-keyed MAP-shaped column whose rows have different key sets. Compare the ordinary-map workloads before and after the change to assess common-case overhead. Record workloads, commands, baseline and updated results, and relevant runtime settings. Verify by code review that normalized lookup construction and collision scans occur at most once per map value per cell during row writing; record the reviewed locations and conclusion. This allocation/scan bound is a code-review check supported by the recorded benchmark, not an externally observable unit-test assertion. Do not add production counters solely for tests or timing thresholds in unit tests. Run `./gradlew :matrix-avro:codenarcMain`, then `./gradlew :matrix-avro:codenarcTest`, then `./gradlew :matrix-avro:spotlessCheck`, then `./gradlew :matrix-avro:test`; record the exact commands and results before marking complete.

## 2. [P2] Preserve column type metadata when reading

- Location: `MatrixAvroReader.groovy`, `readInternal`, line 489 at review time.
- The reader builds the Matrix without supplying column types, leaving every column declared as `Object` despite having an effective Avro schema.
- Reproduced with empty and all-null integer columns: their imported Matrix type is `Object`, so exporting them again loses the numeric schema and infers a string schema.

2.1 [x] Derive Matrix column types from the effective Avro schema according to what `convertValue` returns, rather than reusing the writer mapping or `AvroSchemaDecl.SCALAR_TYPE_BY_CLASS`. For unions, ignore null branches and derive the Java class for every remaining branch. Unwrap single-option unions, including those without null. If all non-null branches yield the same Java class, use that class; call a union heterogeneous only when those classes differ, and use `Object` in that case. Use `Object` for a null-only schema or union. Map UUID to String; timestamp-millis and timestamp-micros to Instant; marked scale-zero bytes decimals to BigInteger and other decimals to BigDecimal; BYTES and FIXED to byte[]; ENUM to String; ARRAY to List; MAP and RECORD to Map. Match the reader's date, time, local timestamp, and primitive conversions as well. Unknown logical types must fall back to their underlying Avro type, consistently with value conversion.

2.2 [x] Add a column type assertion next to the value assertion for each conversion kind in 2.1, including nullable and heterogeneous unions, unknown logical types, and reader-schema evolution. Cover empty and all-null typed columns and their repeated export. Include single-option unions without null, `[null, string, enum]` as String, and `[null, bytes, fixed]` as byte[], alongside a union whose non-null branches return different classes. Add read-then-write schema assertions showing that FLOAT stays FLOAT and LONG stays LONG even when all values fit in 32 bits; these paths previously inferred DOUBLE and INT respectively (traced during review, not yet reproduced). Run `./gradlew :matrix-avro:codenarcMain`, then `./gradlew :matrix-avro:codenarcTest`, then `./gradlew :matrix-avro:spotlessCheck`, then `./gradlew :matrix-avro:test`; record the exact commands and results before marking complete.

2.3 [x] Update the README and 0.3.2 release notes to explain that imported columns now carry schema-derived types instead of always being Object. Call out the effect on `matrix.type(col)` and type comparisons. Explain that read-then-write pipelines now preserve FLOAT and small-valued LONG column types instead of inferring DOUBLE and INT, changing the generated schemas seen by downstream consumers with fixed reader schemas. Do not imply full preservation of original Avro schemas: types such as enum and fixed still use their converted Java representations.

- Primitive schema mapping omits `Byte` and `Short`, so these declared numeric types fall through to `STRING`.

Map wrapper and primitive variants of Byte and Short to Avro `INT` in scalar and nested paths while preserving special decimal/BigInteger handling. Explicitly accept widening to Integer on read; do not add Byte/Short preservation markers. Document that widening in the README and release notes.

3.2 [x] Add regression coverage for both types and their primitive variants, plus Byte/Short values inside lists, maps, and records. Assert Avro INT schemas, numeric values, and Integer types on read. Accept rejection of mixed lists such as `[(short) 1, 'a']` when their first non-null element selects INT, consistent with existing Integer behavior; verify the equivalent Byte and Integer cases and the resulting schema error. This mixed-list behavior was traced, not reproduced during the review. ### Map-key cache review

- `MatrixAvroWriter.writeRows` creates one `AvroWriteContext` per cell and passes it to compatibility checking, recursive conversion, and union selection. The first map uses an identity-compared slot; additional nested maps use an `IdentityHashMap`. Contexts are discarded after the cell.
- `AvroWriteContext.keys` performs null/collision validation only on a cache miss. Exact allowlisted String-key maps reuse the original input without a normalized-key Set or lookup-map allocation. On the first non-String key, previously visited String keys seed the validation table once; subsequent keys receive collision checks in the same traversal. This prefix seeding does not rerun collision checks. Wrapped identity maps and comparator-based TreeMaps use full validation.
- `AvroWriteContext.MapKeys.getNormalized` builds and caches a lookup view only when needed (first missing record key, MAP serialization, or inference). `value` tries direct lookup first and preserves present-null values. Ordinary String-key maps use their original map for missing optional fields. No field-by-field key rescanning or repeated collision validation occurs during compatibility/conversion/union probes.
- `scanMapValue` uses a separate inference context and validated normalized keys; `recordFieldSchema` builds fields from `recordKeys`. Inference and writing are separate passes, as planned. The obsolete `recordSample` field was removed.
- Successful scalar compatibility/conversion does not construct nested path strings. Failure paths and container paths retain full context. Null compatibility uses Avro's `Schema.isNullable()` so non-nullable record fields reject missing/null values.
