# Matrix-AVRO v0.3.1 Fix Plan

## Scope

This plan addresses four verified AVRO defects: legal Avro unions with multiple non-null branches cannot be read, `BigInteger` values can be silently corrupted, decimal-safe writes reject or under-profile losslessly-convertible numeric values in mixed columns, and SPI boolean strings are interpreted using Groovy truthiness. The boolean-parser repair is deliberately shared with `matrix-core`, `matrix-csv`, `matrix-parquet`, and `matrix-spreadsheet` so equivalent SPI options do not diverge. Existing `as boolean` uses in `matrix-core` that are not SPI `fromMap(...)` parsing paths (`MatrixBuilder`, `Matrix`, and `RollingWindowOptions`) are outside this fix's scope.

`BigInteger` will always be written losslessly as standard Avro `decimal` over `bytes` with scale `0`, independent of `inferPrecisionAndScale`. This is a deliberate compatibility change: even values that fit in `long` will no longer be written as Avro `long` when the declared or inferred column type is `BigInteger`.

A task is complete only when its focused tests and the section's verification commands pass. Record the exact commands and outcomes in the PR description before changing a checkbox to `[x]`.

## 1. Decode the Actual Branch of Multi-Type Unions

1.1 [ ] Add `AvroSchemaUtil.resolveUnionBranch(Schema unionSchema, Object datum)` in `matrix-avro/src/main/groovy/se/alipsa/matrix/avro/AvroSchemaUtil.groovy`. For a non-null datum, it must delegate branch selection to `GenericData.get().resolveUnion(unionSchema, datum)` and return that indexed branch; do not hand-roll type matching. Preserve null handling in the reader before calling the helper.

1.2 [ ] Route `MatrixAvroReader.convertValue(...)` through the resolved union branch for every union. This must handle Avro raw datum representations such as `Utf8`, `ByteBuffer`, `GenericRecord`, fixed values, enums, arrays, and maps using Avro's own resolver.

1.3 [ ] Extract the writer's recursive `schemaTypeLabel(...)` into `AvroSchemaUtil` and use it from both writer and reader exception paths. Preserve the existing uppercase format, so a union label includes every branch as `UNION[null, int, string]` rather than silently naming its first non-null branch. Document in the AVRO release notes that `AvroConversionException.targetType` for every nullable field now includes its enclosing `UNION[...]`, because target type is a public exception-surface message.

1.4 [ ] Change `MatrixAvroWriter.toRecordAvroValue(...)` to pass each nested field's complete `field.schema()` to `toAvroValue(...)`, allowing `toUnionAvroValue(...)` to resolve nested multi-branch unions if that internal path is ever reached. Remove `AvroSchemaUtil.nonNullSchema(...)` if this eliminates its final use; do not retain a first-non-null helper that can reintroduce the defect. This is a defensive refactor only: public writer declarations currently generate nullable single-type unions, so do not add a public raw-schema/union declaration API or claim public writer coverage for multi-branch unions in this release.

1.5 [ ] Add reader tests in `matrix-avro/src/test/groovy/test/alipsa/matrix/avro/MatrixAvroReaderTest.groovy` using real Avro OCF payloads. Cover each non-null branch of `['null', 'int', 'string']`, plus nested record/collection and logical-type branches, and assert values and resulting Java types. Do not require an `UnresolvedUnionException` regression payload: Avro's decoder resolves legal OCF unions before `MatrixAvroReader` receives the raw datum, so an unmatched union datum cannot be constructed through this public read path.

1.6 [ ] Verify section 1 with `./gradlew :matrix-avro:codenarcMain`, `./gradlew :matrix-avro:spotlessCheck`, and `./gradlew :matrix-avro:test`.

## 2. Preserve Arbitrary BigInteger Values Losslessly

2.1 [ ] Encode inferred and explicitly declared `BigInteger` columns as interoperable Avro `decimal` logical types over `bytes`, with scale `0`. Infer precision from the greatest absolute non-null column value; for an empty or all-null `BigInteger` column, reuse AVRO's package-scoped `ColumnProfile.decimalMeta()` default of precision `10`, scale `0`. `DecimalColumnProfile` supplies raw observed metadata only; it does not own this fallback.

2.2 [ ] Define the Matrix schema property `se.alipsa.matrix.javaType: "java.math.BigInteger"` to avoid collisions with other Avro tools' custom properties. Add it to the inner `bytes` schema carrying the scale-zero decimal, before that schema is wrapped in a nullable union; never add it to the union. `MatrixAvroReader` must return `BigInteger` only when this property is present, the decimal scale is `0`, and the physical type is `BYTES`. Although ordinary Avro decimal reading supports `FIXED`, ignore the marker on `FIXED` and return `BigDecimal`; Matrix writers emit only `BYTES`. A reader schema that omits the property must also follow normal Avro decimal behavior and return `BigDecimal`, preserving schema-evolution interoperability.

2.3 [ ] Add per-position nested numeric profile state to `ColumnProfile` for list elements, map values, and every record-like map field, replacing the current first-non-null sample as the source of numeric precision/scale. Populate it in one O(total nested values) pass, with paths that identify the enclosing column and record field where relevant. Profile every non-null nested `BigInteger` to obtain required scale-zero precision; use `[10, 0]` for an empty nested position. When `inferPrecisionAndScale=true`, use these profiles to write nested BigDecimal-only positions as decimal, aligning them with scalar BigDecimal behavior; when false, retain their existing `double` fallback unless a `BigInteger` requires lossless decimal handling. Apply numeric profiling only when every non-null value at that position is an accepted numeric type; preserve the existing first-non-null schema selection and conversion/failure behavior for positions that mix numeric and nonnumeric values. Extend the existing `MatrixAvroSchemaBenchmark` main class under `matrix-avro/src/test/groovy/se/alipsa/matrix/avro/benchmarks` with a representative large nested-value case and record the baseline/result from `./gradlew :matrix-avro:avroSchemaBenchmark` in the PR to detect unintended super-linear scanning or repeated materialization.

2.4 [ ] Refactor `MatrixAvroWriter` schema inference and conversion so top-level and nested `BigInteger` values use their profiles, never convert through `long`, and never take the `LONG` fallback, regardless of `inferPrecisionAndScale`. For a declared or inferred `BigInteger` column whose values all fit in `long`, still produce the scale-zero decimal schema and marker. Apply exact-long validation to every value written through a resolved `LONG` schema, whether that schema came from an `AvroSchemaDecl`, the Matrix column's declared `Long` type, or inference. For every accepted `Number`, use `longValueExact()` semantics: after first rejecting non-finite `Double`/`Float`, convert them with `new BigDecimal(value.toString())` and then use the exact check. Accept `2.0G` and `2.0d`, but reject `2.5G`, `2.5d`, non-finite values, and values outside `long` range with a clear schema/value error instead of narrowing or truncating.

2.5 [ ] Add a typed `AvroSchemaDecl.bigInteger(int precision)` declaration, validated like `decimal(precision, 0)`, with complete SPI map round-tripping and the same bytes/decimal/marker representation as inference. Remove `BigInteger -> LONG` from `AvroSchemaDecl.SCALAR_TYPE_BY_CLASS`; make `AvroSchemaDecl.type(BigInteger)`, `arrayOf(BigInteger)`, and `mapOf(BigInteger)` fail with guidance to use `bigInteger(precision)`, `array(bigInteger(precision))`, or `map(bigInteger(precision))`, because the class-only forms cannot supply precision. Keep public APIs specifically typed rather than adding `Object` overloads.

2.6 [ ] Define mixed `Object`-column and nested-value inference explicitly. A numeric position containing at least one `BigInteger` and no `BigDecimal`, `Double`, or `Float` must be a marked scale-zero decimal and read every non-null value back as `BigInteger`, even when all values fit in `long`. If that position also contains `BigDecimal`, `Double`, or `Float`, write an unmarked standard decimal with profiled precision and scale; all non-null values, including original integers and `BigInteger`s, read back as `BigDecimal` at the column scale (for example, `1` reads as `1.00G` for scale `2`). A `BigInteger` forces this decimal behavior even when `inferPrecisionAndScale=false`. A BigDecimal-only scalar or nested position writes a profiled decimal when the flag is true, while a BigDecimal, `Double`, or `Float` position with no `BigInteger` retains the existing `double` fallback when the flag is false. Apply these rules to scalar columns and the nested positions profiled in 2.3, preventing the existing `Double` fallback from losing a large `BigInteger`.

2.7 [ ] Add writer, declaration, and round-trip tests in `matrix-avro/src/test/groovy/test/alipsa/matrix/avro/MatrixAvroWriterTest.groovy`, `MatrixAvroRoundTripTest.groovy`, and a new `AvroSchemaDeclTest.groovy`. Extend `AvroFormatProviderTest.groovy` for the declaration SPI map round-trip. Cover values above `Long.MAX_VALUE`, below `Long.MIN_VALUE`, zero, multiple digit lengths, all-null/empty scalar and nested positions, and a `BigInteger` column whose values all fit in `long`. Cover scalar and nested `BigInteger` mixed with `BigDecimal`, `Double`, and `Float`, plus nested BigDecimal-only values, under both values of `inferPrecisionAndScale`. Assert physical type, logical type, scale, precision, marker placement, Java result class and value, explicit-declaration SPI round-trip, unmarked reader-schema evolution returning `BigDecimal`, and rejection for every resolved `LONG` schema source with out-of-range, fractional, and non-finite numeric inputs.

2.8 [ ] Update `matrix-avro/README.md` and `matrix-avro/release.md` with direct and SPI examples for automatic and explicit BigInteger handling. Replace the type-table entry `Long, BigInteger -> long` with separate `Long -> long` and `BigInteger -> bytes decimal(precision, 0)` entries. Document the marker name, placement, reader-schema evolution behavior, all-null defaults for scalar and nested positions, and the compatibility change for existing generic consumers. Explicitly document the `inferPrecisionAndScale=false` asymmetry: non-BigInteger decimal/floating positions use their existing `double` fallback, while any position containing `BigInteger` remains a lossless decimal. Document that nested BigDecimal-only positions newly follow the scalar decimal behavior when the flag is true.

2.9 [ ] Verify section 2 with `./gradlew :matrix-avro:codenarcMain`, `./gradlew :matrix-avro:spotlessCheck`, and `./gradlew :matrix-avro:test`.

## 3. Support Mixed Numeric Values in Decimal-Safe Writes

3.1 [ ] Define decimal-safe conversion in `MatrixAvroWriter`: `Byte`, `Short`, `Integer`, `Long`, and `BigInteger` are losslessly converted to `BigDecimal`; `BigDecimal` is retained; finite `Double` and `Float` are converted with `new BigDecimal(value.toString()).setScale(decimalSchema.scale, HALF_UP)`. Use this one schema-driven path for inferred and declared decimal schemas; inferred metadata from 3.3 makes the scale operation numerically lossless, including values expressed with a negative scale such as `1.0E10`. Reject `NaN`, positive infinity, and negative infinity during schema analysis with a column-qualified `AvroSchemaException` (and a nested value path where applicable), rather than leaking `NumberFormatException` or converting them to null. The same accepted types must be used consistently by compatibility validation, conversion, and profiling.

3.2 [ ] Update `isLogicalTypeCompatible('decimal')` and `toDecimalAvroValue(...)` so an inferred or declared decimal accepts the types from 3.1. Preserve the existing failure for unsupported values rather than attempting coercion through strings or an untyped `Object` API.

3.3 [ ] Profile every accepted finite `Number`, including `Double` and `Float`, through `DecimalColumnProfile` before an inferred decimal schema is constructed. `Double` and `Float` contribute their `toString()` decimal expansion to inferred precision and scale, ensuring the common conversion path in 3.1 does not change their numeric value. For declared decimal schemas, use the same conversion path and validate that the rounded value fits the declared precision; retain the contextual write-time failure when it does not. Ensure inferred metadata accommodates negative values, large integrals, decimals, and finite floating-point values without `DecimalConversion.toBytes` overflow.

3.4 [ ] Add round-trip tests in `matrix-avro/src/test/groovy/test/alipsa/matrix/avro/MatrixAvroRoundTripTest.groovy` for mixed `Object` columns containing integral values, `BigInteger`, `BigDecimal`, `Double`/`Float`, nulls, negative values, and large values. Include `BigInteger` plus fractional `Double`/`Float`, a floating-point value with a negative decimal scale such as `1.0E10`, and `NaN`/both infinities, the latter asserting the column-qualified analysis error. Assert decimal schema metadata, exact value, and runtime class; specifically assert inferred decimal schemas do not numerically change finite `Double`/`Float` values. In particular, assert the mixed `BigInteger`/decimal-or-floating contract from 2.6: all values return as `BigDecimal` at the schema scale, rather than relying on Groovy's scale-insensitive `==` alone.

3.5 [ ] Update `matrix-avro/README.md` with an end-to-end decimal-safe write example and document accepted mixed numeric inputs, inferred precision/scale, the single schema-driven `Double`/`Float` conversion rule, and declared-schema rounding. Also document the `inferPrecisionAndScale=false` asymmetry: ordinary decimal/floating positions retain their `double` fallback, but a position containing `BigInteger` is decimal to preserve its value; nested BigDecimal-only positions newly use decimals when the flag is true.

3.6 [ ] Verify section 3 with `./gradlew :matrix-avro:codenarcMain`, `./gradlew :matrix-avro:spotlessCheck`, and `./gradlew :matrix-avro:test`.

## 4. Parse SPI Boolean Options Strictly and Once

4.1 [ ] Move CSV's strict boolean parsing behavior into `matrix-core/src/main/groovy/se/alipsa/matrix/core/spi/OptionMaps.groovy` as a nullable `Boolean`-returning API next to `stringValueOrNull`. It must accept `Boolean`, and trimmed, case-insensitive `CharSequence` values `true` and `false`; return `null` for `null`; and reject every other value with an option-specific `IllegalArgumentException`.

4.2 [ ] Change `CsvOptionUtil.booleanValue(...)` to delegate to the shared parser and retain its non-null primitive contract by rejecting a `null` result. This removes the duplicate parser without changing CSV's existing null rejection or whitespace/case behavior.

4.3 [ ] Replace Groovy truthiness conversion with `OptionMaps` in `AvroWriteOptions.fromMap(...)`, `ParquetWriteOptions.fromMap(...)`, and `SpreadsheetReadOptions.fromMap(...)`. Preserve each option's existing absent/null default behavior, including AVRO and Parquet `inferPrecisionAndScale`, while making string configuration values strict and consistent.

4.4 [ ] Add focused tests in the relevant AVRO, CSV, Parquet, Spreadsheet, and core test suites. Cover real Booleans; `TRUE`, `False`, and whitespace-padded strings; absent and null values; invalid strings; and non-string values including numeric `1` and `0`, which must be rejected rather than following `ValueConverter.asBoolean` semantics. Add an AVRO SPI write proving `'false'` selects the non-decimal `BigDecimal` fallback schema. Assert each caller's documented null/default behavior.

4.5 [ ] Update `matrix-avro/README.md` and option descriptions where needed to document actual Boolean values and accepted string forms for configuration-backed callers. Keep CSV's current externally documented strict behavior unchanged.
