# Matrix-AVRO v0.3.1 Fix Plan

## Scope

This plan addresses four verified AVRO defects: legal Avro unions with multiple non-null branches cannot be read, `BigInteger` values can be silently corrupted, decimal-safe writes reject or under-profile losslessly-convertible numeric values in mixed columns, and SPI boolean strings are interpreted using Groovy truthiness. The boolean-parser repair is deliberately shared with `matrix-core`, `matrix-csv`, `matrix-parquet`, and `matrix-spreadsheet` so equivalent SPI options do not diverge.

`BigInteger` will always be written losslessly as standard Avro `decimal` over `bytes` with scale `0`, independent of `inferPrecisionAndScale`. This is a deliberate compatibility change: even values that fit in `long` will no longer be written as Avro `long` when the declared or inferred column type is `BigInteger`.

A task is complete only when its focused tests and the section's verification commands pass. Record the exact commands and outcomes in the PR description before changing a checkbox to `[x]`.

## 1. Decode the Actual Branch of Multi-Type Unions

1.1 [ ] Add `AvroSchemaUtil.resolveUnionBranch(Schema unionSchema, Object datum)` in `matrix-avro/src/main/groovy/se/alipsa/matrix/avro/AvroSchemaUtil.groovy`. For a non-null datum, it must delegate branch selection to `GenericData.get().resolveUnion(unionSchema, datum)` and return that indexed branch; do not hand-roll type matching. Preserve null handling in the reader before calling the helper.

1.2 [ ] Route `MatrixAvroReader.convertValue(...)` through the resolved union branch for every union. This must handle Avro raw datum representations such as `Utf8`, `ByteBuffer`, `GenericRecord`, fixed values, enums, arrays, and maps using Avro's own resolver.

1.3 [ ] Extract the writer's recursive `schemaTypeLabel(...)` into `AvroSchemaUtil` and use it from both writer and reader exception paths. A union label must include every branch (for example, `union[null, int, string]`) rather than silently naming its first non-null branch.

1.4 [ ] Change `MatrixAvroWriter.toRecordAvroValue(...)` to pass each nested field's complete `field.schema()` to `toAvroValue(...)`, allowing `toUnionAvroValue(...)` to resolve nested multi-branch unions. Remove `AvroSchemaUtil.nonNullSchema(...)` if this eliminates its final use; do not retain a first-non-null helper that can reintroduce the defect.

1.5 [ ] Add reader and writer tests in `matrix-avro/src/test/groovy/test/alipsa/matrix/avro/MatrixAvroReaderTest.groovy` and `MatrixAvroWriterTest.groovy` using real Avro OCF payloads. Cover each non-null branch of `['null', 'int', 'string']`, plus nested record/collection and logical-type branches. Assert values, resulting Java types, and full-union conversion-error labels.

1.6 [ ] Verify section 1 with `./gradlew :matrix-avro:codenarcMain`, `./gradlew :matrix-avro:spotlessCheck`, and `./gradlew :matrix-avro:test`.

## 2. Preserve Arbitrary BigInteger Values Losslessly

2.1 [ ] Encode inferred and explicitly declared `BigInteger` columns as interoperable Avro `decimal` logical types over `bytes`, with scale `0`. Infer precision from the greatest absolute non-null column value; for an empty or all-null `BigInteger` column, reuse `DecimalColumnProfile.decimalMeta()`'s existing default of precision `10`, scale `0`.

2.2 [ ] Define the Matrix schema property `matrixJavaType: "java.math.BigInteger"`. Add it to the inner `bytes` schema carrying the scale-zero decimal, before that schema is wrapped in a nullable union; never add it to the union. `MatrixAvroReader` must return `BigInteger` only when this property is present and the decimal scale is `0`. A reader schema that omits the property must follow normal Avro decimal behavior and return `BigDecimal`, which preserves schema-evolution interoperability.

2.3 [ ] Refactor `MatrixAvroWriter` profiling and schema inference so `BigInteger` never converts through `long` and never takes the `LONG` fallback, regardless of `inferPrecisionAndScale`. For a declared or inferred `BigInteger` column whose values all fit in `long`, still produce the scale-zero decimal schema and marker. Generalize explicit `LONG` validation to every accepted `Number`: accept only finite, integral values exactly representable in `long` range; reject fractional, non-finite, or out-of-range values with a clear schema/value error instead of calling `longValue()` and narrowing or truncating.

2.4 [ ] Add a typed `AvroSchemaDecl.bigInteger(int precision)` declaration, validated like `decimal(precision, 0)`, with complete SPI map round-tripping and the same bytes/decimal/marker representation as inference. Remove `BigInteger -> LONG` from `AvroSchemaDecl.SCALAR_TYPE_BY_CLASS`; make `AvroSchemaDecl.type(BigInteger)` fail with guidance to use `bigInteger(precision)`, since `type(Class)` cannot supply required precision. Keep public APIs specifically typed rather than adding `Object` overloads.

2.5 [ ] Define mixed integral `Object`-column inference explicitly. A column containing at least one `BigInteger` and no `BigDecimal` must be a marked scale-zero decimal and read every non-null value back as `BigInteger`, even when all values fit in `long`. A column containing `BigInteger` and `BigDecimal` must be an unmarked standard decimal with inferred precision and scale; all non-null values, including original integers and `BigInteger`s, read back as `BigDecimal` at the column scale (for example, `1` reads as `1.00G` for scale `2`).

2.6 [ ] Add writer, declaration, and round-trip tests in `matrix-avro/src/test/groovy/test/alipsa/matrix/avro/MatrixAvroWriterTest.groovy`, `MatrixAvroRoundTripTest.groovy`, and declaration tests. Cover values above `Long.MAX_VALUE`, below `Long.MIN_VALUE`, zero, multiple digit lengths, all-null/empty columns, and a `BigInteger` column whose values all fit in `long`. Assert physical type, logical type, scale, precision, marker placement, Java result class and value, explicit-declaration SPI round-trip, unmarked reader-schema evolution returning `BigDecimal`, and rejection for explicitly forced `LONG` with out-of-range, fractional, and non-finite numeric inputs.

2.7 [ ] Update `matrix-avro/README.md` and `matrix-avro/release.md` with direct and SPI examples for automatic and explicit BigInteger handling. Replace the type-table entry `Long, BigInteger -> long` with separate `Long -> long` and `BigInteger -> bytes decimal(precision, 0)` entries. Document the marker name, placement, reader-schema evolution behavior, all-null precision default, and the compatibility change for existing generic consumers.

2.8 [ ] Verify section 2 with `./gradlew :matrix-avro:codenarcMain`, `./gradlew :matrix-avro:spotlessCheck`, and `./gradlew :matrix-avro:test`.

## 3. Support Mixed Numeric Values in Decimal-Safe Writes

3.1 [ ] Define decimal-safe conversion in `MatrixAvroWriter`: `Byte`, `Short`, `Integer`, `Long`, and `BigInteger` are losslessly converted to `BigDecimal`; `BigDecimal` is retained; `Double` and `Float` retain the existing `HALF_UP` rounding to the selected schema scale. The same accepted types must be used consistently by compatibility validation, conversion, and profiling.

3.2 [ ] Update `isLogicalTypeCompatible('decimal')` and `toDecimalAvroValue(...)` so an inferred or declared decimal accepts the types from 3.1. Preserve the existing failure for unsupported values rather than attempting coercion through strings or an untyped `Object` API.

3.3 [ ] Profile every accepted `Number`, including `Double` and `Float`, through `DecimalColumnProfile` before a decimal schema is constructed. Ensure inferred precision and scale accommodate negative values, large integrals, decimals, and the rounded floating-point values that will actually be encoded, preventing `DecimalConversion.toBytes` overflow at write time.

3.4 [ ] Add round-trip tests in `matrix-avro/src/test/groovy/test/alipsa/matrix/avro/MatrixAvroRoundTripTest.groovy` for mixed `Object` columns containing integral values, `BigInteger`, `BigDecimal`, `Double`/`Float`, nulls, negative values, and large values. Assert decimal schema metadata and both exact value and runtime class. In particular, assert the mixed `BigInteger`/`BigDecimal` contract from 2.5: all values return as `BigDecimal` at the schema scale, rather than relying on Groovy's scale-insensitive `==` alone.

3.5 [ ] Update `matrix-avro/README.md` with an end-to-end decimal-safe write example and document accepted mixed numeric inputs, inferred precision/scale, and `Double`/`Float` rounding.

3.6 [ ] Verify section 3 with `./gradlew :matrix-avro:codenarcMain`, `./gradlew :matrix-avro:spotlessCheck`, and `./gradlew :matrix-avro:test`.

## 4. Parse SPI Boolean Options Strictly and Once

4.1 [ ] Move CSV's strict boolean parsing behavior into `matrix-core/src/main/groovy/se/alipsa/matrix/core/spi/OptionMaps.groovy` as a nullable `Boolean`-returning API next to `stringValueOrNull`. It must accept `Boolean`, and trimmed, case-insensitive `CharSequence` values `true` and `false`; return `null` for `null`; and reject every other value with an option-specific `IllegalArgumentException`.

4.2 [ ] Change `CsvOptionUtil.booleanValue(...)` to delegate to the shared parser and retain its non-null primitive contract by rejecting a `null` result. This removes the duplicate parser without changing CSV's existing null rejection or whitespace/case behavior.

4.3 [ ] Replace Groovy truthiness conversion with `OptionMaps` in `AvroWriteOptions.fromMap(...)`, `ParquetWriteOptions.fromMap(...)`, and `SpreadsheetReadOptions.fromMap(...)`. Preserve each option's existing absent/null default behavior, including AVRO and Parquet `inferPrecisionAndScale`, while making string configuration values strict and consistent.

4.4 [ ] Add focused tests in the relevant AVRO, CSV, Parquet, Spreadsheet, and core test suites. Cover real Booleans; `TRUE`, `False`, and whitespace-padded strings; absent and null values; invalid strings and non-string values; and an AVRO SPI write proving `'false'` selects the non-decimal `BigDecimal` fallback schema. Assert each caller's documented null/default behavior.

4.5 [ ] Update `matrix-avro/README.md` and option descriptions where needed to document actual Boolean values and accepted string forms for configuration-backed callers. Keep CSV's current externally documented strict behavior unchanged.

4.6 [ ] Verify section 4 in dependency order: `./gradlew :matrix-core:codenarcMain`, `./gradlew :matrix-core:spotlessCheck`, `./gradlew :matrix-core:test`; `./gradlew :matrix-csv:codenarcMain`, `./gradlew :matrix-csv:spotlessCheck`, `./gradlew :matrix-csv:test`; `./gradlew :matrix-parquet:codenarcMain`, `./gradlew :matrix-parquet:spotlessCheck`, `./gradlew :matrix-parquet:test`; `./gradlew :matrix-spreadsheet:codenarcMain`, `./gradlew :matrix-spreadsheet:spotlessCheck`, `./gradlew :matrix-spreadsheet:test`; then `./gradlew :matrix-avro:codenarcMain`, `./gradlew :matrix-avro:spotlessCheck`, and `./gradlew :matrix-avro:test`.
