**Goal:** Fix the issues found in the code review of `matrix-smile` (2026-09-15): a `SmileClassifier.confusionMatrix()`/`evaluate()` crash whenever a test set doesn't contain every class seen during training, a missing minimum-sample guard on `SmileStats.poissonFit(Matrix, String)`, a missing `bins >= 1` guard in `SmileFeatures.binning(Matrix, String, int)`, silent no-ops on typo'd/unknown column names across several `SmileFeatures` transforms, and a `SmileData.trainTestSplit` edge case that can produce a zero-row training set.

Ordering: the crash bug with real-world reach first (§1), then the two missing-validation bugs that produce silently-wrong output (§2, §3), then the more pervasive silent-no-op gap across several transform methods (§4), then the lower-severity non-stratified split edge case (§5), then verification and release notes (§6).

**Tech Stack:** Groovy 5.1.1 (static compilation enforced globally for `src/main`), JUnit Jupiter 6, `groovier-junit`, Smile 4.4.2.

**Module state:** `matrix-smile` is already at `0.2.1-SNAPSHOT` (`matrix-smile/build.gradle:12`) — no version bump needed before starting.

**Spec:** The review findings are reproduced in the "Findings" appendix at the bottom of this file. Findings 2–10 from the prior review round (documented in `BugVerificationTest.groovy` and `matrix-smile/release.md` under `## v0.2.0`) are already fixed and verified passing — this plan covers only the newly identified issues.

## 1. `SmileClassifier.confusionMatrix()` / `evaluate()` throw `ArrayIndexOutOfBoundsException` when the test set doesn't cover every trained class

`smile.validation.metric.ConfusionMatrix.of(truth, prediction)` sizes its returned `int[][]` as `(maxObservedClassIndex + 1)²`, based only on the class indices actually *present* in the `truth`/`prediction` arrays passed to it — not on the number of classes the model was trained with. `confusionMatrix()` and `evaluate()` both then index that matrix with loops bounded by `classLabels.length` (the full training-time class count). If the test set doesn't contain every class seen during training (small/imbalanced test splits, stratified holdouts of rare classes, k-fold folds, etc.), the returned matrix is smaller than `classLabels.length`, and both methods throw `ArrayIndexOutOfBoundsException`.

Verified: training a `decisionTree` on 3 classes (`A`/`B`/`C`), then calling `confusionMatrix()`/`evaluate()` on a test set containing only `A`/`B` → `ArrayIndexOutOfBoundsException: Index 2 out of bounds for length 2` from both methods.

1.1 [ ] Add a failing regression test in `matrix-smile/src/test/groovy/SmileClassifierTest.groovy`, e.g. `testConfusionMatrixAndEvaluateHandleTestSetMissingAClass`:
    - Reuse (or closely mirror) the existing `createIrisLikeData()` 3-class fixture (`species`: e.g. `setosa`/`versicolor`/`virginica`), trained via `SmileClassifier.decisionTree(trainData, 'species')` (not `randomForest` — see the Global Constraints note above).
    - Build a small test `Matrix` containing rows for only **two** of the three trained species (omit the third entirely).
    - Call `classifier.confusionMatrix(testData)` and `classifier.evaluate(testData)`; assert both return successfully (no exception) rather than `assertThrows` (the fix must make these *succeed*, not merely change the exception type).
    - Assert the returned `confusionMatrix()` `Matrix` still has one row and one `pred_*` column **per trained class** (3, matching `classifier.classLabels.length`), including the omitted species, with all-zero counts in the omitted species' row/column.
    - Assert the returned `evaluate()` `Matrix` still has one row per trained class (3), including the omitted species, with `support == 0` and `precision`/`recall`/`f1` following the existing 0-denominator convention (`0.0d`) already used elsewhere in `evaluate()`.
    - Run: `./gradlew :matrix-smile:test --tests "SmileClassifierTest" --rerun-tasks` and confirm the new assertions fail against the current implementation (the exact `ArrayIndexOutOfBoundsException` above) before fixing it.

1.2 [ ] Fix `SmileClassifier.groovy` (`matrix-smile/src/main/groovy/se/alipsa/matrix/smile/ml/SmileClassifier.groovy`) to stop relying on `ConfusionMatrix.of(...)`'s auto-sized matrix. Add a private helper that builds a matrix sized explicitly to the known class count:
    ```groovy
    private static int[][] buildConfusionCounts(int[] actual, int[] predicted, int numClasses) {
      int[][] counts = new int[numClasses][numClasses]
      for (int i = 0; i < actual.length; i++) {
        counts[actual[i]][predicted[i]]++
      }
      counts
    }
    ```
    (Safe because `actual` comes from `extractTargetAsInt`, which already throws `IllegalArgumentException` for any label not in `classLabels`, and `predicted` comes from `model.predict(df)`, which only ever returns indices `0..classLabels.length-1` for a model trained via `encodeTarget`/`classLabels` — both arrays are guaranteed in-range.)
    Replace the `ConfusionMatrix cm = ConfusionMatrix.of(actual, predicted); int[][] matrix = cm.matrix()` lines in both `confusionMatrix()` (~line 173) and `evaluate()` (~line 211) with `int[][] matrix = buildConfusionCounts(actual, predicted, classLabels.length)`. Remove the now-unused `import smile.validation.metric.ConfusionMatrix` if nothing else in the file references it.

1.3 [ ] Run `./gradlew :matrix-smile:test --tests "SmileClassifierTest" --rerun-tasks` and confirm all tests (new and existing) pass.

1.4 [ ] Record the fix in `matrix-smile/release.md` under a new `## v0.2.1` → `### Bug Fixes` heading.

## 2. `SmileStats.poissonFit(Matrix, String)` is missing the minimum-sample guard its sibling `*Fit` methods have

Every other `*Fit(Matrix, String)` method (`normalFit`, `exponentialFit`, `gammaFit`, `betaFit`, `logNormalFit`) calls `requireMinimumSamples(compacted, MINIMUM_SAMPLES, "...")` before fitting, producing a clear `IllegalArgumentException` for too-few non-null values. `poissonFit(Matrix, String)` skips this check.

Verified: `SmileStats.poissonFit(matrix, 'x')` on a column with 0 non-null values returns `PoissonDistribution(NaN)` with no exception, instead of failing loudly like its siblings.

2.1 [ ] Add a failing regression test in `matrix-smile/src/test/groovy/SmileStatsTest.groovy`, e.g. `testPoissonFitOnColumnTooFewSamplesThrows`:
    - Build a `Matrix` with an `Integer` column containing 0 non-null values (e.g. all `null`, or an empty column) and assert `SmileStats.poissonFit(matrix, 'x')` throws `IllegalArgumentException` mentioning `'x'` and the minimum sample count — mirror the existing assertion style used for `normalFit`/`exponentialFit`'s minimum-sample tests in this file.
    - Add a second case with exactly 1 non-null value, also asserting it throws (matching `MINIMUM_SAMPLES = 2`).
    - Run: `./gradlew :matrix-smile:test --tests "SmileStatsTest" --rerun-tasks` and confirm the new test fails against the current implementation (no exception, `PoissonDistribution(NaN)` returned) before fixing it.

2.2 [ ] Fix `poissonFit(Matrix, String)` in `matrix-smile/src/main/groovy/se/alipsa/matrix/smile/stats/SmileStats.groovy` (~line 115):
    ```groovy
    static PoissonDistribution poissonFit(Matrix matrix, String column) {
      int[] compacted = toIntArray(matrix, column)
      requireMinimumSamples(compacted, MINIMUM_SAMPLES, "poissonFit on column '$column'")
      poissonFit(compacted)
    }
    ```
    Note `requireMinimumSamples` is currently typed to accept `double[]` (used by every other `*Fit(Matrix, String)` caller). Add a same-named `int[]` overload rather than duplicating the length-check logic; retain the existing `double[]` overload unchanged. This is unambiguous under `@CompileStatic`: the local `compacted` variable is explicitly `int[]`, so its call resolves to the `int[]` overload, while all existing `double[]` callers continue to resolve to their exact overload. Do not route this through `def`, `Object`, or an array cast. Confirm the module compiles when running the task's test command.
    ```groovy
    private static void requireMinimumSamples(int[] data, int minimum, String context) {
      if (data.length < minimum) {
        throw new IllegalArgumentException(
            "$context requires at least $minimum non-null values, but found ${data.length}. " +
            'Use SmileFeatures.dropna() or fillna() before computing statistics.')
      }
    }
    ```

2.3 [ ] Run `./gradlew :matrix-smile:test --tests "SmileStatsTest" --rerun-tasks` and confirm all tests pass.

## 3. `SmileFeatures.binning(matrix, column, bins)` doesn't validate `bins >= 1`

## 4. Several `SmileFeatures` transforms silently no-op on an unknown/typo'd column name

`standardize(matrix, columns)`, `normalize(matrix, columns)` (both the 2-arg and the 4-arg min/max overload), `logTransform(matrix, columns)`, and `sqrtTransform(matrix, columns)` all iterate the matrix's *existing* columns and check `columns.contains(colName)` — none of them verify that every name the caller passed in `columns` was actually found. A typo'd column name is silently ignored: no exception, matrix returned unchanged for that column.

Verified: `SmileFeatures.standardize(data, ['xx_typo'])` returns the matrix completely unchanged with no error, where `data` has no `xx_typo` column.

This is inconsistent with `dropna(matrix, columns)` (already fixed in v0.2.0 — see `BugVerificationTest.testDropnaSpecificColumnsThrowsForUnknownColumnName`), which explicitly validates `columns` against `matrix.columnNames()` and throws `IllegalArgumentException` naming the bad column. It's also inconsistent with `StandardScaler.fit`/`MinMaxScaler.fit`, which call `matrix.column(col)` directly per requested column and so already fail for an unknown name.

4.1 [ ] Add failing regression tests in `matrix-smile/src/test/groovy/SmileFeaturesTest.groovy`, one per affected method (name them individually, e.g. `testStandardizeUnknownColumnNameThrows`, `testNormalizeUnknownColumnNameThrows`, `testNormalizeToRangeUnknownColumnNameThrows`, `testLogTransformUnknownColumnNameThrows`, `testSqrtTransformUnknownColumnNameThrows`):
    - For each, build a small numeric `Matrix` (e.g. a single `x` column) and assert calling the method with `['nonexistent']` (or `['x', 'nonexistent']` to also confirm the valid column doesn't mask the bad one) throws `IllegalArgumentException` whose message contains `nonexistent` — mirror the assertion style of `BugVerificationTest.testDropnaSpecificColumnsThrowsForUnknownColumnName`.
    - Run: `./gradlew :matrix-smile:test --tests "SmileFeaturesTest" --rerun-tasks` and confirm all five fail against the current implementation (silent no-op, no exception) before fixing it.

4.2 [ ] Add a shared validation helper in `SmileFeatures.groovy` next to the other private helpers (~line 484), mirroring `dropna(matrix, columns)`'s existing inline check:
    ```groovy

      List<String> knownColumns = matrix.columnNames()
    ```

## 5. `SmileData.trainTestSplit` can produce a zero-row training set

`testRatio` is validated only to be strictly between 0 and 1 (`testRatio <= 0.0 || testRatio >= 1.0` throws). `testSize` is computed as `Math.max(1, (int) Math.round(rowCount * testRatio))`, with no corresponding floor on the resulting `trainSize = rowCount - testSize`.

Verified: `trainTestSplit(matrix, 0.99, false)` on a 2-row matrix returns `train.rowCount() == 0`. The existing `MIN_PARTITION = 2` check only guards `rowCount` itself, not the post-split `trainSize`.

5.1 [ ] Add a failing regression test in `matrix-smile/src/test/groovy/SmileDataTest.groovy`, e.g. `testTrainTestSplitDoesNotProduceEmptyTrainingSet`:

    - Add a second case confirming a reasonable split (e.g. `rowCount = 10, testRatio = 0.9`, which still leaves `trainSize = 1`) continues to succeed — this pins the boundary at "train must have at least 1 row," not something stricter.
    - Run: `./gradlew :matrix-smile:test --tests "SmileDataTest" --rerun-tasks` and confirm the first assertion fails against the current implementation (returns a 0-row train `Matrix` instead of throwing) before fixing it.

5.2 [ ] Fix `trainTestSplit(Matrix, double, boolean, Random)` in `matrix-smile/src/main/groovy/se/alipsa/matrix/smile/data/SmileData.groovy` (~line 56): after computing `trainSize`, add:

## Findings (review source, 2026-09-15)

1. **`matrix-smile/src/main/groovy/se/alipsa/matrix/smile/ml/SmileClassifier.groovy:168-198, 206-260`** — `confusionMatrix()` and `evaluate()` both call `ConfusionMatrix.of(actual, predicted)` and then index the resulting matrix with loops bounded by `classLabels.length`. Smile's `ConfusionMatrix.of()` sizes its matrix based on the maximum class index actually present in `actual`/`predicted`, not on the full trained class count, so a test set missing any trained class produces a smaller matrix and both methods throw `ArrayIndexOutOfBoundsException`. Verified via a 3-class `decisionTree` evaluated against a 2-class-only test set.

2. **`matrix-smile/src/main/groovy/se/alipsa/matrix/smile/stats/SmileStats.groovy:115-117`** — `poissonFit(Matrix, String)` omits the `requireMinimumSamples(...)` guard present on every sibling `*Fit(Matrix, String)` method, so fitting on 0 or 1 non-null values silently returns `PoissonDistribution(NaN)` instead of a clear `IllegalArgumentException`.

3. **`matrix-smile/src/main/groovy/se/alipsa/matrix/smile/data/SmileFeatures.groovy:266-281`** — `binning(Matrix, String, int)` doesn't validate `bins >= 1`; `bins <= 0` produces nonsensical negative bin labels (verified `bins=0` → all rows `-1`, `bins=-2` → all rows `-3`) instead of throwing.

4. **`matrix-smile/src/main/groovy/se/alipsa/matrix/smile/data/SmileFeatures.groovy` (`transformColumns` helper ~line 486, and the `columns.contains(colName)` loops in `logTransform`/`sqrtTransform`)** — `standardize`, `normalize` (both overloads), `logTransform`, and `sqrtTransform` never verify that every caller-supplied column name in `columns` actually exists in the matrix; an unknown/typo'd name is silently ignored rather than raising an error, unlike `dropna(matrix, columns)` (already fixed in v0.2.0) and the `StandardScaler`/`MinMaxScaler` classes (which already fail loudly via direct `matrix.column(col)` calls).

5. **`matrix-smile/src/main/groovy/se/alipsa/matrix/smile/data/SmileData.groovy:56-81`** — `trainTestSplit` validates `testRatio` is in `(0, 1)` and that `rowCount >= MIN_PARTITION`, but never guards the post-split `trainSize`. A small `rowCount` combined with a `testRatio` close to 1 can round `testSize` up to the full row count, leaving `trainSize = 0` (verified: `rowCount=2, testRatio=0.99` → 0 training rows) with no error. `stratifiedSplit` is not affected because its per-class cap preserves at least one training row for every class.
