# matrix-tablesaw v0.4.0 Review Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this

**Goal:** Fix the 15 findings from the 2026-09-16 review of `matrix-tablesaw` (8 reproduced bugs,
7 consistency issues) before 0.4.0 is released, without introducing new public API beyond what
the findings require.

**Architecture:** Every fix is local to the file named in its task. Groovy facade fixes
(`Gtable`, `Normalizer`, `TableUtil`) get Groovy JUnit tests; `tech.tablesaw.*` Java fixes get
Java JUnit tests in the existing test classes. Missing-value handling follows the module's
established rule: `null` is the only missing marker crossing the API boundary; Tablesaw
sentinels (`NaN`, `Integer.MIN_VALUE`, `""`) never leak through a new code path.

**Tech Stack:** Groovy 5.1.1 (`@CompileStatic` enforced globally through
`config/groovy/compileStatic.groovy`), Java 21, Tablesaw 0.44.4, Apache POI (XLSX), SODS (ODS),
dom4j (XML), JUnit Jupiter 6, `groovier-junit`.

**Spec:** The review findings are reproduced in section "Findings being fixed" below so this
plan is self-contained. The previous 0.4.0 plan (`matrix-tablesaw/req/0.4.0-fixes.md`) holds the
design decisions this plan must stay consistent with (binary-only XLSX, `null` missing marker,
`toBigDecimal` NaN/infinity policy, lossless-only coercion).

### Task 1: `Gtable.putAt(row, col, null)` must not mutate a shared `StringColumn`

**Files:**
- Modify: `matrix-tablesaw/src/main/groovy/se/alipsa/matrix/tablesaw/gtable/Gtable.groovy:376-396` (method `putAt(int rowIndex, int columnIndex, Object value)`)
- Test: `matrix-tablesaw/src/test/groovy/test/alipsa/groovy/matrix/tablesaw/GtableTest.groovy`

**Interfaces:**
- Consumes: `Table.replaceColumn(int, Column<?>)`, `StringColumn.copy()`, `StringColumn.inRange(int, int)` (Tablesaw 0.44.4).
- Produces: unchanged signature `void putAt(int rowIndex, int columnIndex, Object value)`; the source `Table` passed to `Gtable.create(Table)` is never resized by `putAt`.
  A `null` put on a `StringColumn` replaces that column in the Gtable with a private copy, so from
  then on that one column is no longer shared with the source `Table` (puts on every other column
  still write through). This asymmetry is inherent to Tablesaw 0.44.4 (`setMissing`/`set(null)` on a
  `StringColumn` built with `create(name, List)` leave `isMissing == false`, and `appendMissing()` is
  the only way to register the missing key — there is no in-place row removal) and must be documented
  in the `putAt` GroovyDoc (Task 3.3) and in the release notes (Task 12.1).

Background: Tablesaw's `StringColumn.setMissing(i)` leaves `isMissing(i) == false` on a column built
with `create(name, List)` (dictionary key for the missing marker is only registered by `append`).
The existing work-around (`appendMissing()` + `setMissing()` + `inRange()`) is correct but runs on
the live column, which `Gtable.create(Table)` shares with the source table.

### Task 2: `Gtable.addIntColumn/addLongColumn/addShortColumn` accept `null` as missing

**Files:**
- Modify: `matrix-tablesaw/src/main/groovy/se/alipsa/matrix/tablesaw/gtable/Gtable.groovy:261-283`
- Test: `matrix-tablesaw/src/test/groovy/test/alipsa/groovy/matrix/tablesaw/GtableTest.groovy`

**Interfaces:**
- Consumes: `IntColumn.append(Integer)`, `LongColumn.append(Long)`, `ShortColumn.append(Short)` — all
  three map `null` to `appendMissing()` in Tablesaw 0.44.4 (`IntColumn.java:216`, `LongColumn.java:230`,
  `ShortColumn.java:222`). Do **not** use `ShortColumn.create(String, Short[])`: it goes through Guava's
  `Shorts.toArray` and throws `NullPointerException` on a `null` element (`ShortColumn.java:66`).
- Produces: unchanged signatures `Gtable addIntColumn(String, List)`, `Gtable addLongColumn(String, List)`,
  `Gtable addShortColumn(String, List)`; `null` elements become missing values. Elements are coerced
  through the same private `Gtable.coerce(Object, Class)` helper `putAt` uses (Task 3.3) — empty string
  → missing, a `CharSequence` into a `Number` target strictly pre-parsed with
  `new BigDecimal(value.toString().trim())`, then narrowed with `ValueConverter.convert` — so all three
  methods and `putAt` share one coercion policy (DRY): numeric strings keep working as the old
  `data as int[]` form accepted (`['5'] as long[]` → `[5]`, verified with Groovy 5), garbage strings
  (`'abc'`, `'12abc'`, `'1,234'`) throw `NumberFormatException` exactly as 0.3.x did, and overflow
  throws `IllegalArgumentException` instead of silently wrapping (`addShortColumn('s', [70000])`
  previously stored `4464`). Routing through `ValueConverter` also gives the matrix-core 3.9.0
  semantics uniformly for numbers: `NaN`/infinity → missing, fractions truncate (`'5.7'` → `5`,
  exactly as `ValueConverter` narrows everywhere else). Like Task 3, this is a **runtime requirement on
  matrix-core 3.9.0 or later** (`compileOnly` here); it is stated in the release notes (12.1) and
  readme (12.2) alongside the `putAt` requirement. Note the helper lives in `Gtable.groovy`, which
  Task 3.3 edits — implement the helper there in this task (it is self-contained) and Task 3.3 then
  only switches `putAt` to call it.

```groovy
  /**
   * Coerces {@code value} to {@code targetType} with {@link ValueConverter#convert(Object, Class)},
   * applying the module's uniform input rules first: {@code null} and the empty string map to
   * {@code null} (missing), and a {@code CharSequence} targeting a {@code Number} type is strictly
   * pre-parsed with {@code new BigDecimal(text.trim())} so garbage such as {@code 'abc'},
   * {@code '12abc'} or {@code '1,234'} throws {@code NumberFormatException} instead of being
   * partially parsed by {@code ValueConverter}'s lenient scrapers. Used by {@code putAt} and the
   * {@code addXColumn} methods so every value-entry path shares one coercion policy.
   */
  private static Object coerce(Object value, Class targetType) {
    if (value == null) {
      return null
    }
    if (value instanceof CharSequence && !CharSequence.class.isAssignableFrom(targetType)
        && value.toString().isEmpty()) {
      return null
    }
    if (value instanceof CharSequence && Number.class.isAssignableFrom(targetType)) {
      // strictness guard: ValueConverter.asInteger/asShort/asBigDecimal scrape digits out of garbage
      // ('12abc' -> 12) while asLong/asFloat/asDouble parse strictly; pre-parsing with BigDecimal
      // restores the fail-fast behavior Groovy's asType had in 0.3.x, uniform across numeric types.
      // Narrowing (truncation of fractions, IllegalArgumentException when out of range) is then
      // ValueConverter's, so strings and numbers behave identically (needs matrix-core >= 3.9.0).
      return ValueConverter.convert(new BigDecimal(value.toString().trim()), targetType)
    }
    ValueConverter.convert(value, targetType)
  }
```

Static-compilation note: the explicit `(Integer)` / `(Long)` / `(Short)` cast on the `Object` returned
by `coerce` is required so static compilation selects the boxed `append(Integer)`/`append(Long)`/
`append(Short)` overload (which maps `null` to `appendMissing()`); after `coerce` the value is already
of the target type or `null`, so this is a plain upcast, not a conversion.

### Task 3: `putAt` coerces through `ValueConverter`; deduplicate `asJavaClass`

**Files:**
- Modify: `matrix-tablesaw/src/main/groovy/se/alipsa/matrix/tablesaw/gtable/Gtable.groovy` (`putAt(int,int,Object)` non-null branch, `asJavaClass(int)`, imports)
- Test: `matrix-tablesaw/src/test/groovy/test/alipsa/groovy/matrix/tablesaw/GtableTest.groovy`

**Interfaces:**
- Consumes: `se.alipsa.matrix.core.ValueConverter.convert(Object o, Class<E> type)` (matrix-core; already a
  `compileOnly` + `testImplementation` dependency of this module, `Gtable` already imports `Matrix` from it)
  and `TableUtil.classForColumnType(ColumnType)` (existing, returns `Class<?>`).
- Produces: `Class asJavaClass(int columnIndex)` keeps its signature and delegates to
  `TableUtil.classForColumnType`. `putAt` keeps its signature; non-null values are converted with
  `ValueConverter.convert(value, targetType)` instead of Groovy's `asType`, so the shorthand follows the
  same coercion rules as the rest of matrix: `'false'`/`'no'`/`'0'` → `false` and `'true'`/`'yes'`/`'on'`/`'1'`
  → `true` for BOOLEAN columns (instead of Groovy truth, where every non-empty string was `true`);
  numeric strings such as `'7'` keep parsing for numeric columns (as they already did via Groovy `as`
  in 0.3.x); ISO strings parse for LOCAL_DATE/LOCAL_DATE_TIME/LOCAL_TIME columns (not INSTANT:
  `ValueConverter.convert` has no `Instant` case, so a String into an INSTANT column still falls through
  `default -> type.cast(o)` to `o.asType(Instant)` and throws `GroovyCastException` exactly as in 0.3.x).
  Existing accepted inputs (`123.10` into DOUBLE, `5` into DOUBLE, `42` into STRING, `5.7` into INTEGER → `5`)
  behave as before, with two deliberate, documented exceptions (also recorded in the release notes and
  tested in 3.1): the string `'NaN'` or `'Infinity'` into a DOUBLE/FLOAT column now throws
  `NumberFormatException` from the strictness guard (0.3.x parsed it via `Double.valueOf` and stored
  `NaN`, which Tablesaw treats as missing), and `Double.NaN` into an integral column now marks the cell
  missing (0.3.x stored `0`; matrix-core 3.9.0 maps `NaN` to no-value).
  **Consistency note (resolved decision):** this truncation-on-narrowing is deliberately *more lenient*
  than `Gtable.create`/`TableUtil.createColumn`, whose shipped 0.4.0 contract is lossless-only coercion
  ("no silent coercion", readme "Strict Gtable type validation"): `putAt` accepts `'5.7'`/`5.7` into an
  INTEGER column and stores `5`, where `Gtable.create` rejects the same value. The divergence is kept,
  not unified, because `putAt` follows the matrix-wide `ValueConverter` narrowing rules (the same
  truncation `Stat`, `Matrix` and every other matrix-core caller gets), while `create` is a
  construction-time bulk-validation path that rejects lossy input by design. The divergence is stated
  verbatim in the breaking-changes bullet (12.1): "putAt is lenient where `Gtable.create` is strict,
  because it follows the matrix-wide `ValueConverter` coercion rules; `create`'s lossless-only policy is
  unchanged."
  For custom column types `asJavaClass` returns `Object` and `ValueConverter.convert`
  falls through to `type.cast`, which is a no-op.
  Strictness guard (resolved decision): `ValueConverter`'s `asInteger`/`asShort`/`asBigDecimal` strip
  every non-numeric character (`'12abc'` → `12`) while `asLong`/`asFloat`/`asDouble` parse strictly, so
  all value entry (`putAt` and the `addXColumn` methods) routes through the shared private
  `coerce(Object, Class)` helper (Task 2.3), which pre-parses any `CharSequence` whose target is a
  `Number` type strictly first (`new BigDecimal(value.toString().trim())`, `NumberFormatException` on
  garbage such as `'abc'`, `'12abc'` or `'1,234'`) and only then narrows through
  `ValueConverter.convert(BigDecimal, targetType)`.
  This restores the fail-fast behavior Groovy's `asType` had in 0.3.x for non-numeric text and makes
  strictness uniform across numeric column types. Two consequences of narrowing through
  `ValueConverter` are accepted deliberately and documented: a fractional numeric string is truncated
  toward zero exactly like the equivalent number (`'5.7'` into INTEGER → `5`, as `5.7` → `5` already
  did; 0.3.x threw `NumberFormatException` for the string), and an out-of-range value (`'70000'` into
  SHORT, `'3000000000'` into INTEGER, and the same numbers) throws `IllegalArgumentException` — the
  latter comes from matrix-core's exact-narrowing fix (`matrix-core/req/3.9.0-exact-narrowing.md`),
  which is a **prerequisite** of this task: without it `ValueConverter.asInteger`/`asShort` wrap
  silently (`'3000000000'` → `-1294967296`). Because `matrix-core` is `compileOnly` here, this is a
  runtime requirement of matrix-tablesaw 0.4.0 on matrix-core 3.9.0 or later; it must be stated in
  the release notes (12.1) and readme (12.2), and matrix-bom must ship both. An **empty string
  (`''`)** marks the cell **missing** for numeric, Boolean, `java.time` and custom (`Object`) column
  types; `putAt` routes that through the existing null branch (0.3.x threw
  `NumberFormatException` for `''` into a numeric column). Only the empty string is uniform across those
  column types: `'null'` into BOOLEAN stores `false`, into LOCAL_DATE/LOCAL_DATE_TIME/LOCAL_TIME throws
  `DateTimeParseException`, and into numeric columns throws `NumberFormatException` under the guard — so
  the plan, GroovyDoc, release notes and readme document only the empty-string rule. This is a deliberate,
  documented behaviour change, not a side effect of `Column.set(row, null)`.

- Consumes: `Normalize.logNorm(T, int...)`, `Normalize.minMaxNorm(T, Number, Number, MissingValueType, int...)`,

  `Normalize.stdScaleNorm(T, Number, Number, int...)` from matrix-stats;
  `BigDecimalAggregateFunctions.min/max/mean.summarize(BigDecimalColumn)` (return `null` when empty;
  `mean` delegates to `Stat.mean(List)` whose quotient is rounded to `Stat.DEFAULT_MEAN_SCALE` = 16
  decimal places, so it is *not* exact for a non-terminating mean such as `[1, 1, 2]`);

- Produces: `public static final NumberAggregateFunction BigDecimalAggregateFunctions.stdDev`
  (`BigDecimal summarize(BigDecimalColumn)`, sample standard deviation = `Stat.variance(...).sqrt(DECIMAL64)`;
  only the square root uses `DECIMAL64`, `Stat.variance` itself rounds its mean to 16 places and divides
  with Groovy's default BigDecimal division; `null` when fewer than two non-missing values). All twelve `Normalizer` methods keep their signatures; missing input rows produce
  missing output rows; an all-missing (or single-value for std-scale) BigDecimal column produces an
  all-missing column instead of throwing. The BigDecimal min-max, mean and std-scale overloads compute
  `(x - min) / (max - min)`, `(x - mean) / (max - min)` and `(x - mean) / sd` in BigDecimal arithmetic:
  subtraction is exact, but every division uses `MathContext.DECIMAL64` (the module's documented context
  for `BigDecimalColumn.divide`), so a non-terminating quotient such as `1/3` is rounded to 16
  significant digits — **no path is "fully exact"**. Additionally `meanNorm` and `stdScaleNorm` inherit
  the 16-place mean from `Stat.mean` (and `stdDev` its `DECIMAL64` square root). Do not describe any of
  this as "exact statistics" in GroovyDoc, readme or release notes — say "exact subtraction, division in
  `MathContext.DECIMAL64`" (and, where relevant, "mean rounded to 16 places"). The point of the change
  is that inputs are never converted to `double` before being compared, so values that differ only
  beyond double precision are still distinguished.

Resolved design decision: the BigDecimal formulas live in `Normalizer` (this module) rather than as new
overloads on `se.alipsa.matrix.stats.Normalize`. `Normalize`'s generic `<T extends Number>` methods
convert to `double` by design, and `matrix-stats` is a `compileOnly` dependency here, so overloads added
there would impose a silent runtime version floor on every consumer of `matrix-tablesaw`.
`Normalizer.logNorm(BigDecimalColumn)` keeps delegating to `Normalize.logNorm`, whose BigDecimal path uses
`x.log()` and is out of scope for this task.

import tech.tablesaw.api.BigDecimalAggregateFunctions
import tech.tablesaw.api.BigDecimalColumn
import tech.tablesaw.api.DoubleColumn
import tech.tablesaw.api.FloatColumn

import se.alipsa.matrix.stats.Normalize
import se.alipsa.matrix.stats.Normalize.MissingValueType

import java.math.MathContext
import java.math.RoundingMode

/**
 * Column-level normalization for Tablesaw numeric columns.
 *
 * <p>Missing input values always produce missing output values. Results are returned as new
 * columns named {@code norm_<original name>}; the input column is never modified.
 *
 * <p>Double and Float overloads delegate the arithmetic to {@link Normalize} from matrix-stats and
 * use Tablesaw's double-precision aggregates. BigDecimal min-max, mean and standard-score overloads
 * take their statistics from {@link BigDecimalAggregateFunctions} (min and max are exact; the mean is
 * rounded to 16 decimal places by {@code Stat.mean}, and the sample standard deviation is the
 * {@link MathContext#DECIMAL64} square root of {@code Stat.variance}) and perform the per-value
 * arithmetic in BigDecimal (exact subtraction, division in {@link MathContext#DECIMAL64}). Inputs are
 * never converted to {@code double}, so values that only differ beyond double precision are still
 * distinguished. Log normalization of BigDecimal values delegates to
 * {@link Normalize#logNorm(Number, int...)}.
 */
class Normalizer {

  private static final String NORM_PREFIX = 'norm_'
  private static final MathContext DIVISION_CONTEXT = MathContext.DECIMAL64

  /**
   * Natural-log normalization of each non-missing value.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */
  static DoubleColumn logNorm(DoubleColumn column, int... decimals) {
    mapDoubles(column) { double x -> Normalize.logNorm(x, decimals) }
  }

  /**
   * Natural-log normalization of each non-missing value.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */
  static FloatColumn logNorm(FloatColumn column, int... decimals) {
    mapFloats(column) { float x -> Normalize.logNorm(x, decimals) }
  }

  /**
   * Natural-log normalization of each non-missing value.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */

    mapBigDecimals(column) { BigDecimal x -> Normalize.logNorm(x, decimals) }
  }

  /**
   * Min-max normalization to the [0, 1] range.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */
  static DoubleColumn minMaxNorm(DoubleColumn column, int... decimals) {
    double min = column.min()
    double max = column.max()
    mapDoubles(column) { double x -> Normalize.minMaxNorm(x, min, max, MissingValueType.DOUBLE_NAN, decimals) }
  }

  /**
   * Min-max normalization to the [0, 1] range.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */
  static FloatColumn minMaxNorm(FloatColumn column, int... decimals) {
    float min = column.min() as float
    float max = column.max() as float
    mapFloats(column) { float x -> Normalize.minMaxNorm(x, min, max, MissingValueType.FLOAT_NAN, decimals) }
  }

  /**
   * Min-max normalization to the [0, 1] range in BigDecimal arithmetic (exact subtraction, division
   * in {@link MathContext#DECIMAL64}): {@code (x - min) / (max - min)}.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to (HALF_EVEN)
   * @return a new column named {@code norm_<name>}; all missing if the column has no values or
   *         all values are equal (zero range)
   */
  static BigDecimalColumn minMaxNorm(BigDecimalColumn column, int... decimals) {
    BigDecimal min = BigDecimalAggregateFunctions.min.summarize(column)
    BigDecimal max = BigDecimalAggregateFunctions.max.summarize(column)
    if (min == null || max == null) {
      return allMissing(column)
    }
    BigDecimal range = max - min
    mapBigDecimals(column) { BigDecimal x -> divideRounded(x - min, range, decimals) }
  }

  /**
   * Mean normalization: (x - mean) / (max - min).
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */
  static DoubleColumn meanNorm(DoubleColumn column, int... decimals) {
    double min = column.min()
    double max = column.max()
    double mean = column.mean()
    mapDoubles(column) { double x -> Normalize.meanNorm(x, mean, min, max, MissingValueType.DOUBLE_NAN, decimals) }
  }

  /**
   * Mean normalization: (x - mean) / (max - min).
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */
  static FloatColumn meanNorm(FloatColumn column, int... decimals) {
    float min = column.min() as float
    float max = column.max() as float
    float mean = column.mean() as float
    mapFloats(column) { float x -> Normalize.meanNorm(x, mean, min, max, MissingValueType.FLOAT_NAN, decimals) }
  }

  /**
   * Mean normalization in BigDecimal arithmetic: {@code (x - mean) / (max - min)}, where the mean is
   * rounded to 16 decimal places by {@code Stat.mean} and the division uses {@link MathContext#DECIMAL64}.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to (HALF_EVEN)
   * @return a new column named {@code norm_<name>}; all missing if the column has no values or
   *         all values are equal (zero range)
   */
  static BigDecimalColumn meanNorm(BigDecimalColumn column, int... decimals) {
    BigDecimal min = BigDecimalAggregateFunctions.min.summarize(column)
    BigDecimal max = BigDecimalAggregateFunctions.max.summarize(column)
    BigDecimal mean = BigDecimalAggregateFunctions.mean.summarize(column)
    if (min == null || max == null || mean == null) {
      return allMissing(column)
    }
    BigDecimal range = max - min
    mapBigDecimals(column) { BigDecimal x -> divideRounded(x - mean, range, decimals) }
  }

  /**
   * Standard-score normalization: (x - mean) / sd.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */
  static DoubleColumn stdScaleNorm(DoubleColumn column, int... decimals) {
    double mean = column.mean()
    double stdDev = column.standardDeviation()
    mapDoubles(column) { double x -> Normalize.stdScaleNorm(x, mean, stdDev, decimals) }
  }

  /**
   * Standard-score normalization: (x - mean) / sd.
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to
   * @return a new column named {@code norm_<name>}
   */
  static FloatColumn stdScaleNorm(FloatColumn column, int... decimals) {
    float mean = column.mean() as float
    float stdDev = column.standardDeviation() as float
    mapFloats(column) { float x -> Normalize.stdScaleNorm(x, mean, stdDev, decimals) }
  }

  /**
   * Standard-score normalization in BigDecimal arithmetic: {@code (x - mean) / sd} (mean rounded to
   * 16 decimal places, sample standard deviation from {@link BigDecimalAggregateFunctions#stdDev},
   * division in {@link MathContext#DECIMAL64}).
   *
   * @param column the column to normalize
   * @param decimals optional number of decimals to round to (HALF_EVEN)
   * @return a new column named {@code norm_<name>}; all missing if fewer than two values are
   *         present or the standard deviation is zero
   */
  static BigDecimalColumn stdScaleNorm(BigDecimalColumn column, int... decimals) {
    BigDecimal mean = BigDecimalAggregateFunctions.mean.summarize(column)
    BigDecimal stdDev = BigDecimalAggregateFunctions.stdDev.summarize(column)
    if (mean == null || stdDev == null) {
      return allMissing(column)
    }
    mapBigDecimals(column) { BigDecimal x -> divideRounded(x - mean, stdDev, decimals) }
  }

  private static DoubleColumn mapDoubles(DoubleColumn column, Closure<Double> fn) {
    List<Double> vals = []
    for (int i = 0; i < column.size(); i++) {
      vals.add(column.isMissing(i) ? null : fn.call(column.getDouble(i)))
    }
    DoubleColumn.create(NORM_PREFIX + column.name(), vals as Double[])
  }

  private static FloatColumn mapFloats(FloatColumn column, Closure<Float> fn) {
    List<Float> vals = []
    for (int i = 0; i < column.size(); i++) {
      vals.add(column.isMissing(i) ? null : fn.call(column.getFloat(i)))
    }
    FloatColumn.create(NORM_PREFIX + column.name(), vals as Float[])
  }

  private static BigDecimalColumn mapBigDecimals(BigDecimalColumn column, Closure<BigDecimal> fn) {
    List<BigDecimal> vals = []
    for (int i = 0; i < column.size(); i++) {
      vals.add(column.isMissing(i) ? null : fn.call(column.get(i)))
    }
    BigDecimalColumn.create(NORM_PREFIX + column.name(), vals as BigDecimal[])
  }

  private static BigDecimalColumn allMissing(BigDecimalColumn column) {
    BigDecimalColumn.create(NORM_PREFIX + column.name(), column.size())
  }

  /**
   * {@code numerator / denominator} in {@link #DIVISION_CONTEXT}, {@code null} (missing) when the
   * denominator is zero, rounded to {@code decimals[0]} places (HALF_EVEN) when decimals are given.
   */
  private static BigDecimal divideRounded(BigDecimal numerator, BigDecimal denominator, int... decimals) {
    if (denominator.signum() == 0) {
      return null
    }
    BigDecimal result = numerator.divide(denominator, DIVISION_CONTEXT)
    decimals.length > 0 ? result.setScale(decimals[0], RoundingMode.HALF_EVEN) : result
  }
}

  Interfaces note above).
- `DoubleColumn.create(String, Double[])` resolves to Tablesaw's `create(String, Number[])`, which maps

import java.util.Locale;
import java.util.Set;

/** Collision-safe column naming shared by the table readers. */
public final class ColumnNames {

  private ColumnNames() {}

  /**
   * Returns {@code candidate}, or {@code candidate + "-" + k} (k = 2, 3, ...) when the lowercased
   * candidate is already in {@code taken}; the returned name (lowercased) is added to {@code taken}.
   *
   * @param candidate the desired column name
   * @param taken lowercased names that are no longer available; updated in place
   * @return a name that does not collide, case-insensitively, with any name in {@code taken}
   */
  public static String unique(String candidate, Set<String> taken) {
    String result = candidate;
    String normalized = result.toLowerCase(Locale.ROOT);
    int suffix = 2;
    while (taken.contains(normalized)) {
      result = candidate + "-" + suffix++;
      normalized = result.toLowerCase(Locale.ROOT);
    }
    taken.add(normalized);
    return result;
  }
}

## Review round 2026-09-17 (applied)

Findings from the plan review, all folded into the tasks above:
1. Task 1: a `null` put on a `StringColumn` detaches that column from the source `Table`; documented in
   the Interfaces note, the `putAt` GroovyDoc (3.3), test 1.1 and the release notes (12.1).
2. Task 12.1: the `putAt` coercion change silently alters stored values (`'maybe'` → `false`, `2` →
   `false`), so it is recorded under `### Breaking changes`, not `### Validation`.
3. Task 3: an **empty string (`''`)** into a numeric, Boolean or `java.time` column is routed through
   the null branch explicitly and marks the cell missing, with test `testPutAtEmptyStringBecomesMissing`
   and a release-note sentence. Only `''` is uniform across those column types; `'null'` and
   whitespace-only strings behave per column type and are deliberately not documented as missing.
4. Task 3: INSTANT columns are excluded from the "strings are parsed" claim (`ValueConverter` has no
   `Instant` case).
5. Task 4: "exact statistics" replaced by an accurate description (mean rounded to 16 places,
   `DECIMAL64` division). Corrected in the 2026-09-18 round: no path is fully exact (see item 4 of
   that round).
6. Task 4.5: `assertEquals(BigDecimal, BigDecimal)` is scale-insensitive in Groovy, so explicit
   `.scale()` assertions were added and the obsolete `compareTo` hedge in 4.8 removed.
7. Task 8: a blank root `name=""` attribute no longer overrides the configured table name.
8. Task 3 (strictness guard): `ValueConverter.asInteger`/`asShort`/`asBigDecimal` scrape digits out of
   garbage strings (`'12abc'` → `12`) while `asLong`/`asFloat`/`asDouble` parse strictly. The plan picks
   the guard: `putAt` pre-parses any `CharSequence` into a `Number`-typed column strictly with
   `new BigDecimal(text.trim())` and only then narrows through `ValueConverter.convert`; `'abc'`,
   `'12abc'` and `'1,234'` throw `NumberFormatException` (test `testPutAtRejectsGarbageNumericStrings`),
   restoring the fail-fast 0.3.x behavior and making strictness uniform across numeric column types.
9. Task 3 / 12 (wording): the `''`/`'null'`/"blank" claims were over-generalised — only the empty
   string is uniform. All of the Interfaces note, the `putAt` GroovyDoc (3.3), the breaking-changes
   bullet (12.1), the readme paragraph (12.2), review-round item 3 above and the self-review checklist
   now state "an empty string (`''`) marks the cell missing" and nothing about `'null'`/"blank".
10. Findings #11 and Task 3.2 / 12.1 / 12.2 (accuracy): numeric strings were already accepted by
    Groovy `as` in 0.3.x; only date/time strings are newly parsed. The findings-table row, the
    3.2 expected failures (LocalDate line; `NumberFormatException` for `''`) and the readme example
    comments were corrected accordingly.
11. Task 3 test: the StringColumn `''` assertion was dropped from the empty-string test — `""` is
    Tablesaw's own missing indicator for `StringColumn`, so the assertion passed vacuously.
12. Task 3 (narrowing, round 3): the guard's `BigDecimal` → `ValueConverter.convert` path inherited
    `intValue()`/`shortValue()` wrapping (`'3000000000'` → `-1294967296`, `'70000'` into SHORT →
    `4464`) where 0.3.x threw. Resolved at the source rather than in `Gtable`: matrix-core 3.9.0
    gets exact integral narrowing (`matrix-core/req/3.9.0-exact-narrowing.md`, out-of-range →
    `IllegalArgumentException`, `NaN`/infinity → `valueIfNull`), which fixes strings and numbers alike
    for every `ValueConverter` caller. The guard stays for garbage text (`'abc'` → `null` and
    `'12abc'` → `12` are intentional R-style NA/lenient parsing in matrix-core and must not change).
    Fractional numeric strings now truncate like numbers (`'5.7'` → `5`), documented instead of
    special-cased. Consequence: matrix-tablesaw 0.4.0 requires matrix-core 3.9.0+ at runtime
    (release note + readme BOM bump). Also applied: redundant `(value as CharSequence)` casts removed
    (flow typing), GroovyDoc lists custom-typed columns in the empty-string rule, and the readme
    example keeps its throwing lines at the end as comments.

## Review round 2026-09-18 (applied)

Second review of the plan against Tablesaw 0.44.4 (javap), SODS 1.10.1, POI 5.5.1, the merged
matrix-core 3.9.0 `ValueConverter`, `Stat`, `Normalize`, and Groovy 5.1.1 (`@CompileStatic` coercion
verified in a scratch script). Findings, all folded into the tasks above:
1. Task 2/3 coercion-policy consistency: the module shipped two policies (`Gtable.create`/
   `TableUtil.createColumn` lossless-only vs `putAt` truncation) plus a third (`addShortColumn`
   silently wrapping 70000 → 4464). Resolved: (a) the Task 3 strictness guard is extracted into a
   private `Gtable.coerce(Object, Class)` helper (empty string → missing, `CharSequence` into a
   `Number` target strictly pre-parsed with `new BigDecimal(text.trim())`, then
   `ValueConverter.convert`), introduced in Task 2.3 and shared by `putAt` (3.3) and all three
   `addXColumn` methods — so every value-entry path has one coercion policy and garbage strings
   (`'abc'`, `'12abc'`) throw `NumberFormatException` for `putAt` **and** `addXColumn` alike, as
   0.3.x did (this also fixes the intra-Task-2 disagreement where `asLong('abc')` would have thrown
   while `asInteger('abc')` became missing); (b) the `putAt`-vs-`create` divergence (truncation of
   fractions) is kept as a resolved decision and stated verbatim in the breaking-changes bullet
   (12.1) and the Task 3 Interfaces note — `putAt` follows the matrix-wide `ValueConverter` narrowing
   rules, `create` remains construction-time strict.
2. Task 3.3 codenarc: the "make sure `java.math.BigDecimal` is imported" instruction would trip
   `UnnecessaryGroovyImport` (it is a Groovy default import; only `NoWildcardImports` is excluded
   from the imports ruleset) — removed, with an explicit do-not-import note. The import cleanup list
   now also names `tech.tablesaw.column.numbers.BigDecimalColumnType` (unused once `asJavaClass`
   delegates to `TableUtil` → `UnusedImport`).
3. Task 2 static-compilation note was wrong: `value as Integer` on `Object` does **not** compile to
   `DefaultTypeTransformation.castToType` (which returns 51 for `'3'` and throws for `'30'`); it
   compiles to `ScriptBytecodeAdapter.asType`, which for `String` dispatches to
   `StringGroovyMethods.asType` → `Integer.valueOf`. Since Task 2 now uses `ValueConverter`, the note
   was replaced with a warning not to "simplify" back to `castToType`/`as`.
4. Task 4 "exact" rule violations fixed: `divideExact` renamed to `divideRounded` (the division runs
   in `DECIMAL64`, so non-terminating quotients round); the `minMaxNorm(BigDecimalColumn)` GroovyDoc
   and the Interfaces note no longer claim the min-max path is "fully exact" — all paths are "exact
   subtraction, `DECIMAL64` division".
5. Task 3 undocumented behaviour changes (contradicting "Values that were already accepted are
   stored unchanged"): `'NaN'`/`'Infinity'` into DOUBLE/FLOAT now throw `NumberFormatException`
   (0.3.x stored NaN = missing) and `Double.NaN` into an integral column now becomes missing (0.3.x
   stored 0). Both are improvements, now recorded in the breaking-changes bullet and tested by
   `testPutAtNanAndInfinitySemantics`; the "stored unchanged" sentence carries the two exceptions.
6. Task 3.1 out-of-range assertions switched to `assertThrowsExactly(IllegalArgumentException)` —
   plain `assertThrows` would also pass on a `NumberFormatException` garbage-parse failure.
7. Task 7 placeholder collision: `"C" + colNum` can collide with a real header `C1` (Tablesaw then
   rejects the duplicate name). The suffix loop was extracted from `XmlReader.columnNames` into a
   shared `tech.tablesaw.io.ColumnNames` utility (DRY) and `OdsReader` seeds it with the real
   headers, so a colliding placeholder becomes `C1-2` (same rule as XML); new test
   `testOdsPlaceholderHeaderDoesNotCollideWithRealHeader` and a no-behaviour-change `XmlReader`
   refactor step added.
8. Task 4.3 inefficiency fixed: `cv.summarize` no longer calls `stdDev.summarize(column)` (which
   would re-run `nonMissingValues(column)`); a private `sampleStdDev(List<BigDecimal>)` helper

   `<matrixCoreVersion>3.9.0-SNAPSHOT</matrixCoreVersion>` — there is no `matrix-core.version`

10. Task 7 refactor precision: the instruction now states explicitly that `XmlReader` calls
    `ColumnNames.unique` only inside the `originalNamesSeen.contains(...)` duplicate branch (the

    occurrence because `taken` is seeded with the reserved names; the `OdsReader` import list gains

11. Task 2/3 import hygiene: 3.3 now says the `ValueConverter` import and the `coerce` helper come
