# Matrix-Parquet v0.7.0 Fix Plan

## Scope

This plan addresses four verified `matrix-parquet` defects:

- Directory-target writes can escape the requested directory through a path-bearing Matrix name.
- Explicit `DECIMAL(precision, scale)` writes validate byte-array capacity rather than decimal precision and can emit schema-invalid Parquet values.
- Explicit decimal scale conversion silently rounds with `HALF_UP`.
- `java.sql.Time` loses milliseconds during both write and read, while metadata-free external Parquet `TIME` fields are inferred incorrectly and `TIME(MICROS)`/`TIME(NANOS)` fields are not decoded as time values.

All implementation work belongs to `matrix-parquet` (plus its release documentation). A task is complete only after its specified checks pass and the exact commands and outcomes have been recorded in the PR description.

## Compatibility Decision

### Backwards-compatible API options

1. Keep the current implicit `HALF_UP` default and add a `roundingMode` option for callers who want `UNNECESSARY`.

   - Source and runtime compatible.
   - Rejected: it leaves the unsafe, lossy behavior as the default and does not meet the requirement to reject lossy rescaling.

2. Change the default to `RoundingMode.UNNECESSARY` and add an explicit `roundingMode(RoundingMode)` / `roundingMode(String)` opt-in for callers that require rounding.

   - Existing source continues to compile; exact-scale and scale-expansion writes retain their behavior.
   - Existing calls that previously rounded a non-zero discarded fraction fail with a contextual `IllegalArgumentException` unless they explicitly choose a rounding mode such as `HALF_UP`.
   - Recommended: this makes losslessness the default while retaining a clear migration path.

3. Add separate `writeRounded(...)` APIs while keeping the old overloads implicitly rounding.

   - Source and runtime compatible, but duplicates the configuration surface and preserves the unsafe default.
   - Rejected in favor of a single typed `roundingMode` setting.

Choose option 2 and bump `matrix-parquet` from `0.6.1-SNAPSHOT` to `0.7.0-SNAPSHOT`. The new API is additive, but the changed default is an intentional runtime compatibility break for callers relying on implicit rounding. Document the migration: either make source values exact at the configured scale or set `roundingMode: 'HALF_UP'` (or another `RoundingMode`) explicitly.

If maintaining `0.6.1-SNAPSHOT` is required, retain `HALF_UP` as the default and introduce a separate opt-in strict mode; this is source/runtime compatible but does not satisfy the requested default behavior. Do not silently ship option 2 as a patch-level release.

## 3. Make Decimal Validation and Rounding Explicit

3.1 [x] Added the strict typed `roundingMode` option, map conversion, validation, and descriptor.

3.2 [x] Added both builder overloads; all builder output paths use typed options.

3.3 [x] Added only the specified direct overload; existing paths default to `UNNECESSARY`.

3.4 [x] Threaded `RoundingMode` through the write pipeline without adding a ThreadLocal.

3.5 [x] Enforced contextual lossless rescaling and decimal-precision validation before defensive byte-width encoding checks.

3.6 [x] Defined and documented the error contract:

   - A non-zero discarded fraction with default `UNNECESSARY` fails with contextual `IllegalArgumentException` before data is encoded.
   - A rescaled value whose `precision()` exceeds schema precision fails even if its two's-complement byte representation fits in the fixed-length field.
   - An explicit rounding mode may change the value, but the rounded result must still satisfy declared precision.

3.7 [x] Added regression coverage in `matrix-parquet/src/test/groovy/MatrixParquetDecimalMetaTest.groovy`, `MatrixParquetTest.groovy`, and `ParquetFormatProviderTest.groovy` for:

   - `10.00G` with `DECIMAL(3,2)`, which must fail even though unscaled `1000` fits in two bytes.
   - Positive and negative precision boundaries (`9.99G`/`-9.99G` accepted; `10.00G`/`-10.00G` rejected).
   - Default rejection for `1.235G` at scale `2`, asserting `IllegalArgumentException` and its contextual message.
   - Explicit builder and SPI `HALF_UP` options producing `1.24G`, plus another named mode such as `DOWN`.
   - Exact rescaling that only adds trailing zeroes, which remains accepted under `UNNECESSARY`.
   - Invalid and null rounding-mode configurations, plus `toMap()`/`fromMap()` and descriptor default/type assertions.

3.8 [x] Updated GroovyDoc, README, option listing, and release notes with direct, builder, and SPI migration guidance.
