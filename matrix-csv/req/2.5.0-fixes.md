# Matrix-CSV 2.5.0 Fixes

## Scope

This document records verified defects in `matrix-csv` and the implementation plan for the 2.5.0 development cycle.

Sections 1–11 are findings and acceptance criteria. Section 12 is the only authoritative task list. A task is complete only after its tests have passed and the exact verification commands have been recorded in this plan or the pull request description.

## 1. Prepare the 2.5.0 Development Version

The module is currently version `2.4.0`. Development of these fixes targets `2.5.0-SNAPSHOT`. A new `v2.5.0` entry must be added at the top of `matrix-csv/release.md`; other version references should only be changed when they describe the module being built rather than an intentionally pinned usage example.

## 2. Reject Header and Data Width Mismatches

`CsvReader.parse(...)` validates data records against the first data record but does not validate the parsed or explicitly configured header against those records. `parserHeaderRow(...)` instead truncates or pads header metadata, which silently changes the schema.

Reproductions:

```
a,b\n1,2,3\n => columns ['a', 'b', '']
a,b,c\n1,2\n => columns ['a', 'b']
```

Acceptance requirements:

- Parsed headers narrower or wider than their data records must be rejected.
- Explicitly configured headers must follow the same width rule.
- The exception must be an informative `IllegalArgumentException` containing the normalized 1-based source-record position and expected and actual column counts.
- Base the position on `CSVRecord.getRecordNumber()` and add one only when Commons CSV consumed the source header before returning records.
- Do not add the consumed-header offset for an externally configured header.
- Fluent, typed, deprecated, and `CsvImporter` paths must report the same normalized position for the same malformed source record.
- With no parsed or configured header, the first data record establishes the expected width; synthesize column names from it only after validation.
- Header maps must not reshape non-empty duplicate metadata; when Commons CSV omits allowed empty names from `headerNames`, header indices may restore only those missing-name positions.
- `ALLOW_ALL` must retain the original order and width of non-empty duplicate headers.
- `ALLOW_EMPTY` and `DISALLOW` must reject non-empty duplicates with the Commons CSV error.
- `ALLOW_EMPTY` must accept repeated empty header names when `allowMissingColumnNames` is enabled through `read().excel()`.
- Empty header names must remain rejected when `allowMissingColumnNames` is false.
- Adding a general public `allowMissingColumnNames` option is outside this fix's scope.

Record positions use `CSVRecord.getRecordNumber()` rather than a physical-line counter because quoted fields may span multiple lines. The conditional consumed-header offset normalizes paths where Commons CSV removes the source header before exposing data records. The positive `ALLOW_EMPTY` case uses the Excel preset because `ReadBuilder` has no public setter or descriptor for its private `allowMissingColumnNames` flag.

This is a runtime compatibility change for fluent and typed readers: ragged inputs that were previously padded or truncated will now fail. Deprecated readers already reject these inputs, but their exception message and reported position will change to the normalized format. The README and release notes must call out both effects and show the new message fields.

## 3. Prevent Duplicate Headers in Deprecated CSVFormat Writes

The deprecated `CsvWriter.write(Matrix, CSVFormat, PrintWriter, boolean)` path constructs a `CSVPrinter` from the caller's format. `CSVPrinter` automatically emits a configured header unless `skipHeaderRecord` is set, after which `CsvWriter` prints another header manually.

Reproduction:

```
CSVFormat.Builder.create().setHeader('a', 'b').build()
withHeader = true  => a,b\r\na,b\r\n1,2\r\n
withHeader = false => a,b\r\na,b\r\n1,2\r\n
```

When `withHeader` is true and the configured header width matches the matrix, writer-owned printer paths must emit exactly one configured header. When the widths differ, they must preserve the current fallback and emit the matrix column names exactly once. When `withHeader` is false, writer-owned printer paths must emit no header. The implementation must create a defensive `CSVFormat` copy with `CSVFormat.Builder.create(format)` and set `skipHeaderRecord` on that copy. It must not mutate caller-owned formats or shared constants such as `CSVFormat.EXCEL`.

The `CsvWriter.write(Matrix, CSVPrinter, boolean)` overload is explicitly outside this header-suppression guarantee: the caller constructs and owns the printer, and its constructor may emit a configured header before `CsvWriter` is called. Document that callers who want `withHeader` to control all header output must construct their printer with `skipHeaderRecord(true)`. This finding does not authorize a new exception for configured headers whose width differs from the matrix. Tests must cover both a same-width configured header whose names differ from the matrix column names and a mismatched-width configured header that falls back to matrix column names.

## 4. Correct the Read-Side Record Separator Contract

Apache Commons CSV uses `recordSeparator` for output; its parser recognizes CR, LF, and CRLF regardless of this setting. The current read API therefore advertises behavior it cannot provide.

Decision for 2.5.0:

- `CsvReadOptions.recordSeparator` backing field: retain for binary compatibility, deprecate, and keep inert.
- `CsvReadOptions.getRecordSeparator()` and `setRecordSeparator(String)`: declare explicit deprecated accessors so Groovy property syntax receives deprecation metadata; preserve their existing JVM signatures and inert behavior.
- `CsvReadOptions.recordSeparator(String)`: retain and deprecate the fluent setter; keep it inert.
- `CsvReader.ReadBuilder.recordSeparator(String)`: retain and deprecate the fluent-reader setter; keep it inert.
- Public accessors and fluent setters: add GroovyDoc with `@param`/`@return` and `@deprecated` tags that explain the read setting is inert and point output-separator callers to `CsvWriteOptions.recordSeparator(...)`.
- `CsvReadOptions.fromMap(...)`: continue accepting the legacy map/SPI key without validation or failure, and warn at most once per JVM.
- `CsvReadOptions.toMap()`: omit the undiscoverable legacy value so serialization agrees with option discovery.
- `CsvOption.RecordSeparator`: retain the read-map key, deprecate it, and amend its GroovyDoc to say it is accepted but inert.
- `CsvImporter.Format.RecordSeparator`: make no additional change because its containing enum is already deprecated.
- Read `OptionDescriptor` lists, README tables, and examples: remove the option so new callers do not discover unsupported custom-separator behavior.
- Write APIs: keep `recordSeparator` fully supported for `CsvWriteOptions` and `CsvWriter`.

Logging and guard requirements:

- Add `private static final Logger log = Logger.getLogger(CsvReadOptions)` using `se.alipsa.matrix.core.util.Logger`; do not use console output.
- Warn when the legacy map/SPI key reaches `CsvReadOptions.fromMap(...)`, whether directly, through `CsvReader.read(Map, ...)`, through `CsvImporter`, or through the format provider.
- Guard the warning with a thread-safe `AtomicBoolean` so repeated `fromMap()` calls warn at most once per JVM.
- Annotate the guard and its test-only swap method with `groovy.transform.PackageScope`; otherwise Groovy would expose a public property accessor and public method.
- Test the guard from the same package by resetting it, exercising the warning branch twice, asserting one claim, and restoring its prior state in `finally`. Do not install a global `System.LoggerFinder` solely to capture the warning.
- Do not add validation that turns formerly accepted custom separator values into errors in this minor release.

Reader tests must confirm CR, LF, and CRLF inputs remain readable and option discovery no longer advertises arbitrary read-side separator support.

## 5. Derive Matrix Names from URL Paths

`CsvReader.tableName(URL)` uses `URL.getFile()`, which includes query parameters, then removes text after the last dot. For `https://example.test/path/data.csv?version=1.2`, the derived matrix name is `data.csv?version=1`.

The name must come from `URL.toURI().getPath()`, which excludes query parameters and fragments, decodes percent escapes, and preserves literal `+` characters. Do not use `URLDecoder`, whose form-decoding rules incorrectly turn `+` into a space.

If `URL.toURI()` throws `URISyntaxException`, fall back to URL file/path accessors without propagating the conversion failure. The same fallback applies when an opaque URI has no path. This is explicitly best-effort: the fallback still excludes query and fragment data but may retain percent escapes because URI decoding was unavailable. Tests must cover encoded spaces, literal plus signs, multiple dots, dotted query parameters, fragments, illegal literal spaces, root URLs, trailing-slash URLs, and opaque jar URLs.

## 6. Stop Closing Caller-Owned Writers in the Deprecated Write Path

The deprecated `CsvWriter.write(Matrix, Writer, CSVFormat, boolean)` wraps the caller's `Writer` in a `PrintWriter` and hands it to `CSVPrinter`. `CSVPrinter.close()` closes its appendable, so the caller's writer is closed as a side effect. The fluent path already protects caller-owned writers with `CloseShieldWriter`.

Reproduction:

```
CsvWriter.write(m, trackingWriter, CSVFormat.DEFAULT, true) => caller writer closed = true
CsvWriter.write(m).to(trackingWriter)                       => caller writer closed = false
```

Acceptance requirements:

- Caller-supplied `Writer` and `PrintWriter` instances must be flushed before the write method returns.
- Caller-supplied `Writer` and `PrintWriter` instances must remain open.
- Flush the `CSVPrinter` inside its try-with-resources block after all output is written and before `CSVPrinter.close()` closes the `CloseShieldWriter`.
- Do not attempt to flush a `CloseShieldWriter` after it has replaced its delegate with `ClosedWriter`.
- The in-block `CSVPrinter.flush()` must also flush the intermediate `PrintWriter` created for a caller-supplied `Writer`.
- Writers opened by `CsvWriter` for file destinations must still be flushed and closed.
- A caller-supplied `CSVPrinter` remains caller-owned; `CsvWriter` must neither close nor replace it.
- Headers already emitted by a caller-supplied printer's constructor remain the caller's responsibility.
- Document that callers needing `withHeader` to control all header output must construct their `CSVPrinter` with `skipHeaderRecord(true)`.
- Apply the same ownership and flushing contract through deprecated `CsvExporter` delegates.

Shielding a buffered caller writer from `CSVPrinter.close()` is insufficient by itself: without an explicit flush, output can remain unavailable until the caller later flushes or closes the writer. Flushing the printer before the shield closes preserves immediate output visibility without transferring ownership.

## 7. Strip Compatible Byte Order Marks on Byte-Based Reads

Byte-based sources do not strip a leading BOM, so a UTF-8 BOM becomes part of the first column name and breaks normal column lookup. `commons-io` is already a module dependency and provides `BOMInputStream`.

Reproduction for bytes `EF BB BF` followed by `a,b\n1,2\n`:

```
CsvReader.read().from(bomFile).columnNames() => ['\uFEFFa', 'b']
```

Decision for 2.5.0: strip only a BOM compatible with the configured UTF-8, UTF-16LE, UTF-16BE, UTF-32LE, or UTF-32BE charset. Configure `BOMInputStream.Builder.setByteOrderMarks(...)` with exactly the matching `ByteOrderMark` value; the builder's default recognizes only UTF-8 and is insufficient for the UTF-16 and UTF-32 variants. Stripping is forbidden when the configured charset is plain `UTF-16`, plain `UTF-32`, or any other endianness-detecting charset because its decoder needs the BOM to choose byte order. Byte-based `File`, `Path`, `URL`, and `InputStream` entry points, including the deprecated `CsvImporter` delegates, are in scope. `Reader` and String entry points are deliberately excluded because their content has already been decoded and a leading `\uFEFF` may be intentional character data.

For caller-owned input streams, first create `CloseShieldInputStream.wrap(callerStream)`, then add `BOMInputStream` only when `markFor(charset)` returns a compatible mark:

```groovy
InputStream shielded = CloseShieldInputStream.wrap(callerStream)
ByteOrderMark mark = markFor(charset)
InputStream input = mark == null
    ? shielded
    : BOMInputStream.builder()
        .setInputStream(shielded)
        .setByteOrderMarks(mark)
        .get()
```

Never pass null or an empty mark array to `setByteOrderMarks(...)`. Plain UTF-16 and other no-strip charsets must bypass `BOMInputStream` so their decoder receives the original BOM. Streams opened internally for `File` and `URL` sources must use try-with-resources and must not be close-shielded; apply the same conditional BOM layer directly to their owned stream. Deprecated byte-based read methods, `CsvImporter`, and `CsvFormatProvider` must use the same helper path.

## 8. Normalize Duplicate Header Mode Parsing

`CsvReader.ReadBuilder.duplicateHeaderMode(String)` calls `DuplicateHeaderMode.valueOf(mode)` directly, while `CsvReadOptions.duplicateHeaderMode(String)` trims and upper-cases first. The documented entry points therefore accept different values.

```
CsvReader.read().duplicateHeaderMode('allow_all')         => rejected
CsvReadOptions.fromMap([duplicateHeaderMode:'allow_all']) => accepted
CsvReader.read().duplicateHeaderMode((String) null)       => NullPointerException
CsvReader.read().duplicateHeaderMode(null)                => dispatches to String overload
CsvReader.read().duplicateHeaderMode((DuplicateHeaderMode) null) => accepted as ALLOW_EMPTY
```

Both paths must use one normalization helper. Lower-case, mixed-case, and surrounding whitespace must be accepted. Unknown and null strings must produce an informative `IllegalArgumentException`. In dynamic Groovy, an uncast `duplicateHeaderMode(null)` resolves to the String overload and must therefore throw that exception. The typed `DuplicateHeaderMode` overload may continue treating a null enum value as the default `ALLOW_EMPTY` mode; dynamic callers reach that behavior only by explicitly casting null to `DuplicateHeaderMode`.

## 9. Resolve Dynamic Groovy Null-Options Ambiguity

Typed options overloads overlap deprecated `CSVFormat` overloads at the same arity. Dynamic Groovy cannot dispatch an explicit null argument:

```
CsvReader.read(file, null)
  => GroovyRuntimeException: Ambiguous method overloading for method se.alipsa.matrix.csv.CsvReader#read
```

Method-body changes cannot fix overload resolution. Decision for 2.5.0: explicit null options are unsupported and the dynamic ambiguity is accepted and documented. Typed overloads must require non-null `CsvReadOptions` or `CsvWriteOptions` rather than implying null support with fallback expressions.

Do not promote the generated legacy short forms to non-deprecated APIs. They must remain deprecated and retain their published Commons CSV behavior: `CsvReader.read(file)` keeps `CSVFormat.DEFAULT` whitespace handling, and `CsvWriter.write(matrix, file)` keeps the `CSVFormat.DEFAULT` CRLF separator. The supported no-options route is the fluent API: `CsvReader.read().from(...)` and `CsvWriter.write(matrix).to(...)`, whose trim and LF defaults remain unchanged.

Dynamic Groovy tests must pin the legacy short-form semantics, exercise typed entry points with non-null options and fluent no-options usage, and document the expected ambiguity for explicit null options.

## 10. Use UTF-8 in the Deprecated File Write Path

`CsvWriter.write(Matrix, File, CSVFormat, boolean)` constructs `new PrintWriter(out)`, which uses `Charset.defaultCharset()`, while every other file write path defaults to UTF-8. This diverges when the process default encoding is overridden.

The deprecated `File`, `Path`, string-path, and `CsvExporter` file entry points must write UTF-8 explicitly. Verification must use the dedicated Gradle `testNonUtf8DefaultEncoding` task configured with `-Dfile.encoding=ISO-8859-1`; a non-ASCII test under the normal UTF-8 test JVM is insufficient. Keep its test class out of the default `test` task, invoke the dedicated task explicitly during final verification, and make `check` depend on it so `check`, `build`, and CI retain the regression coverage after this release.

## 11. Minor Consistency Fixes

Apply `matrixName ?: DEFAULT_MATRIX_NAME` consistently to populated and empty matrices when no source name can be derived. `ReadBuilder.header(null)` must preserve `firstRowAsHeader`, matching the existing null guard in `CsvReadOptions.header(List)`. The URL-name rewrite must also remove the dead `URL.getFile() == null` branch because `URL.getFile()` never returns null.

Remove the unreachable `matrix.columnNames() != null` branches from both the deprecated and fluent writer header paths. `Matrix.columnNames()` always returns a list, including an empty list for a zero-column matrix, and matrix construction already supplies generated names when columns exist without explicit names. The fallback is therefore dead and is itself incorrect for zero columns because Groovy's `1..0` range produces two values. Header emission must use `matrix.columnNames()` directly.

Tests must cover the populated-source fallback name, retain the existing empty-input fallback as a characterization, and cover `header(null)` behavior.
