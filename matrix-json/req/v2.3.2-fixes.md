# matrix-json v2.3.2 fixes plan

This plan addresses the defects found in the v2.3.2 review of `matrix-json`: a broken
`to(Writer)` terminal, lossy/throwing temporal serialization, malformed column names from `null`
array elements, a wrong URL-derived matrix name, internal use of deprecated API, missing argument
validation, and a few smaller consistency items. The write-path fixes come first because they
either fail outright or silently lose data.

All findings were reproduced against the built `matrix-json-2.3.2-SNAPSHOT` jar with
Jackson 3.2.2 before this plan was written.

## 0. Compatibility decision

Keep this work in v2.3.2 (already `2.3.2-SNAPSHOT` in `matrix-json/build.gradle`). Every change is
additive or a bug fix; no public signature is removed or changed:

- `to(Writer)` currently throws for every non-`StringWriter`, so making it work is a pure fix.
- Temporal serialization currently truncates `LocalDateTime` and throws for `LocalTime`,
  `Instant`, `YearMonth`, etc.; the new behaviour produces the same output for `LocalDate` (the
  only type that worked correctly) and lossless output for everything else. Document this as a
  behaviour change in `release.md`.
- Rejecting `null`/non-object array elements with `IllegalArgumentException` replaces a
  nonsense column and a raw Jackson exception; document it.

0.1 [x] Confirm the module version is `2.3.2-SNAPSHOT` in `matrix-json/build.gradle` (it already
is; do not bump again). Section 5 also touches matrix-core (`3.9.0-SNAPSHOT`) and matrix-csv
(`2.5.0-SNAPSHOT`); both are already in progress, so no further bumps are needed, but
matrix-json 2.3.2 and matrix-csv 2.5.0 must be released after matrix-core 3.9.0.

## 1. Fix `WriteBuilder.to(Writer)` closing the caller-owned writer

`JsonWriter.WriteBuilder.writeTo` wraps the generator in `gen.withCloseable { ... }`. Jackson's
`StreamWriteFeature.AUTO_CLOSE_TARGET` is enabled by default, so closing the generator closes the
`Writer` the caller passed in; the subsequent `writer.flush()` in `to(Writer)` then throws
`IOException: Stream closed` for `FileWriter`, `BufferedWriter`, `OutputStreamWriter`, and every
other real writer. Only `StringWriter` (no-op `close()`) works today, which is all the tests use.

1.1 [x] In `matrix-json/src/main/groovy/se/alipsa/matrix/json/JsonWriter.groovy`, build the
`JsonFactory` with `StreamWriteFeature.AUTO_CLOSE_TARGET` disabled:

```groovy
private static final JsonFactory FACTORY = JsonFactory.builder()
    .disable(StreamWriteFeature.AUTO_CLOSE_TARGET)
    .build()
```

Keep `gen.withCloseable { ... }` so the generator itself is always closed (which flushes its
buffer to the writer), and keep the explicit `writer.flush()` in `to(Writer)`. Ownership then
matches matrix-csv: the writer is flushed but remains open for the caller to close.

1.2 [x] Verify that `to(File)`, `to(Path)`, and `to(String)` still close their own writer: they go
through `file.withWriter('UTF-8') { ... }`, which closes it regardless of the Jackson feature. No
change should be needed; confirm with the existing file-based tests.

1.3 [x] Update the GroovyDoc of `to(Writer)` to state: "The writer is flushed before this method
returns but remains open; the caller is responsible for closing it." Add the same sentence to
the deprecated `write(Matrix, Writer, ...)` overloads that delegate to it.

1.4 [x] Add tests in `matrix-json/src/test/groovy/JsonWriterTest.groovy`:
- `to(Writer)` with a `BufferedWriter(new FileWriter(tempFile))`: the call must not throw, the
  writer must still accept a subsequent `write('')` (i.e. is open), and after the test closes it
  the file must contain the expected JSON.
- `to(Writer)` with a custom `Writer` subclass that records `close()` calls: assert `close()` was
  never called and `flush()` was called at least once.

## 2. Make temporal serialization lossless

`JsonWriter.writeValue` applies the single `dateFormat` pattern (default `yyyy-MM-dd`) to every
`TemporalAccessor`. Verified results with the default pattern:

- `LocalDateTime.of(2024,1,2,3,4,5)` → `"2024-01-02"` (time silently dropped)
- `LocalTime`, `Instant` → `UnsupportedTemporalTypeException: Unsupported field: YearOfEra`
- `YearMonth` → `UnsupportedTemporalTypeException: Unsupported field: DayOfMonth`
- `java.util.Date` → `"Thu Jan 01 01:00:00 CET 1970"` (locale/zone-dependent `toString()`)

2.1 [x] In `JsonWriter.groovy`, restrict the `dateFormat` pattern to `LocalDate` values only
(the type for which it has always produced correct output). Add an optional, separate
`dateTimeFormat` pattern for `LocalDateTime` (`WriteBuilder.dateTimeFormat(String)`), defaulting
to `null`, meaning ISO-8601 via `toString()`.

2.2 [x] For every other `TemporalAccessor` write `value.toString()` and do not apply either
user pattern. Document this precisely: `toString()` is ISO-8601 for the core `java.time`
value types (`LocalTime`, `Instant`, `ZonedDateTime`, `OffsetDateTime`, `OffsetTime`,
`YearMonth`, `Year`, `MonthDay`), but *not* for every `TemporalAccessor` — e.g. `Month` and
`DayOfWeek` (`JANUARY`, `MONDAY`) and the `java.time.chrono` dates (`JapaneseDate` →
`Japanese Heisei 8-01-01`). Word the README and GroovyDoc as: "`LocalDate` and
`LocalDateTime` use the configured patterns; other `java.time` value types are written in
ISO-8601 via `toString()`; any other `TemporalAccessor` implementation is written using its
`toString()` value." Cover `Month` and `DayOfWeek` in the tests of task 2.6 so the documented
behaviour is pinned.

2.3 [x] Serialize `java.util.Date` (and its `java.sql.Timestamp` subclass) as ISO-8601 instants
via `value.toInstant().toString()`. Both `java.sql.Date.toInstant()` and
`java.sql.Time.toInstant()` throw `UnsupportedOperationException` (verified), so branch on those
two subclasses *before* the `java.util.Date` branch and write their `toString()` value
(`yyyy-MM-dd` and `HH:mm:ss` respectively). Order in `writeValue`:

```groovy
} else if (value instanceof java.sql.Date || value instanceof java.sql.Time) {
  gen.writeString(value.toString())
} else if (value instanceof Date) {            // java.util.Date, java.sql.Timestamp
  gen.writeString(((Date) value).toInstant().toString())
}
```

Put these branches before the generic `else`.

2.4 [x] Validate `WriteBuilder.dateFormat(String)` and the new `dateTimeFormat(String)`: throw
`IllegalArgumentException('dateFormat pattern cannot be null or blank')` (respectively
`dateTimeFormat`) on `null`/blank input, and compile the pattern eagerly with
`DateTimeFormatter.ofPattern(pattern)` inside the setter so an invalid pattern fails at
configuration time instead of at the first temporal value. `dateFormat(null)` currently fails
with `NullPointerException: pattern` at write time. Put the check in one package-scoped helper
(e.g. `JsonWriteOptions.validatePattern(String name, String pattern)`) so the builder and the
options class share it. `dateTimeFormat` differs from `dateFormat` only in that `null` is
allowed (meaning ISO-8601 default); blank or uncompilable values are rejected for both.

2.5 [x] Mirror the new option in `matrix-json/src/main/groovy/se/alipsa/matrix/json/JsonWriteOptions.groovy`:
add `dateTimeFormat` (field, fluent setter, `fromMap` key `datetimeformat`, `toMap`, and an
`OptionDescriptor('dateTimeFormat', String, null, 'Date-time format pattern for LocalDateTime values (default: ISO-8601)')`).
Pass it through in `JsonFormatProvider.write` (see task 4.1). Apply the task 2.4 validation in
`JsonWriteOptions` too: the fluent `dateFormat(String)` and `dateTimeFormat(String)` setters and
the `fromMap` branches for `dateformat` / `datetimeformat` must reject blank or uncompilable
patterns (and `null` for `dateFormat`) with the same `IllegalArgumentException` messages, so
an SPI caller (`Matrix.write([dateFormat: 'bogus'], file)`) fails at option parsing rather
than inside the writer. `fromMap` continues to treat an absent or `null` `dateTimeFormat` as
the ISO-8601 default.

2.6 [x] Add tests in `JsonWriterTest.groovy` covering, with the default settings: `LocalDate`
(unchanged `yyyy-MM-dd`), `LocalDateTime` (full ISO `2024-01-02T03:04:05`), `LocalTime`,
`Instant`, `ZonedDateTime`, `YearMonth`, `java.util.Date`, `java.sql.Timestamp`,
`java.sql.Date`, and `java.sql.Time`; plus one test each for `dateTimeFormat('yyyy/MM/dd HH:mm')` applied to
`LocalDateTime` only (a `LocalDate` in the same matrix must still use `dateFormat`), and for
`dateFormat(null)` / `dateFormat('')` / `dateFormat('not a pattern')` throwing
`IllegalArgumentException` at configuration time.

2.7 [x] Add `JsonWriteOptions` tests asserting `fromMap([dateTimeFormat: 'HH:mm'])` round-trips
through `toMap()`, that `Matrix.write([dateTimeFormat: ...], file)` via the SPI honours it, and
that each options entry point rejects bad patterns: `new JsonWriteOptions().dateFormat(null)`,
`.dateFormat('')`, `.dateFormat('not a pattern')`, `.dateTimeFormat('')`,
`.dateTimeFormat('not a pattern')`, `fromMap([dateFormat: ''])`, and
`fromMap([dateTimeFormat: 'not a pattern'])` all throw `IllegalArgumentException`, while
`.dateTimeFormat(null)` and `fromMap([dateTimeFormat: null])` are accepted.

## 3. Reject `null` and non-object array elements in `JsonReader`

`parseStream` calls `MAPPER.readValue(parser, Map)` for every element. A `null` element yields a
`null` map, `flatten('', null, flatRow)` falls through to the leaf branch and inserts the key
`''`, producing a column with an empty name (verified: `[{"a":1},null]` → columns `[a, ]`).
A scalar or array element surfaces as a raw Jackson `MismatchedInputException` mentioning
`LinkedHashMap<Object,Object>`.

3.1 [x] In `matrix-json/src/main/groovy/se/alipsa/matrix/json/JsonReader.groovy`, inspect the
token returned by `parser.nextToken()` in the loop before calling `readValue`:
- `START_OBJECT`: parse as today.
- `VALUE_NULL`: throw `IllegalArgumentException("JSON array element ${rowCount} is null; expected an object")`.
- anything else: throw `IllegalArgumentException("JSON array element ${rowCount} is ${token}; expected an object")`.

Use the zero-based element index consistently in both messages. Rejecting rather than skipping is
chosen because silently dropping a row changes row counts relative to the source, which the
existing empty-object handling (`[{}]` preserves row count) deliberately avoids.

3.2 [x] Add a `null` guard in `flatten` for defence in depth: a `null` node at `prefix == ''` is
now unreachable, but a `null` leaf under a real key (`{"a": null}`) must still be stored as a
`null` value for that column. Add a comment making this distinction explicit.

3.3 [x] Add tests in `matrix-json/src/test/groovy/JsonReaderTest.groovy` for `[{"a":1},null]`,
`[1,2]`, `[[1,2]]`, and `["x"]` asserting the `IllegalArgumentException` message includes the
element index and token, and a regression test asserting `[{"a":1},{"a":null}]` still yields a
single column `a` with values `[1, null]`.

## 5. Fix URL-derived matrix name (shared helper in matrix-core)

`https://x/y/data.json?v=1.2` yields the matrix name `data.json?v=1` (verified). The

not. Switching to bare `url.getPath()` would fix the query string but leave percent-encoding in

## 6. Argument validation in options classes

6.1 [x] `JsonWriteOptions.fromMap` casts any `Map` under `columnFormatters` to
`Map<String, Closure>` without checking entries; a non-`String` key or non-`Closure` value fails
later inside formatter lookup / `Matrix.apply` with a `ClassCastException` or an unhelpful
message. Add a single package-scoped helper (e.g. `JsonWriteOptions.validateColumnFormatters(Map)`)
that checks every entry and throws `IllegalArgumentException`:
checked in this order for each entry:
1. key `null`, or a `CharSequence` that is blank → `"columnFormatters column name cannot be null or blank"`
2. key not a `String` → `"columnFormatters key must be a String but was ${key.class}"`
3. value not a `Closure` (including `null`) → `"columnFormatters value for column '${key}' must be a Closure but was ${value?.class}"`

The null/blank check must come first; otherwise a `null` key would be reported as a key-type
error.

Call the helper from `JsonWriteOptions.fromMap`, `JsonWriteOptions.columnFormatters(Map)`,
`JsonWriter.WriteBuilder.columnFormatters(Map)`, and `JsonWriter.WriteBuilder.formatter(String, Closure)`
(the last one validating its two arguments the same way). Unknown column names continue to be
reported at write time by the existing check in `writeTo`, since the matrix is not known when
the options object is built.

6.2 [x] `JsonReadOptions.fromMap` silently ignores a `types` value that is neither a `List` nor
an array, and accepts any `List`/array contents; `[String, 'not-a-class']`, an `Object[]` of
non-classes, or a primitive array all fail later in `Matrix.convert`. Make it consistent with
the `charset` option:
- `null` → treated as absent (no `types` conversion), exactly like `charset: null` today; must not throw
- non-`null`, non-`List`, non-array value → `IllegalArgumentException("types must be a List<Class> or Class[] but was ${value.class}")`
- array that is not a `Class[]` (`value.class != Class[]`) → same message
- any element that is not a `Class` (including `null`) → `IllegalArgumentException("types[${index}] must be a Class but was ${element?.class}")`

Apply the element check in the fluent `types(List<Class>)` setter as well, since Groovy's
generics are unchecked at runtime; `types(null)` in the setter also stays valid (clears the
option). Add a regression test for `JsonReadOptions.fromMap([types: null]).types == null`.

6.3 [x] Add tests in a new `matrix-json/src/test/groovy/JsonOptionsTest.groovy` for every
validation path in 6.1 and 6.2 (non-`String` key, `null` key, blank key, non-closure value,
`null` value, bad `types` container, `Object[]`/`int[]` arrays, and a non-`Class` element),
plus a positive case for each entry point. For the `null` key case assert the exact
"column name cannot be null or blank" message, so the check order in the helper (null/blank
key → key type → value) is pinned and a `null` key is not reported as a key-type error.

## 7. Trailing content after the JSON array

`JsonReader` disables `DeserializationFeature.FAIL_ON_TRAILING_TOKENS`, but `parseStream` stops
at `END_ARRAY` and never looks further, so the feature has no effect and `[{"a":1}] xyz`
returns one row without error (verified).

Verified Jackson behaviour for `parser.nextToken()` after `END_ARRAY`:
- `[{"a":1}]` and `[{"a":1}] ` → `null`
- `[{"a":1}] {"b":2}` → `START_OBJECT`
- `[{"a":1}] xyz` → throws `tools.jackson.core.exc.StreamReadException: Unrecognized token 'xyz'`
- `[{"a":1}]]` → throws `StreamReadException: Unexpected close marker ']'`

So a simple `!= null` check cannot produce a uniform error: lexically invalid trailing text
throws before a token is returned.

7.1 [x] Decide the intended behaviour. Recommended: after the loop, wrap the extra
`parser.nextToken()` call:

```groovy
JsonToken trailing
try {
  trailing = parser.nextToken()
} catch (StreamReadException e) {
  throw new IllegalArgumentException("Unexpected content after JSON array: ${e.originalMessage}", e)
}
if (trailing != null) {
  throw new IllegalArgumentException("Unexpected content after JSON array: ${trailing}")
}
```

Keep `.disable(DeserializationFeature.FAIL_ON_TRAILING_TOKENS)` on the per-element mapper:
without it, Jackson treats the next array element (or `END_ARRAY`) as trailing content while
deserializing a single `Map`. The explicit parser check above remains the authoritative strict
whole-document validation.

7.2 [x] Add tests matching the decision in 7.1 for all four shapes above: valid extra JSON
(`[{"a":1}] {"b":2}`), invalid text (`[{"a":1}] xyz`), stray close marker (`[{"a":1}]]`), and
trailing whitespace only (`[{"a":1}] \n`, which must still succeed). For the strict option,
assert `IllegalArgumentException` with the trailing-content message and, for the invalid-text
case, that the cause is a `StreamReadException`.

## 8. `NaN`/`Infinity` doubles are written as strings

Jackson's default `JsonWriteFeature.WRITE_NAN_AS_STRINGS` produces `{"d":"NaN"}`, which reads
back as the `String` `"NaN"` instead of a number (verified).

/ `Float.isFinite` check before `gen.writeNumber`), since JSON has no representation for them

`JsonWriter` class GroovyDoc and in `README.md`.

8.2 [x] Add a writer test with `Double.NaN`, `Double.POSITIVE_INFINITY`, and `Float.NaN`
