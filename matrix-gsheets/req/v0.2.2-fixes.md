# matrix-gsheets v0.2.2 fixes plan

This plan addresses the defects found in the v0.2.2 review of `matrix-gsheets`: authentication
failures surfacing as bare `NullPointerException`s, range parsing crashes on inputs Google accepts,
converter boundary errors, a post-write failure in `GsheetsWriter.update()`, per-call token
refresh/tokeninfo overhead, ADC file permissions, an inconsistent numeric precision guard, and a
number of stale docs. Every finding was reproduced with a probe against the module's test
classpath before this plan was written. The module is already at `0.2.2-SNAPSHOT`.

Ordering: user-facing failures first (sections 1–4), then auth/perf/security (5–6), then
consistency and docs (7–10), verification last (11). Tests live in package
`test.alipsa.matrix.gsheets`, so anything a test must call has to be public (the existing
`*WithService` pattern in `GsheetsReader` is the model).

## 1. Fail loudly when authentication fails

Today `GsAuthenticator.authenticate()` logs and returns `null`
(`GsAuthenticator.groovy:230-237`); every caller then does
`new HttpCredentialsAdapter(creds)` which throws `NullPointerException: null`
(`GsheetsReader.groovy:289`, `GsheetsWriter.groovy:440`, `GsUtil.groovy:44,155`).

1.1 [x] Introduce a seam so the decision logic in `authenticate` can be exercised without gcloud,
a browser, or the network. Add a small interface in `GsAuthenticator`:
```groovy
interface AuthBackend {
  /** Existing ADC credentials, or null when none are usable (mirrors getCredentials). */
  GoogleCredentials existing(List<String> scopes)
  /** Runs the interactive login and returns the resulting credentials, or null on failure. */
  GoogleCredentials login(List<String> scopes, String quotaProjectId)
  /** True when the credentials' token carries every required scope. */
  boolean hasAllScopes(GoogleCredentials creds, List<String> scopes)
  /** The authenticated user's email for the success log line, or null if it cannot be fetched. */
  String userEmail(GoogleCredentials creds)
}
```
with a private static `DEFAULT_BACKEND` whose four methods call `getCredentials(scopes)`,
`loginAndGetCredentials(scopes, quotaProjectId)`, `GsAuthUtils.hasAllScopes(creds, scopes)` and
the existing `getUserEmail(creds)` respectively (no behaviour change). The three-argument
`authenticate` must call `backend.userEmail(creds)` — not `getUserEmail` directly — so a stub
backend keeps the success path fully offline.

1.2 [x] Split `authenticate(List<String> requestedScopes = SCOPES, String quotaProjectId = null)`
into a thin public wrapper that calls
`authenticate(requestedScopes, quotaProjectId, DEFAULT_BACKEND)` and a public three-argument
overload containing the current scope-merging and check logic. In the overload, replace the two
`return null` branches with
`throw new SheetOperationException('authenticate', <the message currently logged>)` (the
`(operation, message)` constructor). Keep the `log.error` lines. Update the GroovyDoc `@return`
on all `authenticate` overloads to say they return credentials or throw
`SheetOperationException`, and remove the wrong "`@return true if successful`" text.

1.3 [x] `getCredentials(...)` and `loginAndGetCredentials(...)` keep returning `null` (they are the
probe/login primitives behind the backend); only `authenticate` changes. Confirm no production
caller of `authenticate` null-checks the result (grep shows none do).

1.4 [x] Tests in `GsAuthenticatorTest` using a stub `AuthBackend` (a Groovy map-coerced or
anonymous implementation) and a dummy `GoogleCredentials.create(new AccessToken('tok', farFuture))`:
- `existing` → null, `login` → null: `authenticate([SCOPE_SHEETS], null, backend)` throws
  `SheetOperationException` with `operation == 'authenticate'` and a message containing
  `Authentication failed` (first throw branch);
- `existing` → creds, `hasAllScopes` → false, `login` → creds, `hasAllScopes` still false:
  throws `SheetOperationException` whose message contains `missing required scopes` (second
  branch), and `login` was invoked exactly once;
- `existing` → creds, `hasAllScopes` → true: returns the same instance and `login` was never
  invoked;
- `existing` → null, `login` → creds, `hasAllScopes` → true: returns creds (login path).
The success-path email lookup goes through `backend.userEmail(creds)` (task 1.1); the stub returns
a fixed string such as `'stub@example.test'`, so no test reaches the network even though the scope
merge always adds `openid`/`userinfo.email`. Update `release.md`: "`authenticate()` now throws
`SheetOperationException` instead of returning `null`".

## 2. Make range validation and column counting agree

`GsUtil.validateRange` (`GsUtil.groovy:271-281`) accepts `'a1:d10'`, `'Sheet1!1:5'` and
`'hello B2 world'`, but `columnCountForRange` (`GsUtil.groovy:114-115`) indexes
`(cell =~ COLUMN_PATTERN)[0]` without checking for a match and throws
`IndexOutOfBoundsException: index is out of range 0..-1` for the first two. Google accepts
lowercase column letters.

2.1 [x] In `columnCountForRange`, uppercase the cell part before matching
(`String cellRange = (...).toUpperCase(Locale.ROOT)`) so `a1:d10` counts as 4. Replace the two
unchecked `[0][1]` lookups with a full-endpoint match, not just a leading-column check: each
endpoint must satisfy `ENDPOINT_PATTERN = ~/^([A-Z]+)(\d*)$/` via `matcher.matches()` (column
letters with an optional row number, so `A1`, `A`, `D10` pass; `Bgarbage`, `D10 junk`, `1`, `A1B`
fail). A single-cell range keeps the existing `^[A-Z]+\d+$` check. Any endpoint that does not
match throws `IllegalArgumentException("Invalid range format: '${range}'. Expected A1 notation like ...")`
(reuse the existing message text via a private constant so it is not duplicated three times).
Row-only ranges (`1:5`) therefore fail with the same message — the column count is undefined for
them. Take the column letters from `matcher.group(1)`. Drop `@CompileDynamic` from the method once
the explicit `Matcher` compiles statically (it should).

2.2 [x] Rewrite `validateRange(String)` to delegate: null/blank check, then
`columnCountForRange(range)` inside a try that rethrows `IllegalArgumentException` unchanged.
Delete the `.*!?[A-Z]+\d+.*` regex. `parseStartCell` in `GsheetsWriter` (`:428`) has a narrower
contract than `validateRange`: it needs a *full* starting cell (column **and** row) to place
number formats, so it must become case-insensitive (uppercase the start cell before the
`^([A-Z]+)\d+$` match, so `b2:c9` → `[1, 1]`) but must keep rejecting row-less starts such as
`A:D` or `A1:D`'s counterpart `A:D10` with `IllegalArgumentException("Cannot parse starting cell ...")`.
That rejection is intentional and, after task 4.1, happens in the preflight before any write:
open-ended ranges are valid for plain updates, but a formatted write (matrix with positive-scale
`BigDecimal`s) to a range without a starting row cannot be anchored. Update the exception message
to say so: `"Cannot parse starting cell from range '${range}': a range with a starting row (e.g. Sheet1!A1) is required when the matrix contains decimal values that need number formatting"`.

2.3 [x] Tests in `GsUtilTest`:
- `columnCountForRange('a1:d10') == 4`, `columnCountForRange('Sheet1!b2:c2') == 2`
- `columnCountForRange('Sheet1!1:5')`, `columnCountForRange('A:1')`,
  `columnCountForRange('A1:Bgarbage')`, `columnCountForRange('A1:D10 junk')`,
  `columnCountForRange('A1B:C2')` → `IllegalArgumentException` whose message contains
  `Invalid range format` (not `IndexOutOfBoundsException`)
- `columnCountForRange('A:D') == 4` and `columnCountForRange('A1:D') == 4` still pass (open-ended
  ranges Google accepts)
- `validateRange('hello B2 world')` and `validateRange('Sheet1')` → `IllegalArgumentException`
- `validateRange('a1:d10')` and `validateRange("'My Sheet'!A1")` pass
Existing tests `testColumnCountForRange*` and `GsheetsReaderTest.testReadInvalidRangeThrows` must
still pass.

## 3. Fix `GsConverter` boundary behaviour

3.1 [x] `asLocalTime(Number)` (`GsConverter.groovy:147-153`): `LocalTime.ofSecondOfDay(86400)` and
negative seconds throw `DateTimeException`. Compute
`long totalSeconds = Math.floorMod(((val as BigDecimal) * SECONDS_PER_DAY).round() as long, SECONDS_PER_DAY)`
so `1.0` → `00:00` and `-0.5` → `12:00` (consistent with how `asLocalDateTime` treats the
fraction as time-of-day within the serial's day).

3.2 [x] `asLocalDate(Number)` (`:56-59`) truncates with `longValue()` while `asLocalDateTime(Number)`
(`:101-110`) effectively floors: `asLocalDate(-0.5)` → `1899-12-30`, `asLocalDateTime(-0.5)` →
`1899-12-29T12:00`. Use `long days = Math.floor(val.doubleValue()) as long` in `asLocalDate`.
Note: for `BigDecimal` input `val.doubleValue()` is already what `asLocalDateTime` does; do not
change `asLocalDateTime`.

3.3 [x] Remove the stale 1900-leap-year comment block at `GsConverter.groovy:95-100` — it describes
an adjustment the code does not perform, and the code's mapping (`61` → `1900-03-01`) is the
correct Google Sheets mapping (Sheets, unlike Excel, has no 1900-02-29). Replace with one line:
`// Google Sheets serials: day 0 = 1899-12-30, no Excel-style 1900 leap-day bug.`

3.4 [x] Tests in `GsConverterTest`:
- `asLocalTime(1.0) == LocalTime.MIDNIGHT`, `asLocalTime(1.5) == LocalTime.NOON`,
  `asLocalTime(-0.5) == LocalTime.NOON`
- `asLocalDate(-0.5) == LocalDate.of(1899, 12, 29)` and
  `asLocalDateTime(-0.5).toLocalDate() == asLocalDate(-0.5)`
- `asLocalDate(61) == LocalDate.of(1900, 3, 1)` (pins the no-leap-bug mapping)
- round trip `asLocalDateTime(asSerial(LocalDateTime.of(2024,1,1,23,59,59)))` unchanged

## 4. Validate `GsheetsWriter.update()` inputs before writing

`update()` (`GsheetsWriter.groovy:361-364`) only calls `parseStartCell(range)` after
`values().update(...)` has succeeded, so a matrix with a positive-scale `BigDecimal` and a range
such as `Sheet1!A:D` throws `IllegalArgumentException("Cannot parse starting cell ...")` after the
sheet was already modified.

4.1 [x] Extract the local, API-free checks into one private helper
`private static int[] preflightUpdate(String spreadsheetId, String range, Matrix matrix)` that runs
`GsUtil.validateSheetId`, `GsUtil.validateRange`, the null/empty matrix checks, and — only when
`hasScaledDecimalCell(matrix)` — `parseStartCell(range)`; it returns the parsed `[row, col]` or
`null` when no number formats will be needed.

4.2 [x] Add a public overload
`static String updateWithService(String spreadsheetId, String range, Matrix matrix, Sheets sheetsService, boolean convertNullsToEmptyString = true, boolean convertDatesToSerial = false)`
mirroring `GsheetsReader.readAsObjectWithService`. It calls `preflightUpdate` first (so it is safe
to call directly), throws `IllegalArgumentException('sheetsService must not be null')` for a null
service, then performs the `values().update` call, and reuses the returned start cell for
`buildNumberFormatRequests` instead of re-parsing. `resolveSheetId` (needs the API) stays where it
is, after the write.

4.3 [x] Rewrite `update(...)` as: `preflightUpdate(spreadsheetId, range, matrix)` →
`Sheets sheets = buildSheetsService(credentials)` → `updateWithService(...)`. The preflight runs
twice on that path, but it is cheap and side-effect free, and it guarantees no service (and no
interactive login) is constructed for inputs that would fail. Update the GroovyDoc
`@throws IllegalArgumentException` on both methods to say it is thrown before any write.

4.4 [x] Also use the `(operation, spreadsheetId, cause)` constructor at
`GsheetsWriter.groovy:183` (`'create spreadsheet', null, e`) so the `IOException` cause and stack
trace are preserved like the other three catch blocks.

4.5 [x] Test in `GsheetsWriterTest` using a `mock(Sheets)` (pattern from `GsheetsReaderTest:101`):
`updateWithService(id, 'Sheet1!A:D', matrixWithBigDecimal('1.50'), sheetsService)` throws
`IllegalArgumentException` and `verifyNoInteractions(sheetsService)`. Add a positive mock test that
`updateWithService(id, 'Sheet1!B2', plainMatrix, sheetsService)` calls `values().update(...)`
once and never `batchUpdate`.

4.6 [x] Test in `GsheetsWriterTest` that proves the case-insensitive `parseStartCell` path end to
end (the two tests above never parse coordinates successfully): a one-row matrix with a single
`BigDecimal('1.50')` column, written with `updateWithService(id, 'Sheet1!b2', matrix, sheetsService)`.
Mock chain: `spreadsheets().values().update(eq(id), eq('Sheet1!b2'), any(ValueRange))` →
`Update` whose `setValueInputOption('RAW').execute()` returns an `UpdateValuesResponse`;
`spreadsheets().get(id)` → `Get` whose `setFields('sheets.properties').execute()` returns a
`Spreadsheet` with one `Sheet` titled `Sheet1` and `sheetId 7`;
`spreadsheets().batchUpdate(eq(id), captor.capture())` → `BatchUpdate` whose `execute()` returns
a `BatchUpdateSpreadsheetResponse`. Assert on the captured `BatchUpdateSpreadsheetRequest`:
exactly one request, `repeatCell.range` has `sheetId == 7`, `startRowIndex == 2` (`b2` → row
index 1, plus 1 for the header row), `endRowIndex == 3` (one data row), `startColumnIndex == 1`,
`endColumnIndex == 2`, and `repeatCell.cell.userEnteredFormat.numberFormat.pattern == '0.00'`
with `type == 'NUMBER'`. Also `verify(update).execute()` once and that `get` and `batchUpdate`
were each called once. A sibling assertion with `'Sheet1!B2'` must produce an identical captured
request, pinning that case does not affect placement.

## 5. Stop refreshing and calling tokeninfo on every request

`GsAuthUtils.hasAllScopes` (`GsAuthUtils.groovy:161-186`) calls `creds.refresh()` unconditionally
and then GETs `https://oauth2.googleapis.com/tokeninfo`; `authenticate()` calls it twice on the
happy path (`GsAuthenticator.groovy:226,234`). Each `GsheetsReader.read()` with default credentials
therefore costs one forced OAuth refresh plus two tokeninfo round trips before the Sheets call.
The `catch (IOException ignored) { creds.refreshIfExpired() }` fallback rethrows the same
`IOException`, which then escapes `authenticate()` instead of triggering a login.

5.1 [x] In `hasAllScopes`, replace the `refresh()`/`refreshIfExpired()` pair with a single
`creds.refreshIfExpired()` inside `try { } catch (IOException e) { log.debug(...); return false }`
so a dead refresh token falls through to the login path rather than propagating.

5.2 [x] Add a small static cache in `GsAuthUtils`: a `LinkedHashMap<String, Set<String>>` from
access-token value to granted scopes with `removeEldestEntry` at size 8. The lookup-miss →
resolve → insert sequence is a compound operation, so `Collections.synchronizedMap` (which only
guards individual `get`/`put`) is not enough — concurrent callers with the same token would all
miss and all call tokeninfo. Guard the whole sequence with a private static lock object
(`synchronized (SCOPE_CACHE_LOCK) { ... }`), performing the resolver call inside the lock. The
lock is only held during the rare miss and the tokeninfo call is short, so serialising it is
acceptable; do not attempt per-token in-flight futures here. Wrap the resolution in
`try/catch (IOException e)` → `return false` with a `log.warn`, so a network error also routes to
login instead of escaping (do not cache failures). Expose `static void clearScopeCache()`
(public; documented as a test/diagnostic hook, takes the same lock) so tests can reset state in
`@AfterEach`.

5.3 [x] In `GsAuthenticator.authenticate`, drop the second `hasAllScopes` call at `:234` when the
first check at `:226` already passed (track with a local boolean); keep it only on the
post-login path.

5.4 [x] Make the scope source injectable instead of relying on hidden state. Because the resolver
is expected to fail with `IOException`, do **not** use `java.util.function.Function` (its `apply`
declares no checked exception, so the contract would be invisible to Java callers and to the
`catch (IOException e)` in 5.2). Define a dedicated interface in `GsAuthUtils`:
```groovy
@FunctionalInterface
interface ScopeResolver {
  Set<String> grantedScopes(String accessToken) throws IOException
}
```
Extract the tokeninfo call into `static Set<String> fetchGrantedScopes(String token) throws IOException`
(public; Groovy default visibility) and add a public overload
`static boolean hasAllScopes(GoogleCredentials creds, List<String> required, ScopeResolver resolver)`.
The existing two-argument `hasAllScopes` delegates with
`GsAuthUtils.&fetchGrantedScopes as ScopeResolver` (or an explicit closure). The cache from 5.2
sits in the three-argument method, keyed by token value, so both overloads share it.

5.5 [x] Tests in `GsAuthUtilsTest` (no network): build
`GoogleCredentials.create(new AccessToken('tok-1', Date.from(Instant.now().plusSeconds(3600))))`
(not expired, so `refreshIfExpired()` is a no-op), and a resolver closure that records its calls
and returns `[SCOPE_SHEETS] as Set`. Assert:
- `hasAllScopes(creds, [SCOPE_SHEETS_READONLY], resolver)` is true (read-only implied by
  read/write) and `hasAllScopes(creds, [SCOPE_DRIVE_FILE], resolver)` is false;
- calling it twice with the same token invokes the resolver exactly once (cache hit);
- 8 threads calling it concurrently with the same token (a `CountDownLatch`-released
  `ExecutorService`, resolver sleeping ~50 ms and counting with an `AtomicInteger`) invoke the
  resolver exactly once;
- after `clearScopeCache()` the resolver is invoked again;
- a resolver that throws `IOException` makes `hasAllScopes` return false rather than propagate.
Call `GsAuthUtils.clearScopeCache()` in `@AfterEach` so tests do not leak cache entries.

## 6. Write the ADC file with owner-only permissions

`GsAuthUtils.loginAndWriteAdc(Reader, ...)` (`GsAuthUtils.groovy:130-132`) writes
`client_secret` + `refresh_token` with the process umask; gcloud writes the same file `0600`.

6.1 [x] Extract `static void writeAdcFile(File adcFile, String json)` (public; Groovy default
visibility) that never exposes the secrets under umask permissions, even briefly:
- create the parent directories;
- create a temporary file **in the same directory** with owner-only access from the start, and
  refuse to write secrets if that cannot be guaranteed:
  - POSIX (`FileSystems.default.supportedFileAttributeViews().contains('posix')`):
    `Files.createTempFile(dir, 'adc-', '.tmp', PosixFilePermissions.asFileAttribute(PosixFilePermissions.fromString('rw-------')))`;
  - otherwise, if the `acl` view is supported (Windows NTFS): `Files.createTempFile(dir, 'adc-', '.tmp')`,
    then, while the file is still empty, replace its ACL with a single entry —
    `AclEntry.newBuilder().setType(AclEntryType.ALLOW).setPrincipal(view.owner).setPermissions(EnumSet.allOf(AclEntryPermission)).build()`
    via `Files.getFileAttributeView(tmp, AclFileAttributeView).setAcl([entry])`. Read the ACL back
    and verify it contains only that entry;
  - if neither view is available, or setting/verifying the permissions throws or does not match,
    delete the temp file and throw `IOException("Cannot restrict ADC file permissions to the current user on this file system; run 'gcloud auth application-default login' instead")`
    **before** any secret is written. `java.io.File.setReadable/setWritable` are not used: they
    return `false` on Windows for the "readable" case and cannot express owner-only, so a
    log-and-continue fallback would silently leave a umask-permissioned secrets file;
- write the JSON into the temp file;
- `Files.move(tmp, target, StandardCopyOption.ATOMIC_MOVE)`; per the `Files.move` contract, when
  `ATOMIC_MOVE` is given all other options are ignored and replacing an existing target is
  implementation-specific, so a second `writeAdcFile` may throw `FileAlreadyExistsException`
  (or another `IOException`) on some file systems — the portable contract only promises "an
  `IOException`", not a specific subtype. Catch `IOException` from the atomic attempt (this
  covers `AtomicMoveNotSupportedException`, `FileAlreadyExistsException`,
  `AccessDeniedException` and any provider-specific failure) and, provided the temp file still
  exists (an atomic move is all-or-nothing, so on failure it does), retry with
  `Files.move(tmp, target, StandardCopyOption.REPLACE_EXISTING)`. If the fallback also throws,
  add the original atomic-move exception as a suppressed exception and rethrow the fallback's, so
  neither cause is lost. The temp file already carries the owner-only permissions, so the
  non-atomic fallback is still never world-readable; the only thing lost is atomicity of the
  replace;
- on any exception, delete the temp file in a `finally` and rethrow — a login must not leave a
  half-written secrets file behind.
The moved file keeps the temp file's permissions/ACL (same directory, rename), so no
`chmod`-after-write is needed and the secrets are never on disk with broader access, not even
transiently. Document the "refuse rather than degrade" behaviour in the method GroovyDoc and in
`release.md`.

6.2 [x] Tests in `GsAuthUtilsTest` with `@TempDir Path tempDir` (a directory, not a file — the
method takes the target file, so define it explicitly:
`File adc = tempDir.resolve('application_default_credentials.json').toFile()`) and use that same
`adc` for every assertion:
- `writeAdcFile(adc, '{}')` produces a file whose text is `{}`, and on POSIX
  (`Assumptions.assumeTrue(posix)`) `Files.getPosixFilePermissions(adc.toPath()) == PosixFilePermissions.fromString('rw-------')`;
- on a file system with the `acl` view (`Assumptions.assumeTrue(acl)`, i.e. Windows CI) the
  resulting ACL has exactly one entry whose principal is the file owner;
- calling `writeAdcFile(adc, '{"a":1}')` again overwrites in place (`adc.text == '{"a":1}'`) and
  keeps the same permissions;
- after each call `tempDir` contains only `adc` — no `adc-*.tmp` file remains;
- the "neither view available" branch is covered by extracting the permission step into
  `static void restrictToOwner(Path file, Set<String> supportedViews)` (public; Groovy default
  visibility) and calling it with `[] as Set` → `IOException` whose message contains
  `Cannot restrict ADC file permissions`, and asserting the file still has zero length.
Mention in `release.md`.

## 7. Apply the exact-integer guard to all integral numbers

`GsUtil.toCell` (`GsUtil.groovy:225-251`) rejects a `BigDecimal` above 2^53 but passes `Long` and
`BigInteger` of the same magnitude straight through, where Sheets silently rounds them.

7.1 [x] Extract `private static void requireExactDouble(BigInteger value, Object original)` that
throws the existing `IllegalArgumentException` text when `value.abs() > MAX_EXACT_DOUBLE_INTEGER`,
and call it from the `BigDecimal` branch and from a new branch placed before the generic
`v in Number` check that covers every 64-bit-or-wider integral type in the JDK:
`Long`, `BigInteger`, `java.util.concurrent.atomic.AtomicLong` and
`java.util.concurrent.atomic.LongAdder`/`LongAccumulator` (compare via `BigInteger.valueOf(v.longValue())`
for the `long`-backed ones). After validation, `AtomicLong`, `LongAdder` and `LongAccumulator`
are **returned as `v.longValue()`** (a `Long`), never as the wrapper object — Gson would otherwise
serialise the wrapper as a JSON object (`{"value":42}`), not a numeric cell. `Long` and
`BigInteger` are returned as-is. `Integer`/`Short`/`Byte`/`AtomicInteger` cannot exceed 2^53 and
need no check. State in the `toCell` GroovyDoc that any *other* `Number` subclass (third-party
arbitrary-precision types) is passed through unchecked. Message must say "integer value", not
"BigDecimal integer value", so it reads correctly for all guarded types.

7.2 [x] Tests in `GsUtilTest`: `toCell(2L ** 53 as long, ...)` passes, `toCell((2L ** 53) + 1, ...)`
throws, `toCell(BigInteger.ONE.shiftLeft(60), ...)` throws, `toCell(Long.MIN_VALUE, ...)` throws,
and for each of `AtomicLong`, `LongAdder` (via `add(...)`) and `LongAccumulator`
(`new LongAccumulator(Long::sum, 0L)` then `accumulate(...)`): a value of `1L << 60` throws, and a
value of `42L` returns exactly `42L` as a `Long` (`assertEquals(42L, result)` plus
`assertTrue(result instanceof Long)`), not the wrapper instance.
Update the existing `testToCellWith*BigDecimal*` tests only if the message text changed.
Document in `release.md` as a behaviour change (previously silently accepted).

## 8. Small robustness fixes

8.1 [x] `GsUtil.sanitizeSheetName(null)` (`GsUtil.groovy:202`) throws a raw NPE. Treat `null` like
blank: `if (name == null) return 'Sheet1'` (matches the existing empty-string behaviour). Test:
`sanitizeSheetName(null) == 'Sheet1'`.

8.2 [x] Quoted sheet names containing `!` (`'Q!A'!A1:B2`) are rejected by `columnCountForRange`
because of `range.split('!')` (`GsUtil.groovy:92`). Add a **public** (Groovy default visibility —
it is called from `GsheetsReader` and `GsheetsWriter`, so it cannot be private) utility
`static String[] splitSheetAndCells(String range)` in `GsUtil` with this contract, stated in its
GroovyDoc:
- returns a two-element array `[sheetPart, cellPart]`;
- `sheetPart` is `null` when the range has no `!` prefix, otherwise the raw prefix exactly as
  written (surrounding quotes and doubled `''` are **not** removed — unquoting stays in
  `GsheetsWriter.extractSheetName`, which becomes a thin wrapper);
- `cellPart` is everything after the separating `!` (may be empty; callers validate it);
- when the range starts with `'`, the separator is the first `!` after the closing quote (a `''`
  pair inside the name is an escaped quote, not a closing quote); otherwise it is the first `!`;
- a range that starts with `'` but has no closing quote throws `IllegalArgumentException`
  (`Invalid range format`).
Use it from `columnCountForRange`, `GsheetsReader.readAs*Values` (`:182,250`) and
`GsheetsWriter.extractSheetName`/`parseStartCell` (`:409,425`) so there is a single
implementation (DRY); delete the local `SHEET_NAME_SEPARATOR`/`RANGE_SPLIT_LIMIT` constants that
become unused. Tests in `GsUtilTest`: `splitSheetAndCells('A1:B2') == [null, 'A1:B2']`,
`splitSheetAndCells('Sheet1!A1') == ['Sheet1', 'A1']`,
`splitSheetAndCells("'Q!A'!A1:B2") == ["'Q!A'", 'A1:B2']`,
`splitSheetAndCells("'It''s!here'!A1") == ["'It''s!here'", 'A1']`, unterminated quote → IAE, and
`columnCountForRange("'Q!A'!A1:B2") == 2`. `GsheetsWriter.extractSheetName("'It''s!here'!A1")`
→ `It's!here` (make `extractSheetName` public or test through `updateWithService` with a mocked
`spreadsheets().get`).
