### Decisions

- **Null handling policy (F2, F3):** consistent with the existing `removeNulls()` on box values, null *inputs* are **dropped**, not rejected: `BoxChart` skips rows whose category is `null`; `Histogram` skips `null` values. A column that is empty after dropping nulls is rejected with `IllegalArgumentException`.
- **Bins (F3):** `bins` must be a positive integer; `null`, `0` and negatives throw `IllegalArgumentException("bins must be a positive integer, got …")` from the factories and from `Builder.bins(...)`.
- **Positional factories (F4, F8a):** the deprecated positional factories are kept, but `CharmBridge` now rejects series whose length differs from the category list with `IllegalArgumentException` so silent truncation cannot happen. `BarChart.create(...)` with zero value columns produces an empty name list. `Chart.validateSeries` is marked `@Deprecated` (it validates `Matrix[]` inputs no factory accepts).
- **Radar alpha (F5):** fix in Charm (`PolygonRenderer` → `fill-opacity`), which matches ggplot2 (`alpha` on `geom_polygon` affects the fill only) and the other Charm area-like renderers. This deliberately changes the public `PolygonBuilder.alpha(Number)` contract for **every** polygon (currently documented as "polygon opacity"): the Javadoc is updated, a renderer test pins the new behaviour, and it is recorded under *Behaviour changes* in `matrix-charts/release.md`. `matrix-ggplot`'s `GeomPolygonTest` only asserts that alpha renders, so no ggplot test changes are expected (verified by running the ggplot suite in 8.4).
- **Plot API (F7):** add sized overloads that route through `CharmBridge.renderSvg(chart, width, height)`: `jpg(Chart, File, int, int, BigDecimal = 1.0)`, `jpg(Chart, OutputStream, int, int, BigDecimal = 1.0)`, `pdf(Chart, File, int, int)`, `pdf(Chart, OutputStream, int, int)`, `jfx(Chart, int, int)`, `swing(Chart, int, int)`, `base64(Chart, int = 800, int = 600)`; deprecate `base64(Chart, double, double)`. The existing unsized signatures are unchanged.

```groovy
  private static void applyYLabels(Scale scale, Map<String, String> yLabels) {
    List<String> sortedKeys = yLabels.keySet().sort { String key -> yLabelBreak(key) } as List<String>
    scale.breaks = sortedKeys.collect { String key -> yLabelBreak(key) }
    scale.labels = sortedKeys.collect { String key -> yLabels[key] }
  }

  private static BigDecimal yLabelBreak(String key) {
    if (key == null || key.isBlank()) {
      throw new IllegalArgumentException("yLabels key '${key}' is not numeric; keys must be axis break values such as '10' or '2.5'")
    }
    try {
      new BigDecimal(key.trim())
    } catch (NumberFormatException ignored) {
      throw new IllegalArgumentException("yLabels key '${key}' is not numeric; keys must be axis break values such as '10' or '2.5'")
    }
  }
```

```markdown
**Bug fixes**

- `Histogram.ranges` no longer drops the maximum value when `(max - min) / bins` rounds down;
  the last bin's upper bound is now exactly the column maximum.

  series `["1", "0"]`.
- Rendering now rejects value series whose length differs from the category list instead of
  silently plotting `null`s or dropping values. This affects the deprecated positional factories
  (`AreaChart.create(title, categories, values...)`, `PieChart.create(title, categories, values)`,
  `BarChart.create(title, type, direction, categories, values...)`) and charts whose
  `categorySeries`/`valueSeries` — or, for `BubbleChart`, the `sizeSeries`/`groupSeries`
  properties — were assigned directly after construction. A grouped `BubbleChart` (built with
  `group(...)`) whose `groupSeries` is later emptied is rejected instead of silently rendering ungrouped.
- `ScatterChart.create(title, data, x, y)` now sets `valueSeriesNames` to `[y]`, so named
  `seriesColors` overrides apply.
- A non-numeric `yLabels` key is reported as `IllegalArgumentException("yLabels key '…' is not numeric")`.
- `RadarChart.fillAlpha` affects only the polygon fill (Charm now renders polygon alpha as
  `fill-opacity`); previously the outline faded too.

**API improvements (continued)**

- `Plot.jpg`, `Plot.pdf`, `Plot.jfx` and `Plot.swing` gained overloads taking explicit
  `width` and `height`; `Plot.base64(Chart, int, int)` replaces the `double` variant, which is
  deprecated.
- `Chart.validateSeries(Matrix[])` is deprecated; no factory accepts `Matrix[]` input.
```
