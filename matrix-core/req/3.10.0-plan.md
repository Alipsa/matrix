## 7. Reject stale Row writes and share metadata

These tasks are part of the 3.10.0 completion criteria. Rows retain snapshot
reads, including after parent structural changes. Attached writes throw
`ConcurrentModificationException` after a tracked Matrix structural mutation
changes the parent's version. Direct Column mutations are an explicit gap below.
Cell value updates, column renames, and declared-type-only changes do not change
that version. `detach()` remains available on
stale Rows and retains their cached snapshot; detached writes affect only that
snapshot. Parent changes do not change a Row's equality, hashCode, or rendering.

Live reads are excluded: no demonstrated use case requires them, and changing
the existing APIs would break snapshot consumers. In particular, `orderBy`
sorts `rows()` snapshots and then `updateValues` overwrites the parent row by
row; live reads there could duplicate values already overwritten. Any future
live-read feature requires a separate proposal and explicit opt-in API, such
as `liveRow(int)`, rather than changing `rows()` or iteration.

7.1 [x] Introduce a new Matrix structural version field and capture it in each
attached Row. Compare the captured version to the parent's version in `Row.set`
before either parent or cached-content mutation. Direct, sublist, and list-iterator
assignments must use this same check. Do not check the version on reads or detach.
`invalidateIndex()` is not a structural modification counter and
cannot substitute for this field. Bump it only for Matrix operations that change
row/column positions or dimensions: sorting/reordering rows, adding/removing rows,
and adding/inserting/dropping/reordering columns. Replacing a column in the same
position with the same length is nonstructural; a replacement that changes length
is structural. Column renames and declared-type-only changes do not bump it:
Row assignments use cached positional indices and Matrix.putAt does not enforce
declared types, so those edits do not redirect the write. Cached Row names/types
remain snapshots; fetch a new Row to observe updated metadata. Audit each Matrix
mutator against this rule rather than treating all schema changes as structural.
Include the public
`Matrix.putAt(Number, Number, Object)` append branch (`rowIndex == column.size()`)
as structural: bump the version whenever it appends, retaining its existing
behavior. Size-preserving cell assignments do not bump the version. Preserve
internal snapshot-read-then-write paths, including `orderBy` and `updateValues`.

Scope decision (option b): Column remains freely mutable without an owner link.
Direct Column/list add/remove/sort and metadata edits bypass version tracking;
do not promise stale-write detection for them. State this gap in Row/Matrix
GroovyDoc, the cookbook, and release notes. Recommend Matrix structural methods
and fetching a fresh Row after direct Column changes. Do not present markIndexDirty
as a fix: it rebuilds indexes, not Row structural versions. Bounds checks still
reject missing targets but cannot detect an in-range reorder via a Column.

7.2 [x] Make `Row.set` validate its local index first, throwing
IndexOutOfBoundsException for an invalid local index. For attached Rows, next
check the structural version and throw ConcurrentModificationException when
stale; then check parent row/column bounds, throwing IndexOutOfBoundsException
for missing targets from untracked Column mutations. Reject a Row target equal
to the column size rather than allowing Matrix.putAt to append. Assign to the
parent before updating cached content so rejection leaves both unchanged.
Preserve the prior cached value return contract and detached Row assignments.
Direct/sublist/list-iterator paths must all delegate to these checks.

7.3 [x] Share one immutable snapshot of column names and one of declared types
across the Rows constructed by a single `Matrix.rows()` call, rather than copying
both for every Row. Add a package-scoped construction path and preserve copying
for callers supplying mutable metadata. Never share live parent metadata. Make
`Row.columnNames()` and `Row.types()` return unmodifiable lists, including for
individually constructed Rows. Add tests that set/add/remove/clear through these
accessors throw UnsupportedOperationException and leave all sibling metadata
unchanged. Document the read-only contract and verify MatrixBuilder.rowList
continues to accept these lists without modifying them.

7.4 [x] Add stale-write tests for each tracked structural mutation through direct,
sublist, and list-iterator assignments. Explicitly test removal of the last parent
row: assignments must never grow a single column. Test in-range stale positions
after removing an earlier row or sorting, which bounds checks alone cannot detect.
Verify rejected writes preserve parent data, every column length, and cached
Row/sublist values. Cover Matrix.putAt appends as tracked mutations. Separately
cover out-of-bounds targets after direct Column removal (IndexOutOfBoundsException),
