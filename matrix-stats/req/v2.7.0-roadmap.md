# Matrix Stats v2.7.0 Roadmap

## Scope

This roadmap covers the four items that remained deferred after the 2.6.0 correctness work
(`matrix-stats/req/v2.6.0-fixes.md`, "Deferred Work"). They were not pulled into 2.6.0 because they are new features or
redesigns rather than corrections, so a breaking-change window did not help them. All of them close gaps with R:

1. Durbin-Watson p-values (`lmtest::dwtest`).
2. A fast quantile-regression solver with multi-predictor and formula support (`quantreg::rq`).
3. A penalised-regression-spline GAM with automatic smoothing selection and mgcv's thin-plate default (`mgcv::gam`).
4. Loess `surface = "interpolate"`, which becomes the default as in R.

Each numbered section is intended to be implementable and reviewable as a separate pull request. A task is only complete
when its tests have passed and the exact test commands have been recorded in this file or the PR description. The same
reference-testing conventions as the 2.6.0 plan apply: every numerical test asserts against a value produced by R, with
the R expression and package version in a comment, and the producing scripts live under
`matrix-stats/src/test/resources/r-reference/`.

**Prerequisites from 2.6.0:** the QR least-squares kernel (2.6.0 section 16), design-matrix column order (section 27),
aliased coefficients (section 30) and loess parity with R's `direct` surface (section 31) must be complete; sections 1, 3
and 4 below build on them.

**Reference packages** (installed in the maintainer's R user library for reference generation only, never build
dependencies): R 4.6.1, lmtest 0.9.40, quantreg 6.1, mgcv 1.9.4 (recommended package), MASS (recommended package).

### Summary

| Section | Item | Current state | Reference |
|---------|------|---------------|-----------|
| 1 | Durbin-Watson p-values | `DurbinWatson.test(residuals)` returns only the statistic; the `alternative` overload is deprecated in 2.6.0 and ignored | `lmtest::dwtest(lm(mpg ~ wt, mtcars))`: DW = 1.251727, p = 0.0102001 |
| 2 | Quantile-regression solver and multi-predictor/formula support | Correct (matches `rq` to 1e-12 on mtcars) but a dense Bland's-rule simplex: 8 s at n = 1,000, 38 s at n = 2,000; one predictor only | `rq(y ~ x, method = "br")` at n = 20,000: 0.05 s; `rq(stack.loss ~ ., data = stackloss)` |
| 3 | Penalised-spline GAM (`tp` default, `cr` available), with an optimiser probe | `GamMethod` adds `λ·I` (fixed λ) to the smooth columns of a natural-cubic-spline basis; no smoothing selection, no effective degrees of freedom, standard errors ignore the penalty | `mgcv::gam(accel ~ s(times), data = mcycle, method = "REML")`: edf 8.62469 |
| 4 | Loess interpolated surface, the new default | Exact (`direct`) computation at every point, O(n·q) per fit | `loess(..., surface = "interpolate")` differs from `direct` by up to 0.0062 at n = 2,000 and is ~5× faster |

## 1. Durbin-Watson p-Values

**Files:**

- `matrix-stats/src/main/groovy/se/alipsa/matrix/stats/timeseries/DurbinWatson.groovy`

The null distribution of DW depends on the regression design matrix X: DW is a ratio of quadratic forms in the
residuals, and its exact distribution is that of `Σ λ_i z_i² / Σ z_i²`, where λ_i are the non-zero eigenvalues of
`M·A` (M = I − X(XᵀX)⁻¹Xᵀ, A the first-difference matrix `DᵀD`). lmtest uses Pan's (1968) algorithm for the exact
p-value when n < 100 (no condition on the number of regressors) and a normal approximation with the exact mean and
variance of DW otherwise.

1.1 [ ] Add failing reference tests (lmtest 0.9.40, `dwtest`), using `mtcars` from `matrix-datasets`:
- `lm(mpg ~ wt)`: DW = 1.251727; exact p `greater` 0.0102001, `two.sided` 0.0204003, `less` 0.989800 (R: 0.9897998546);
  normal-approximation p `greater` 0.0108561, `two.sided` 0.0217122, `less` 0.989144.
- `lm(mpg ~ wt + hp)`: DW = 1.362399; exact p `greater` 0.0206125, `two.sided` 0.0412251, `less` 0.979387;
  normal-approximation p `greater` 0.0206763, `two.sided` 0.0413527, `less` 0.979324.
- `lm(sales ~ year)` with year = 1..20 and sales = 5.2, 5.8, 6.9, 7.1, 7.8, 8.9, 9.2, 9.6, 10.9, 11.3, 11.6, 12.9, 13.4,
  13.8, 14.9, 15.5, 15.6, 16.9, 17.6, 18.4: DW = 2.555312, p (`greater`) = 0.850062.

1.2 [ ] Add an API that has access to the design: `DurbinWatson.test(List<? extends Number> response,
List<? extends List<? extends Number>> design, String alternative = 'greater', Boolean exact = null)` (design without
intercept column; an `intercept` flag, default true) and a convenience `DurbinWatson.test(ModelFrameResult frame,
String alternative = 'greater', Boolean exact = null)`. Fit the regression with the 2.6.0 QR kernel. `exact = null`
follows lmtest: `exact <- (n < 100)`, with no condition on the number of regressors. Add `pValue`, `alternative` and
`method` (`'exact (Pan)'` or `'normal approximation'`, always the method actually used after any fallback) to
`DurbinWatsonResult`. Keep the residuals-only `test(residuals)` method (statistic only) and remove the deprecated `test(residuals, alternative)` overload.

1.3 [ ] Compute the eigenvalues of `M·A` with EJML (symmetric eigen-decomposition of `Qᵀ A Q`, where Q spans the residual
space from the QR of X) and implement Pan's algorithm (port `lmtest`'s `pan` Fortran routine, called via
`.Fortran("pan", …)`, which follows Farebrother's AS 153 variant; credit both in GroovyDoc). Use the exact mean and variance of DW for the normal
approximation.

Eigenvalue filter: as lmtest, keep only the first n − k eigenvalues and drop those ≤ 1e-10 (`ev <- ev[ev > tol]`,
`tol = 1e-10`) before calling Pan. Without an intercept, a zero eigenvalue appears whenever the constant vector lies in
the residual space (e.g. centred predictors), and the `Qᵀ A Q` decomposition returns it too. Keeping it changes the
p-value. Reference (verified, lmtest 0.9.40): x = (1..8) − 4.5, y = 1.3, −0.8, 0.9, 2.1, −0.4, 1.7, −1.2, 0.6,
`dwtest(y ~ 0 + x)`: eigenvalues 3.84753, 3.41421, 2.76287, 2.00000, 1.22292, 0.585786, plus one near-zero value
whose size depends on the platform (−5.0e-16 on macOS with R 4.6.1, −1.18e-16 in a reviewer run). Assert only the six real eigenvalues, the
count after filtering (6) and the p-values, never the near-zero value. DW = 2.558729066,
p `greater` 0.649541878, `less` 0.350458122, `two.sided` 0.700916244. Pan with all 7 eigenvalues gives 0.807904798, so
this test fails without the filter.

Degenerate fits are a deliberate deviation from lmtest (maintainer decision 2026-10-12), handled the same way as the
n − k = 1 case in rule 2 below. Return the statistic as computed, with `pValue = null`, and log a warning. If the
residual sum of squares is exactly 0, the statistic is NaN. `method` is `'not computed (saturated design)'` or
`'not computed (perfect fit)'`. The GroovyDoc must say that the statistic means nothing in these cases. Do not call
Pan or the normal approximation. The cases are checked in this order, because a saturated design also has a
negligible RSS. Both run before rule 1, so n = 2 with k = 2 reports a saturated design, not lmtest's p = 1:
- n − k = 0 (saturated design). lmtest fails with "NA/NaN/Inf in foreign function call (arg 1)", e.g. n = 3,
  `y ~ a + b`.
- Perfect fit: compare norms, not sums of squares, with an explicit tolerance scaled by the size of y itself:
  `√RSS ≤ 100·n·ε·‖y‖`, where ‖y‖ = √(Σy²) and ε = 2.220446e-16 (machine epsilon). This is the smallest residual size
  double arithmetic can resolve, because rounding error in the residuals grows with ε·‖y‖. Do not scale by
  √TSS = √Σ(y − ȳ)²: when y has a large mean and little variation, rounding noise exceeds that tolerance, and an exact
  line goes to Pan. For example, y = 1e6 + 3x with x = 1..50 gives √RSS = 4.15e-9 against 100·n·ε·√TSS = 3.4e-10.
  lmtest then reports DW = 1.0794, p = 0.000142, i.e. "significant" autocorrelation from rounding alone. The ‖y‖
  tolerance is 7.85e-6. Large offsets are common (years, timestamps, prices). TSS = Σ(y − ȳ)² with an intercept, Σy²
  without, still matters in one case: a TSS of 0 (constant y with an intercept, y ≡ 0 without) always counts as a
  perfect fit, whatever RSS is. Do not apply a value-level tolerance such as 1e-12 directly to RSS/TSS: that would flag
  genuine fits with R² ≈ 1 − 1e-13. The GroovyDoc must say that data whose genuine noise is below about 100·n·ε·‖y‖ is
  treated as a perfect fit, because double precision cannot resolve noise that small. If the 2.6.0 §16.6
  `NumericTolerance` helper does not take an explicit tolerance, add an `isNegligible(value, scale, tol)` overload
  rather than duplicating the check (DRY). Examples, all checked in R:
  - y = 2 + 3x, x = 1..6: √RSS = 2.07e-15 against a tolerance of 4.41e-12. lmtest computes DW from that rounding
    noise and reports DW = 2.715571, p = 0.654063.
  - Exact lines with an offset, x = 1..6, R's √RSS against the ‖y‖ tolerance: y = 1e4 + 3x, 5.98e-13 vs 3.27e-9;
    y = 1e6 + 3x, 2.9e-10 vs 3.26e-7; y = 1e8 + 3x, 2.06e-8 vs 3.26e-5. All are flagged; with the √TSS tolerance
    (1.67e-12), the last two are not.
  - Constant y = 3 (n = 6) with `y ~ x`: TSS = 0 exactly, so this is a perfect fit. lmtest again uses the noise and
    reports DW = 1.7143, p = 0.1315.

Otherwise (the degenerate checks run first), evaluate in this order. The first matching rule wins. Log each warning with
`se.alipsa.matrix.core.util.Logger`.
1. n < 3: p = 1 ("not enough observations for computing a p value, set to 1"), as lmtest.
2. n − k = 1: a deliberate deviation from lmtest (maintainer decision 2026-10-12). DW then equals the single
   eigenvalue in exact arithmetic, so its null distribution is degenerate. lmtest returns p = 0 or 1 depending only on
   rounding, with no warning. Return the statistic with `pValue = null` and `method` `'not computed (n − k = 1)'` and
   log a warning, in both exact and approximate mode. Document it in the `DurbinWatson` GroovyDoc and in the release
   notes (task 5.2). Tests: `cars[1:3,]` `dist ~ speed` gives DW = 2.5 and `mtcars[1:4,]` `mpg ~ wt + hp` gives
   DW = 2.418919, both with a null p-value. lmtest gives p = 0 for both.
3. Exact mode: compute Pan's p-value. If it is NaN or outside [0, 1], warn ("exact p value cannot be computed (not in
   [0,1]), approximate p value will be used") and switch to the normal approximation; `method` then reports
   `'normal approximation'`.
4. Normal approximation with n < max(5, k) (k = number of columns of X including the intercept): p = 1 ("not enough
   observations for computing an approximate p value, set to 1"), as lmtest.

Tests:
- Saturated n = 3 `y ~ a + b`: `pValue` null, `method` `'not computed (saturated design)'`, no exception.
- Perfect fit y = 2 + 3x, x = 1..6: `pValue` null, `method` `'not computed (perfect fit)'`, no exception.
- Total of 0: y = 3 (n = 6) with `y ~ x`, and y ≡ 0 with `y ~ 0 + x`: both `'not computed (perfect fit)'` with a null
  p-value. The y ≡ 0 case is a 0/0 statistic and must not reach Pan.
- Large offset: y = 1e6 + 3x, x = 1..50: `pValue` null, `method` `'not computed (perfect fit)'` (lmtest: DW 1.0794,
  p 0.000142 from rounding noise).
- Near the boundary, a fit that must still get a p-value: x = 1..20, y = 2 + 3x + 2e-4·sin(x). R² = 1 − 6.79e-11,
  √RSS = 6.37e-4, against a tolerance of 7.49e-11. lmtest 0.9.40 gives DW = 0.856091206, p `greater` 0.000751720,
  `less` 0.999248280, `two.sided` 0.001503440.
- The no-intercept centred-x reference above.
- Add a test for each fallback rule. Rule 1: n = 2 → p = 1. Rule 4: `exact = false` with n − k ≥ 2 and n < max(5, k),
  e.g. n = 4, k = 2 → p = 1 (with n − k = 1, rule 2 fires first and returns null). Rule 3: the exact→approximate
  switch, exercised through a package-scope hook that injects an out-of-range exact p-value, asserting the approximate
  p-value and `method`. A hook is needed at this level because Pan's routine stays in [0, 1] on real data: an external
  search of every base-R time series and data-frame column pair with n < 100 found no case outside it. Even residuals
  built as the top eigenvector (`y = cos(4π(i − ½)/5)`, i = 1..5, `y ~ 1`) do not trigger the fallback in lmtest,
  because rounding moves DW off the eigenvalue (verified: p = 1 / 0, no warning).
- Also test `PanDistribution` directly, with no hook. Pan returns NaN when DW equals the largest eigenvalue exactly.
  Use the eigenvalues for n = 5 with an intercept-only design, `2 − 2cos(πj/5)` for j = 1..4 (3.61803398875,
  2.61803398875, 1.38196601125, 0.38196601125), and 15 iterations. Assert NaN at `dw = max(ev)` (the same double),
  1 at `max(ev) − 1e-12` and 0.5 at dw = 2. These are lmtest 0.9.40 values, from calling `.Fortran("pan", …)` the way
  `dwtest` does.

## 2. Fast Quantile Regression

**Files:**

- `matrix-stats/src/main/groovy/se/alipsa/matrix/stats/regression/QuantileRegression.groovy`

- `matrix-stats/src/main/groovy/se/alipsa/matrix/stats/regression/QuantileMethod.groovy` (new, optional task 2.5)
- `matrix-stats/src/main/groovy/se/alipsa/matrix/stats/solver/LinearProgramSolver.groovy` (unchanged API)
- Tests: `QuantileRegressionTest.groovy`, a slow-tagged performance test
- Downstream: `matrix-charts/src/main/groovy/se/alipsa/matrix/charm/render/stat/QuantileStat.groovy`

The current implementation formulates the problem as a dense LP with 2n + 4 variables and solves it with the general
simplex in `LinearProgramSolver`, which costs O(n³). Results are correct; only speed is the problem.

2.1 [ ] Add reference tests (quantreg 6.1, `rq`, default `method = "br"`), which the current implementation already
passes and must keep passing:
- `rq(mpg ~ wt, data = mtcars)`, τ = 0.25: (36.913333333, −6.083333333); τ = 0.5: (34.232236842, −4.539473684);
  τ = 0.75: (38.137151624, −5.113781642).
- `set.seed(11); n <- 20000; x <- runif(n, 0, 10); y <- 2 + 3*x + rt(n, 3)` (stored in `r-reference/`), τ = 0.5:
  (1.988545701, 3.003617158).

2.2 [ ] Implement the Barrodale–Roberts (1974) modified simplex specialised to L1/quantile regression, as used by
`rq(method = "br")` (Koenker & d'Orey 1987, AS 229). It works on an n × p tableau and exploits the problem structure,
so typical cost is far below the general simplex. Port from the published algorithm and credit it in GroovyDoc.
Keep `LinearProgramSolver` as the general-purpose LP.

2.3 [ ] Optionally add the Frisch–Newton interior-point method (`rq(method = "fn")`, Portnoy & Koenker 1997) for very
large n, selected automatically above a threshold (quantreg suggests n > 5,000) or via a `method` parameter. Record the
decision here.

2.4 [ ] Performance target (slow-tagged test, `-PrunSlowTests=true`): n = 20,000 single predictor in under 2 s; n = 2,000
(currently 38 s) in under 0.2 s.

2.5 [ ] Multiple predictors (in scope for 2.7.0, maintainer decision 2026-10-12): `QuantileRegression` currently
supports only `y ~ x` (intercept and slope).
- Generalise the BR solver to an n × p design (the algorithm is defined for general p).
- Add a multi-predictor API as a static factory, not a constructor:
  `static QuantileRegression fit(List<? extends List<? extends Number>> predictors, List<? extends Number> y, Number tau, boolean intercept = true)`, exposing `coefficients` (and `List<BigDecimal>` accessors) and
  `predict(List<? extends Number> x)`. Keep the existing single-predictor constructors, `slope` and `intercept` as a
  convenience over the general fit, so matrix-charts `QuantileStat` is unaffected.
- Do not add a `(List, List, Number[, boolean])` constructor: a default `intercept` makes Groovy generate a 3-argument
  `(List, List, Number)` constructor with the same erasure as the existing single-predictor constructor
  (`QuantileRegression.groovy:196`). Groovy 5.1.3 drops the generated one silently, so `new QuantileRegression([[1], [2]],
  [3, 4], 0.5)` runs the single-predictor code (verified with a probe class). Add a test that `QuantileRegression.fit(predictors,
  y, 0.5)` (3 arguments) runs the multi-predictor fit and that it matches `rq(stack.loss ~ ., data = stackloss)`.
- Register an `'rq'` fit method in `FitRegistry` with a `QuantileOptions(tau = 0.5)` options class and add `FitDsl.rq(...)`,
  so formulas work (factors, interactions and transforms via the existing `ModelFrame`).
- Reference: `rq(stack.loss ~ ., tau = 0.5, data = stackloss)` coefficients (−39.68985507246, 0.83188405797,
  0.57391304348, −0.06086956522); add τ = 0.25 and 0.75 for the same model, and a formula test with a factor
  (`rq(mpg ~ wt + factor(cyl), tau = 0.5, data = mtcars)`), generated by `r-reference/regression.R`.
- Quantile-regression solutions can be non-unique; the BR algorithm returns the same vertex as quantreg for these
  references. Document the non-uniqueness.
- Rank-deficient designs throw a descriptive exception (no aliasing support for `rq`, as quantreg).

2.6 [ ] Confirm matrix-charts `QuantileStat` output is unchanged.

## 3. Penalised Regression Spline GAM

**Files:**

- `matrix-stats/src/main/groovy/se/alipsa/matrix/stats/regression/GamMethod.groovy`, `GamOptions.groovy`, `FitResult.groovy`
- `matrix-stats/src/main/groovy/se/alipsa/matrix/stats/formula/SplineBasisExpander.groovy` (or a new `SmoothBasis`
  family) and the formula parsing of `s(...)` arguments
- `matrix-stats/src/test/groovy/regression/GamMethodTest.groovy`, `formula/SplineBasisTest.groovy`
- `matrix-stats/src/test/resources/r-reference/regression.R`

Today `GamMethod` builds a natural cubic spline basis with equally spaced knots and adds a fixed ridge penalty `λ·I` to
the smooth columns. It has no smoothing-parameter selection, reports no effective degrees of freedom, and its standard
errors ignore the penalty. The goal is an `mgcv`-compatible penalised regression spline for Gaussian responses with
smoothing parameters chosen by REML (default) or GCV, supporting two univariate bases: the cubic regression spline
(`bs = "cr"`, task 3.2) and mgcv's default thin-plate regression spline (`bs = "tp"`, task 3.8), which is the default for
`s(x)` so that `s(x)` means the same in matrix-stats as in R (maintainer decision 2026-10-12).

3.1 [ ] Add reference tests on `MASS::mcycle` (add the dataset to `matrix-datasets` or store it under `r-reference/`):
- `gam(accel ~ s(times, bs = "cr", k = 10), data = mcycle, method = "REML")`: edf 8.44428, fitted values at rows
  1, 50, 100, 133: −0.27050840, −79.50930920, 27.00595251, 0.76096235. This is the primary target, because `bs = "cr"`
  (cubic regression spline with knots placed through the unique covariate values) is deterministic and portable.
- The default thin-plate basis is the parity target of task 3.8 (references there).
Tolerance: 1e-4 relative on fitted values and edf (smoothing-parameter optimisation is iterative).

3.2 [ ] Basis and penalty: implement mgcv's `cr` basis (Wood 2017, §5.3.1): k knots spread evenly through the sorted
**unique** covariate values (mgcv `place.knots`, equivalent to `quantile(unique(x), seq(0, 1, length = k))`), not
quantiles of the covariate itself. On mcycle (133 rows, 94 unique times) the two differ: mgcv's knots are 2.4, 9.0667,
14.7333, 17.8, 22.4, 26.3333, 31.2, 36.8, 44.2667, 57.6, whereas `quantile(times)` gives 2.4, 10.4667, 15.4, … and
would fail the 3.1 and P1 parity tests. Add a test asserting these knots; the cubic-spline interpolation basis parameterised by function values at the knots, and the penalty matrix
`S = DᵀB⁻¹D` integrating the squared second derivative. Apply mgcv's sum-to-zero identifiability constraint
(absorbed by QR of the constraint vector), giving k − 1 columns per smooth. Support `s(x, k = …, bs = …)` arguments in
the formula parser with `bs` ∈ {`"tp"`, `"cr"`} and default `"tp"` (task 3.8) and `k` default 10, as mgcv; reject other
`bs` values with a clear message. Until task 3.8 lands, tests use `bs = "cr"` explicitly; do not release with `cr` as the
`s(x)` default.

3.3 [ ] Fitting: for fixed smoothing parameters λ_j, solve the penalised least-squares problem via QR of the augmented
matrix `[X; √S_λ]` (stable, no normal equations). Compute the influence matrix trace for effective degrees of freedom
(total and per smooth). Per-smooth edf excludes the parametric terms (the intercept); the total edf includes them
(mgcv `sum(g$edf)`). All edf values quoted in this roadmap are per-smooth: e.g. `cr` k = 10 on mcycle has per-smooth edf
8.444279 and total edf 9.444279. The scale estimate uses the total: `σ̂² = RSS/(n − total edf)`; on that model
RSS/(133 − 9.444279) = 505.8498673 = mgcv `g$sig2` (assert it to 1e-4 relative), and the Bayesian covariance `V_β = (XᵀX + S_λ)⁻¹σ̂²`
for standard errors.

3.4 [ ] Smoothing-selection criteria: implement the REML (default, as `method = "REML"`) and GCV (`method = "GCV.Cp"`)
criteria as functions of ρ = log λ (one entry per smooth), evaluated stably through the QR of 3.3, following Wood
(2011). These criterion functions are shared by both optimisers in the probe (3.4a–3.4e), so the probe compares
optimisers only.

3.4a [ ] **Probe: simple optimiser vs full mgcv-style Newton.** Before committing to an optimiser, prototype both on
the same criterion code:
- **Simple:** Brent (`BrentSolver`-style golden-section/parabolic) on ρ for a single smooth; `NelderMeadOptimizer` on ρ
  for several smooths. Box ρ to [−20, 30] (λ ≈ 2e-9 … 1e13) and stop on a relative criterion change below 1e-10.
- **Full:** Wood's (2011) outer Newton iteration on ρ with exact first and second derivatives of the criterion, step
  halving, and mgcv's handling of indefinite Hessians and of smoothing parameters drifting to ±∞ (terms that become
  linear or unpenalised).

  the global seed. Reproducing it would require porting R's Mersenne-Twister `set.seed` scrambling and R ≥ 3.6
  rejection sampling in `sample()`; that is out of scope for 2.7.0. Use a deterministic evenly spaced subset of the
  order statistics instead and document that results then differ slightly from mgcv. Measured with mgcv 1.9.4 on `set.seed(9); x <- runif(3000); y <- sin(6x) + rnorm(3000, sd = 0.2)`:

- **Basis:** for d = 1 and mgcv's default order m = 2, the radial function is `η(r) = r³/12`. Form `E_ij = η(|x_i − x_j|)` over
  the knots and the null-space matrix `T = [1, x]`. Eigen-decompose the symmetric E (EJML; the full decomposition is
  affordable up to 2,000 knots; Lanczos is a later optimisation) and keep the k eigenvectors with the largest absolute
  eigenvalues, `U_k`, `D_k`. Absorb the constraint `Tᵀ U_k δ = 0` by QR, giving k − 2 penalised coefficients plus the

- **Identifiability:** apply the same sum-to-zero constraint as 3.2, so a default smooth has k − 1 = 9 coefficients and a
  1-dimensional unpenalised null space (mgcv reports `bs.dim` 10, `null.space.dim` 1, `df` 9).
- **Prediction:** evaluate the basis at new x from `η(|x − knot_j|)` and `[1, x]` through the stored `U_k` and constraint
  transforms, so `predict` works away from the data.
- **Sign and ordering:** eigenvector signs and the order of equal eigenvalues are arbitrary; fits are invariant to them, so
  tests compare fitted values, predictions, edf and scores, never raw coefficients.

## 4. Loess Interpolated Surface

**Files:**

- `matrix-stats/src/main/groovy/se/alipsa/matrix/stats/regression/LoessMethod.groovy`, `LoessOptions.groovy`
- `matrix-stats/src/test/groovy/regression/LoessMethodTest.groovy`

R's default `loess(surface = "interpolate")` fits the local regression only at the vertices of a kd-tree and
interpolates between them with cubic blending (Cleveland & Grosse 1991). It is faster and is what R, and therefore
ggplot2's `geom_smooth(method = "loess")`, report by default. matrix-stats computes the exact (`direct`) surface, which
2.6.0 section 31 aligns with R. For small n the two agree exactly; for larger n they differ slightly.

4.1 [ ] Add reference tests: `set.seed(3); n <- 2000; x <- sort(runif(n, 0, 10)); y <- sin(x) + rnorm(n, sd = 0.3)`
(stored in `r-reference/`), `loess(y ~ x, span = 0.3, degree = 2)`: prediction at x = 5.0 is −0.94456083 with the
interpolated surface and −0.94569100 with `surface = "direct"`; the fitted values of the two surfaces differ by at most
0.00621. Assert the full fitted vector of each surface against R (relative 1e-6).

4.2 [ ] Add `LoessOptions.surface` (`'interpolate'` or `'direct'`) and `cell` (default 0.2, as R). Implement the
one-dimensional case of R's `lowesb`/`lowese`: build the kd-tree cells over x (cell size `floor(n·span·cell)`), compute
the local fit value and slope at each vertex, and evaluate by cubic Hermite interpolation between vertices. Multi-predictor
loess remains out of scope (matrix-stats loess is univariate).

4.3 [x] **Decision (maintainer, 2026-10-12):** the default surface becomes `'interpolate'`, matching R's `loess()`
default and therefore ggplot2's `geom_smooth(method = "loess")`; `'direct'` stays available for exact local fits. This
is a behaviour change from 2.6.0 (which computes the direct surface): small samples are unaffected (the surfaces coincide,
as in the 2.6.0 section 31 reference), larger samples change slightly. Add a release note and a test that the default
fit equals the `'interpolate'` fit. (matrix-charts `SmoothBuilder` accepts `method('loess')`, but `SmoothStat` does not
call matrix-stats loess today, so no chart output changes.)
