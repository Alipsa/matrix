# Matrix Stats v2.5.3 Correctness Fix Plan

## Scope

This plan covers six findings from the matrix-stats v2.5.3 source review plus direct-KPSS validation gaps identified during plan review: destructive K-means initialization, Kendall tau overflow, inconsistent `UnitRoot` modes, incorrect constant-target R², inconsistent lag-parameter semantics, unvalidated formula-environment alignment, and opaque KPSS failures for non-finite input, degenerate detrended residuals, or non-finite intermediate results. The findings are organized into seven implementation sections plus final verification; lag semantics are split between the aggregate `UnitRoot` API and the standalone KPSS API, while the KPSS validation follow-ups are handled with the standalone lag work. Each implementation section is intended to be independently reviewable, although the time-series sections may be combined in one pull request because they touch related APIs and tests.

A task is only complete when its tests have passed and the exact test commands have been recorded in this file or the PR description.

## Summary of Findings

- `KMeansPlusPlus` aliases and overwrites the caller's point array when basic random initialization is selected with `pp(false)`.
- `Correlation.corKendall()` multiplies non-tied pair counts as `long` values before assigning the result to `BigDecimal`, causing overflow for sufficiently large samples.
- `UnitRoot.test()` accepts and documents `type = 'none'`, but its ADF-GLS component rejects that mode.
- `Accuracy.r2()` returns `1` for every prediction when the actual values are constant, including completely wrong predictions.
- `UnitRoot` does not perform the automatic lag selection documented for `lags = 0`, while `Kpss` treats explicit zero as absent, silently clamps caller-supplied lag counts, and can turn non-finite statistics caused by invalid input, degenerate residuals, or floating-point overflow into an opaque `NumberFormatException`.
- `ModelFrame` does not validate that referenced environment vectors are aligned with the source matrix row count.

- Default `UnitRoot.test(data)` and `UnitRoot.test(data, type)` calls now use bounded MAIC-selected lags instead of literal lag zero; statistics and conclusions may therefore change.
- `UnitRoot.test(..., null)` now has the same automatic-selection meaning as lag zero.
- Explicit `Kpss.test(..., 0)` now uses zero autocovariance lags instead of being replaced by the automatic rule and clamped to at least one; its statistic may therefore change.
- Explicit KPSS lags in the supported range `0 <= lags < n`, including values above `n.intdiv(3)`, are now honored instead of being clamped to the old one-to-`n.intdiv(3)` range; both the statistic and reported lag count may change.
- Negative KPSS lags and values where `lags >= n` now fail with `IllegalArgumentException` instead of being silently clamped and returning a result.
- Direct `Kpss.test()` calls containing `NaN` or positive or negative infinity now fail during input validation with `IllegalArgumentException('Data contains non-finite values')` instead of later leaking a numeric conversion exception.
- Direct `Kpss.test()` calls whose deterministic specification leaves no residual variation, including constant level series and perfectly linear trend series, now fail with a descriptive `IllegalArgumentException` instead of an opaque `NumberFormatException` caused by conversion of a `NaN` statistic.
- KPSS calculations that produce a non-finite long-run variance now fail with `IllegalArgumentException('KPSS calculation produced a non-finite long-run variance')`; calculations that reach a non-finite final statistic instead fail with `IllegalArgumentException('KPSS calculation produced a non-finite statistic')`. Both routes now stop before `BigDecimal` conversion rather than leaking `NumberFormatException`.
- The aggregate `UnitRoot` API now rejects `type = 'none'` at its boundary; standalone `Df` and `Adf` continue supporting it.
- Seeded `KMeansPlusPlus.Builder(...).pp(false)` calls now cluster the original observations instead of observations corrupted by basic sampling, so their centroids, assignments, and WCSS may change. The higher-level `KMeans` wrapper remains unaffected because it uses `pp(true)`.
- Returned K-means assignment rows are now snapshots rather than aliases of caller input or model-internal point rows for both `pp(true)` and `pp(false)`. Mutating `assignment[i].point` therefore no longer mutates either source.
- `KMeansPlusPlus.getCentroids()` now returns a deep copy. Mutating a returned centroid array no longer changes the fitted model, and repeated getter calls no longer return the same array identities.
- `Accuracy.r2()` now returns `0` rather than `1` for constant actual values paired with imperfect predictions; perfect constant predictions continue returning `1`.
- Variables nested in arithmetic, grouped, or unary expressions, such as `I(a + b)` and `I(-x)`, now participate in NA handling and subset filtering. Under `NaAction.OMIT`, rows with nulls in those matrix columns are omitted instead of failing later during expression evaluation; `NaAction.FAIL` continues to reject them through the normal NA validation path.
- Unknown variables nested in arithmetic, grouped, or unary expressions are now rejected during formula validation with the standard `Unknown variable(s) in formula` diagnostic instead of failing later during expression evaluation.
