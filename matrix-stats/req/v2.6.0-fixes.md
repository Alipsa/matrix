# Matrix Stats v2.6.0 Correctness Fix Plan

## Scope

This plan addresses the findings from the matrix-stats source review performed on 2026-10-12 against commit `33f6a775`
(matrix-stats `2.5.4-SNAPSHOT`). Every finding below was reproduced by running the built module jar against R 4.6.1
(base R and the CRAN reference packages listed under task 1.1). The full module suite (1,068 tests) passed at the time
of review, so none of these defects is currently covered by a test.

**Version:** the work is released as the next minor version, **2.6.0** (maintainer decision, 2026-10-12), because several
fixes change default behaviour and section 18 changes a public method signature. `matrix-stats/build.gradle` and
`matrix-bom/bom.xml` (`matrixStatsVersion`) have been bumped to `2.6.0-SNAPSHOT`.

The findings are grouped into implementation sections 2–26 plus shared test infrastructure (1). Sections 27–31 are
former Deferred Work items brought into scope by the 2.6.0 minor version, and section 32 is final verification. Sections are ordered so that foundations come first: the distribution functions (section 2) are used
by almost every hypothesis test, and the least-squares consolidation (section 16) is used by the regression and
time-series sections that follow it. Each section is intended to be independently reviewable; sections 3–8 (normality)
and 9–11 (contingency) may each be combined into one pull request.

A task is only complete when its tests have passed and the exact test commands have been recorded in this file or the
PR description. Line numbers refer to commit `33f6a775` and will drift as work progresses.

## Reference-Testing Conventions

- Every correctness fix must add at least one test that asserts against an externally produced reference value, with
  the producing R expression in a comment next to the expected value, e.g.
  `// R 4.6.1: shapiro.test(iris$Sepal.Length) -> W = 0.976090, p = 0.0101812`.
- Prefer datasets available in both R and `matrix-datasets` (iris, mtcars, …) or small literal vectors, so the reference
  is reproducible without generated data files.
- Reference packages installed in the maintainer's R user library (reference generation only, never build
  dependencies): nortest 1.0.4, fBasics 4052.98, urca 1.3.4, Exact 3.3, moments 0.14.1. Cite the package and version in
  the test comment, e.g. `// nortest 1.0.4: lillie.test(iris$Sepal.Length) -> D = 0.088654, p = 0.00578839`. Use a
  documented direct port only when no package implements the reference.
- Use tolerances that reflect the algorithm, not convenience: 1e-6 relative for closed-form statistics, 1e-4 for
  approximations that R also computes approximately. When R solves for a root with a loose tolerance (e.g. `uniroot`'s default in
  `fisher.test`), assert against the precise root of the same equation and cite the R snippet that computes it (see 28.1).

3.1 [x] Add failing reference tests (Appendix A): classic n=11 data (W=0.788815, p=0.00670381), iris `Sepal.Length`
(W=0.976090, p=0.0101812), mtcars `mpg` (W=0.947565, p=0.122881), n=3 `(1,2,4)` (W=0.964286, p=0.636887),
n=5 `(2.1,3.5,1.2,8.9,4.4)` (W=0.897213, p=0.394673). Also assert `0 < W ≤ 1` for a 300-observation sample.

3.2 [x] Replace `calculateCoefficients`, `calculateW` and `calculatePValue` with a port of R's `swilk.c`:
- coefficients: `m_i = Φ⁻¹((i − 0.375)/(n + 0.25))` (lower quantile, so m₁ < 0, as in `swilk.c`),
  `a₁ = poly(c1, 1/√n) − m₁/√Σm²` and, for n > 5, `a₂ = poly(c2, 1/√n) − m₂/√Σm²`, remaining `a_i = −m_i / fac` with
  `fac = √((Σm² − 2m₁²) / (1 − 2a₁²))` for n ≤ 5 and `fac = √((Σm² − 2m₁² − 2m₂²) / (1 − 2a₁² − 2a₂²))` for n > 5
  (Σm² over all n); n = 3 uses `a₁ = √0.5`. Check the intermediate values for the classic n = 11 data: a₁ = 0.5600253,
  a₂ = 0.3314987 (1e-6). These match the published Shapiro–Wilk table (0.5601, 0.3315). Flipping the sign of the
  polynomial term gives a₁ = 0.5073 and W = 0.7510 instead of R's 0.7888147;
- statistic: `W = (Σ a_i (x_(n+1−i) − x_(i)))² / Σ(x − x̄)²`;
- p-value: n = 3 exact `6/π·(asin(√W) − asin(√0.75))`; 4 ≤ n ≤ 11 uses `γ = −2.273 + 0.459n`; if `ln(1 − W) ≥ γ`,
  return p = 1e-99 (R's guard, otherwise the next step takes the log of a non-positive number). Otherwise use
  `y = −ln(γ − ln(1 − W))` with μ, σ from polynomials c3/c4 in n. n ≥ 12 uses `y = ln(1 − W)` with c5/c6 in `ln n`.
  `p = 1 − Φ((y − μ)/σ)` (upper tail). The guard can only trigger for n = 4 (γ > 0 for n ≥ 5), and there it needs
  W ≤ 0.354, below the smallest attainable n = 4 W (0.63). Keep it for parity, but it cannot be covered by a test.
Keep the polynomial helper private and document the constants with their AS R94 names.
