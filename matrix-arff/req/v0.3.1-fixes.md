# matrix-arff v0.3.1 Review Fixes Implementation Plan

## Scope

This plan fixes the bugs and issues found in the 2026-10-15 review of `matrix-arff` (module version
`0.3.1-SNAPSHOT`). Each numbered section is sized as one reviewable commit (or a small PR) and can be implemented
independently unless a dependency is stated. Sections are ordered by severity.

A task is only complete when its tests have passed and the exact command used has been recorded next to the task
(or in the PR description). Red-phase tasks ("expected: FAIL") are ticked when exactly that failure was observed.

Revision 2026-10-15 (plan review): added the PrintWriter error-swallowing fix and the encodability pre-check (§2), DATE
and out-of-`int`-range INTEGER handling and parseable numeric strings (§5), the quote/`{` keyword boundary (§4),
Boolean explicit nominal (§10), and Path-based delegation for the File overloads (§12). Also fixed the inaccuracies
the review found.

Revision 2026-10-16 (second plan review): parseable date strings stay accepted in DATE columns (§5); the
encodability check now targets what is actually emitted, including formatted dates and nested relational values (§7.4);
the Weka tokenizer check moved to §0.4 because §4 depends on it; a `PrintWriter` already in an error state is rejected
on entry (§2.6); fixed the §4.8 note, §9.2 sparse/relational threading, the §11.2 static-compilation issue and the
§12.3 parent-null case.

Revision 2026-10-16 (third plan review): dropped the per-column cache of formatted WEKA-mode dates, because the shared
nested `ArffAttributeInfo` would mix rows from different nested matrices (§7.4); DATE strings must be consumed fully in
every mode (§5.2); `ensureParentDirectories` is `@PackageScope` (§12.3); the `dateFormatsByColumn` guard also sets the
DATE type (§5.1); documented the flush side effect of `checkError()` (§2.6); the §9.3 test uses an escaped `\n`.

Revision 2026-10-16 (fourth plan review): corrected the SPI argument order (§6.1); made numeric strings
ASCII-only and explicitly rejected missing-marker/blank/padded strings (§5); separated stream encoding validation
from schema resolution, including every nested declaration (§2, §7.4); added post-charset performance measurements
(§7.4); threaded source locations into nominal declaration parsing (§8.4).

Revision 2026-10-16 (fifth plan review): explicitly remove obsolete nominal-parser helpers (§8.4); collect the
UTF-8 stream baseline before §5 and measure ISO-8859-1 only after §7 (§5.4, §7.4); accept non-finite INTEGER cells
before decimal parsing (§5.2); specify row-free encoding diagnostics and their test assertions (§7.4).

### Reproducible performance fixtures (used by §5.4, §7.4 and §11)

Generate these with a throwaway Groovy script in the scratchpad (not committed). Run each measurement once to warm up,
then take the median of 5 runs:
- **Mixed fixture, 200 000 rows:** header `@attribute a numeric`, `@attribute b numeric`, `@attribute c string`,
  `@attribute d {x,y}`, data row `i` = `"$i,${i * 0.5},'str $i',x"`. Measure `MatrixArffReader.readString(text)` and
  `MatrixArffWriter.writeString(matrix)` on the Matrix read from it.
- **High-cardinality fixture, 500 000 rows:** a single `String` column `c` with values `"v$i"`, built with
  `Matrix.builder('m').data(c: values).types(String).build()`. Measure `MatrixArffWriter.writeString(matrix)`.

Reference numbers from the review machine: mixed read ≈ 260 ms, mixed write ≈ 650 ms, high-cardinality write ≈ 840 ms.

## 2. Writer Must Not Truncate the Target on Validation Failure (finding 2)

**Files:** `src/main/groovy/se/alipsa/matrix/arff/MatrixArffWriter.groovy`,
`src/test/groovy/test/alipsa/matrix/arff/MatrixArffTest.groovy`

Approach: split the writer into a pure **schema resolution** step and a **printing** step. Resolve the schema
before the `FileOutputStream` is opened. Schema resolution includes every data-dependent validation added in §5. The separate encodability check added
in §7.4 runs on the resolved schema before stream-backed output is opened or written. A temp file plus atomic move was considered and rejected because it changes
behaviour for symlinked targets and file permissions.

Known limit, documented in the README: once printing has started, only a genuine I/O error (for example, a full
disk) can still fail, and that leaves a partial file. Every validation and encoding failure happens before the target
is opened. Such I/O errors must reach the caller, though. Today they don't: the writer wraps output in a `PrintWriter`,
which swallows `IOException` (an unmappable character with a `REPORT` encoder gave `checkError()==true` and silently
dropped text). §2.6 fixes this.

2.1 [ ] Red: add `failedWriteLeavesExistingFileUntouched()` with a `@TempDir`. Write a known ARFF file, then call
`MatrixArffWriter.write(m, file, options)` for each of:
(a) `nominalColumns(['c'])` on an `Integer` column (no mappings),
(b) `dateFormat('yyyy-qq')` on a `Date` column,
(c) `attributeTypesByColumn([r: RELATIONAL])` where the column holds a non-`Matrix` value.
Assert `IllegalArgumentException` and that the file content is byte-identical to the original.
Expected: FAIL (file length 0).

2.2 [ ] Introduce a private immutable `WriteSchema` holder in `MatrixArffWriter` (relation name, attribute column
names, column indexes, `List<ArffAttributeInfo>`, weight column name/index) and a
`private static WriteSchema resolveSchema(Matrix matrix, ArffWriteOptions options)` that contains
`validateWriteOptions` plus the body of `writeMatrix` lines 125–131.

2.3 [ ] Change `writeMatrix(Matrix, PrintWriter, ArffWriteOptions)` into `printMatrix(Matrix, WriteSchema, Writer)`
that only prints. `write(Matrix, Writer, ArffWriteOptions)` calls `resolveSchema` then `printMatrix`.

2.4 [ ] Add a private `write(Matrix, Writer, WriteSchema)` path and make `write(Matrix, File, ArffWriteOptions)` call
`resolveSchema` **before** `ensureFileOutput` and `new FileOutputStream`, then print with the resolved schema (no second
resolution). Keep the existing comment at line 62 accurate.

2.5 [ ] Regression guard (passes today, because `writeMatrix` already resolves before printing): add a test
asserting the `ByteArrayOutputStream` is empty after `write(Matrix, OutputStream, options)` fails validation, so the
refactor in 2.2–2.4 cannot break it.

2.6 [ ] Stop swallowing write errors. Red: `writeErrorsReachTheCaller()` passes a `Writer` whose `write` throws
`IOException('disk full')` to `write(Matrix, Writer, options)` and asserts an `IOException` (or one in the cause chain)
with that message. Expected: FAIL, because `PrintWriter` hides it today. Fix: `printMatrix` writes to the caller's
`Writer` directly (`writer.write(line); writer.write(LINE_SEPARATOR)` with
`LINE_SEPARATOR = System.lineSeparator()`, so output is byte-identical to today's `println`). Do not wrap it in a
`PrintWriter`. When the caller passes a `PrintWriter` themselves, the error flag is sticky, so check it twice:
- on entry, before anything is written: if `checkError()` is already true, throw
  `IllegalArgumentException('The supplied PrintWriter is already in an error state from an earlier write')`, so an
  earlier failure is not blamed on this write;
- after `flush()`: if `checkError()` is now true, throw
  `IOException('Failed to write ARFF output (PrintWriter reported an error)')`.

Add `printWriterAlreadyInErrorIsRejected()` for the entry check. `PrintWriter.checkError()` flushes the stream before
reporting, so the entry check also flushes the caller's writer. This is harmless, but state it in the GroovyDoc of
`write(Matrix, Writer, …)`: "If `writer` is a `PrintWriter`, it is flushed and its error state checked before and after
writing."

2.7 [ ] Release notes: "Fix a failed write (invalid options or column contents) truncating an existing target file";
"Fix I/O errors during writing being silently swallowed, producing truncated output" **(changed)**.

5.2 [ ] Add `private static void validateCells(Matrix matrix, String colName, ArffAttributeInfo info)` called from
`resolveSchema` for every top-level attribute and from `createRelationalInfo` for every nested part:
- NOMINAL: every non-null cell's `toString()` must be in `info.nominalValues` (use a `Set` built once per column).
- NUMERIC/REAL: a non-null cell must be a `Number`, or a `CharSequence` whose characters are all ASCII
  (`<= 0x7F`) and whose unchanged `toString()` is parsed by `new BigDecimal(s)`. Check ASCII before parsing:
  `BigDecimal` accepts Unicode decimal digits, but those must never reach numeric output. Accepted strings keep being
  written as given. Reject empty/blank strings, `'?'`, and leading/trailing whitespace; do not trim or normalize them.
  Use `null` for a missing numeric value. Anything else (e.g. `'1,5'`) is rejected with a message suggesting `STRING`
  or converting the column first.
- INTEGER: a non-null cell must be a `Number` or a `CharSequence` satisfying the same ASCII and unchanged-string
  parsing rules as NUMERIC/REAL, with no fractional part. First, if `isNonFinite(value)` is true, accept the cell
  immediately (`NaN` and infinite `Double`/`Float` are written as `?`); never pass these values to `BigDecimal`.
  Next, skip the scale check for `Integer`, `Long`, `Short`, `Byte` and `BigInteger` cells (no allocation per cell).
  Only then, for remaining values, check
  `new BigDecimal(value.toString()).stripTrailingZeros().scale() <= 0`. Values outside the `int` range are **allowed** (valid ARFF, see the 5.1 guard); the README
  says that reading them back needs `integerType(Long)` or `integerType(BigDecimal)`.
- DATE: a non-null cell must be a `Date` (including `java.sql.Date`/`Timestamp`), `LocalDate`, `LocalDateTime` or
  `Instant`, which are the types `formatDate` can format. A `CharSequence` cell is also accepted when the column's own
  formatter parses it **completely**, in every mode. `ArffDateFormats.parse` skips the full-consumption check in WEKA
  mode (line 52), so use a new `@PackageScope static boolean parsesCompletely(SimpleDateFormat format, String value)`
  in `ArffDateFormats` instead. The caller passes `value.toString()`, so `GString` and `StringBuilder` cells match the
  `String` parameter under static compilation. The helper body:
  `ParsePosition pos = new ParsePosition(0); format.parse(value, pos) != null && pos.index == value.length()`.
  An accepted string is written unchanged, which preserves today's valid output. Anything else (e.g. `'abc'`, or
  `'… junk'` in WEKA mode) is rejected. This guarantees that the default reader will not reject the text for trailing
  content. A WEKA-mode string with locale-specific names (e.g. `März` for `MMMM`) still needs `dateMode(WEKA)` to read
  back, which is the same as for date values written in WEKA mode.

**What is checked** is the text that will actually be emitted, never a `toString()` that is not written:
- the top-level relation name (once);
- every emitted `@ATTRIBUTE` name and complete `typeDeclaration` (once per schema attribute), recursing through
  `info.relationalColumnNames` and `info.relationalInfos`. This includes nominal declarations and DATE pattern literals
  in every mode, even when all cells are null or a nested matrix has no rows. Also check names emitted in `@END`.
  Traverse the resolved declarations independently of the cell scan;
- STRING cells: `value.toString()`, which is exactly what `formatValue` escapes and writes. NOMINAL cells are not
  scanned: §5.2 guarantees each non-null cell is a declared value, and the declarations are checked above.
  `ArffEscapes` only adds ASCII characters;
- DATE cells holding a `CharSequence` (accepted by §5.2): the string itself;
- DATE cells holding a date value:
  - `ArffDateMode.UTC`: no per-cell check and no separate pattern scan. The pattern's literal text is covered by
    the declaration check above; the formatter's `Locale.ROOT` month, day, era and AM/PM names and `UTC` zone name
    are ASCII. Pin this formatter-text assumption with `rootLocaleDateTextIsAscii()`: format one date per month
    and weekday with a pattern that uses every `SimpleDateFormat` letter, in `Locale.ROOT`/UTC, and assert that every
    char is `<= 0x7F`.
  - `ArffDateMode.WEKA`: the JVM locale can produce non-ASCII names (e.g. `MMMM` → `März`), so each cell is formatted
    and the formatted text is checked. The text is **not** cached; `formatDate` formats it again when printing. A cache
    on `ArffAttributeInfo` would be wrong: `createRelationalInfo` (lines 246–250) shares one `nestedInfos` list across
    every nested Matrix of a column, so a per-row cache would mix rows from different nested matrices, and it would put
    per-row data into a schema object. Formatting twice costs extra only when the charset is not UTF-8 and the mode is
    WEKA, which is rare.
- RELATIONAL cells: `Matrix.toString()` is only a summary (`'n: 1 obs * 1 variables '`) and is **not** what gets
  written. Recurse into each nested Matrix with `info.relationalColumnIndexes` and `info.relationalInfos`, applying
  these same rules to its STRING, DATE and nested RELATIONAL cells. Nested NOMINAL cells are skipped for the
  same reason as top-level NOMINAL cells; their declarations are checked in the schema traversal above.
  The nested weight column holds validated numbers and is skipped.
- `Number` cells and weights are skipped, because their text is ASCII. Numeric `CharSequence` cells are also
  skipped: §5.2 already rejects every non-ASCII character before output.

**How it is checked**, from cheapest to most general:
- UTF-8 (the default): only unpaired surrogates are unencodable, so a `char` scan with no allocation is enough.
- ISO-8859-1 and US-ASCII: a `char` loop (`c <= 0xFF` / `c <= 0x7F`) with no allocation.
- any other charset: one `CharsetEncoder` per write, reused for every `canEncode(CharSequence)` call. This allocates
  per call, which is accepted for uncommon charsets.

Failures throw `IllegalArgumentException("Column 'c' row 0 contains characters that cannot be encoded in
ISO-8859-1")`. For nested values the message names the path, e.g. `bag[3].s row 0`.
For schema text, throw `IllegalArgumentException` with no row number, using these message formats:
- relation: `Relation name 'r' cannot be encoded in ISO-8859-1`;
- attribute name (including the name emitted by `@END`):
  `Attribute name 'bag.€' cannot be encoded in ISO-8859-1`;
- type declaration: `Declaration of column 'd' cannot be encoded in ISO-8859-1`.

Substitute the actual relation name, column path and charset name. Nested schema paths use dotted names without row
indexes (e.g. `bag.d`); cell paths retain their row indexes. The REPORT encoder plus §2.6 is the
safety net for anything the pre-check misses. Tests: add `unencodableNestedRelationalValueFailsBeforeWriting()` (a
nested STRING `'€'` with ISO-8859-1 must fail and leave an existing target file unchanged) and
`unencodableNestedAttributeNameFailsBeforeWriting()` (nested attribute name `'€'`),
`unencodableAllNullWekaDateDeclarationFailsBeforeWriting()` (all-null DATE column with a quoted `'€'` pattern literal
in WEKA mode), and `nonAsciiNumericStringFailsBeforeWriting()` (the §5.1 digit cases). Each uses ISO-8859-1 and asserts
that an existing target is byte-identical and an OutputStream remains empty. The nested-name test asserts
`Attribute name 'bag.€' cannot be encoded in ISO-8859-1`; the all-null DATE test asserts
`Declaration of column 'd' cannot be encoded in ISO-8859-1`. Add relation-name and `@END` name coverage asserting
the corresponding row-free format above. Cell tests assert the column path and row diagnostic; the numeric-string
